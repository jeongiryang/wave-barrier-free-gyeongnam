# 원안 복원 뒤 후속 PR 판단

#737로 #726 원안을 먼저 복원했다. 원안 스타일시트 10개와 Planner 컴포넌트 4개가 `9c988cf`와 동일하며, 원격 PR/main CI가 통과하고 `c206c6b`로 Production 배포됐다. 배포 후 390·960·1440px에서 첫 인트로·Escape·초점 복귀·재방문을 확인했고, 같은 커밋에서 실제 무료 로컬 나루의 제안→명시적 적용→되돌리기도 통과했다. 외부 API/계정을 대체한 경계와 실제 모델·관광 데이터 호출을 보고서에 구분했다.

이후 복원된 동작과 다음 PR의 변경 내용을 대조했다. 복원 전의 잠정 의견을 그대로 최종 판단으로 사용하지 않는다. PR을 자동으로 종료하거나 새 배치를 원안에 미리 섞지 않는다.

## 확인된 검색 복귀 오류

지원되는 기기 저장본에 여행 ID·장소 ID·날짜·편의가 있지만 지역/catalog가 없으면 장소 근거 API로 일정을 복구할 수 있다. 이 상태에서 검색은 아직 실행하지 않아 `resultsAvailable=false`다. 헤더는 `places` 이동만 요청하고 단계 관리자는 준비되지 않은 결과 화면 이동을 거절하여 현재 일정 화면에 머물렀다.

헤더의 결과 화면 이동이 거절된 때에만 기존 조건 화면으로 돌아가게 한다. 이미 검색 결과·로딩·오류가 있는 때에는 기존 결과 화면으로 이동한다. 새 버튼·문구·CSS를 추가하지 않으며 여행을 새로 만들거나 저장 데이터를 지우지 않는다. #730의 조건 화면 복귀 의도 중 재현된 기능 문제에 필요한 범위다.

수정 전 합성 브라우저 재현은 1 PASS/1 FAIL이다. 날짜·장소·편의·여행 ID는 실패 당시에도 보존됐다. 이후 회귀는 desktop/mobile에서 미검색 저장 복원과 API503 두 경우의 이동·초점·저장 상태를 검증한다. 최초 재현 자료는 `harness-results/pr726-original-intent/qa-return-boundary-*`, 수정 검증은 같은 경로의 `search-return-*`에 보관한다. 실제 기기나 실제 계정 복원 인증은 아니다.

수정 후 desktop/mobile 4개 회귀가 retries 0으로 통과했다. 조건/결과 화면의 보이는 제목으로 초점이 옮겨지고, 기존 날짜·장소·편의·여행 ID를 보존하며, 지역 선택 또는 같은 조건 재시도로 실제 fixture 검색 결과까지 도달했다. 전체 단위 1,826개, lint·typecheck·Vercel 빌드·성능 검사도 통과했다. 원격 CI/CD와 Production 결과는 해당 수정 PR의 실행 기록에 연결한다.

원안의 사진·히어로 일부 대비 실패와 9월 30일 최종 전수 인증 미해결 상태는 [원안 복원 기록](pr726-original-intent-20260928.md)대로 유지한다.
