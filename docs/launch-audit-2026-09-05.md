## 검증 현황

### CI #644 이후 재개

최신 안정화와 정확한 로컬 검증 결과는 [PR #287 AI 작업 로그](ai-logs/PR-287.md#ci-644-후속-안정화-기록)에 기록한다.
이번에는 Chromium 설치가 성공해 CI의 두 실패를 데스크톱·모바일에서 직접 재현했다.
hydration 중 환경설정 갱신의 DOM 교체와 select label 탐색 불일치를 제품 코드에서 수정했다.
390px hero 내용 잘림, 마지막 테마 해제 시 이전 결과가 유효하게 남는 문제,
초기 JS 예산 초과, 배포 migration 등록 누락도 재검토에서 발견해 수정했다.
미래 방문 후기 migration의 최종 파일명은 `008_review_date_integrity.sql`이다.
초기 설정 복원·OS 동작 감소 전환·모든 일정 구간과 수단·완료 무효화·단계 잠금 회귀를 보강했다.
기존 정확한 assertion과 timeout, 테스트 범위, 성능 예산은 유지했다.

병합 규칙은 `validate`와 승인 3개다. 관리자 우회 없이 승인 절차를 따른다.
아직 이 PR의 Production 적용/재검증 및 실물 기기·영어 전수 검증을 완료한 것이 아니다.
아래는 이전 체크포인트의 이력이며 최신 실행 결과와 구분한다.

### 이전 체크포인트

- CI #643: 229 통과·2 실패·1 skipped. 날씨 재검색, 대안의 일정 교체, 헤더 겹침 검사는 통과했다. 실패는 두 기기의 OS 동작 감소 변경 중 포커스 유지 검사이며 후속 보강 중이다.
- 후속 구현: 날짜·순서에서 전체 이동 구간을 생성하고 사용자 요청으로 최대 2개씩 조회한다. 전체 조회는 30초 상한·중단을 지원하고 성공한 구간부터 표시한다. 현재 위치 출발 구간은 전송하지 않는다.
- 모든 구간에 선택한 이동수단의 실제 응답이 있어야 일정 검토를 완료할 수 있다. 출발 확인은 별도 확인이며 날짜·순서·이동수단 변경으로 완료 판정을 무효화한다. 조회한 구간을 지도에 표시하면 실제 구간 출발점도 일치시킨다.
- 혼잡 정보는 요청한 장소명과 실제 수치가 일치할 때만 사용한다. 다른 장소나 누락 수치를 0%로 표시하지 않는다.
- CI #642: 224 통과·2 실패·1 flaky·1 skipped. 실패 2건은 삭제된 편의시설 백분율 기대값, flaky는 OS 동작 감소 전환 중 인트로 포커스다. 재생은 캔버스 DOM 교체 없이 렌더러만 초기화하도록 보강했다.
- #642의 실제 390px·1366px 캡처에서 헤더와 첫 제목 겹침을 발견해 워크스페이스 시작 간격과 화면 좌표 회귀를 추가했다. CI 스크린숏 보고서는 약 8MB로 분리 보관된다.
- 날씨 대응 버튼의 테마 변경만 수행하는 결함을 실제 검색으로 연결했다. 혼잡 대안은 사용자 확인 후 기존 날짜·순서를 유지해 장소를 교체하며, 지도만 다른 장소로 이동하지 않는다. 대안의 접근성·혼잡도가 더 낫다고 보장하지 않는다.
- 느린 부가 API 때문에 장소 조회까지 기다리거나 성공 결과가 사라지는 구조를 제공처별 예산·병렬 부가 조회로 수정했다. 배포 후 응답시간 실측은 아직 안 됨.
- PR [#287](https://github.com/jeongiryang/wave-barrier-free-gyeongnam/pull/287), 체크포인트 `cb6c6da` → `e44ecc1`. 아직 초안이며 병합·배포 전이다.
