# PR-184 — ODsay 실패가 키 미등록과 구분되지 않던 문제

## 목적

ODsay 관련 네 가지 상황이 화면에서 같은 문구로 수렴해, 운영자가 무엇을
고쳐야 하는지 알 수 없던 문제를 고친다.

## 원인

**ODsay는 오류를 HTTP 200으로 돌려준다.** 인증 실패는
`{ "error": { "code": "500", "msg": "Invalid API Key." } }` 형태다.

```ts
if (!response.ok) return [];
const result = body.result;                              // 오류 봉투면 undefined
const rawPaths = Array.isArray(result?.path) ? ... : []; // → []
```

`catch { return [] }`도 같은 결과여서, 키 없음·키 만료·상류 장애·구간에 경로
없음이 모두 빈 배열이 됐다.

**제공기관 상태를 갱신하는 대상이 하나뿐이었다.** `handler.ts`가 `kakao-drive`만
갱신해, `odsay` 행은 키 설정값에서 한 번도 바뀌지 않았다.

## 변경

- `lib/transport/odsay-response.js` — `readOdsayResponse`, `odsayProviderStatus`.
- `server/transport/odsay.ts` — `{ routes, provider }`를 돌려준다.
  `fetchKakaoRoute`와 같은 형태다.
- `server/transport/handler.ts` — 두 제공기관 상태를 같은 방식으로 반영한다.
- `tests/odsay-response.test.mjs` — 동작 6건.

## 설계 판단

**키가 없을 때는 `null`을 돌려준다.** ODsay는 `optional: true`인 선택 사항이라
키를 넣지 않은 것은 실패가 아니다.

**"경로 없음"과 "오류"를 나눴다.** 구간에 대중교통이 없는 것은 정상 응답이다.
이것까지 오류로 칠하면 진짜 오류를 놓친다.

**응답 해석을 `lib/*.js`로 뺐다.** CI의 Node 22.13에서 `node --test`가 `.ts`를
읽지 못하므로, 이 관례를 따라야 동작 자체를 검증할 수 있다.

## 결과와 제한

실제 ODsay 키가 없어 상류 응답을 직접 받아 보지 못했다. 오류 봉투 형태는
문서 기준이며 `errorCode`·`message` 대체 필드도 함께 읽는다. 배포 후 진단
패널에서 ODsay 줄이 실제 상태를 보이는지 확인이 필요하다.
