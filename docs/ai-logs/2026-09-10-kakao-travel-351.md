- Owner 최신 요청: 제안 1~5 전체 구현·사용법 안내, 필요한 동의항목 조정, 가능한 택시 기능, 검토 후 merge/deploy.
- 선행 PR #455: 계정 여행·편의 복원·동행자 협업. 본 PR은 카카오 여행 활용과 실제 동의/도메인 설정에 집중한다.

## 구현

- 내 일정·계정 여행에서 공개 일정 카드를 준비하고 사용자가 카카오톡 대화방을 선택한다. 공유 전 범위를 보여주며 편의 조건·메모·현재 위치·동행자 의견은 공개 payload에 넣지 않는다. 공유 링크는 기존 30일 저장/만료 체계를 재사용한다.
- 카카오 JS SDK 2.8.3을 요청 시점에만 SRI 고정 로드한다. CSP form-action에 SDK가 사용하는 정확한 `https://sharer.kakao.com`만 추가한다. 팝업은 최종 클릭에서 동기 실행한다. 창을 열었다고 전송 완료로 표시하지 않는다.
- 나에게 보내기는 서버가 현재 세션의 여행 권한과 연결된 카카오 계정을 확인한 뒤 memo API만 호출한다. 토큰은 Better Auth의 암호화 저장과 서버 API로 처리하며 브라우저 HTTP 토큰 endpoint는 계속 차단한다.
- 기존 로그인은 account_email만 요청한다. fresh-session link-social에서 단일 talk_message 추가 동의만 허용한다. OAuth state/session 연결·이메일 동일성·암호화 토큰 경계는 유지한다. 동의 후 자동 전송하지 않으며 다시 보내기를 눌러야 한다.
- DB 기반 전송 예산: 계정당 3회/분, 같은 여행 1회/분. 전송 전 commit해 네트워크 결과가 불명확해도 즉시 중복 발송되지 않는다. 자동 재시도 없음. 실패 시 나와의 채팅 확인 안내.
- 카카오 T는 공식 홈페이지의 앱 실행 링크와 공개 목적지 복사로 연결한다. 공개 택시 배차 API를 확인하지 못했으므로 자동 호출/예약/결제는 구현하거나 주장하지 않는다.
- `/guide`에 전체 사용 방법, 개인정보처리방침 1.1에 여행·메시지 처리 항목을 반영한다.

## 실제 카카오 설정

- 앱 1539906 W.A.V.E: account_email 필수 유지, 목적을 `W.A.V.E 회원가입·로그인, 계정 식별 및 비밀번호 재설정·탈퇴 확인 메일 발송`으로 저장. 이메일이 없는 사용자에게 추가 수집하는 checkbox는 꺼진 상태 유지.
- talk_message: 사용 안 함 → 이용 중 동의. 목적 `사용자가 요청한 W.A.V.E 여행 일정과 여행 링크를 카카오톡 나와의 채팅으로 전송` 저장 후 표에서 확인.
- 닉네임·프로필 사진·친구 목록·캘린더는 사용 안 함. 이름·성별·연령·생일·전화번호·CI·배송지 등은 미신청. 실제 기능에 필요하지 않은 정보 수집을 추가하지 않는다.
- 제품 링크 관리의 빈 웹 도메인에 `https://wave-barrier-free-gyeongnam.vercel.app` 등록 후 확인. 기존 KAKAO_MAP_JAVASCRIPT_KEY의 SDK 도메인에는 운영 주소가 이미 등록돼 있었다. 키 재발급·유료화 없음.
- 개인정보 국외이전의 운영주체/법적 확정은 기존 #11 human gate를 유지한다. 사실을 지어내 설정하지 않는다.
