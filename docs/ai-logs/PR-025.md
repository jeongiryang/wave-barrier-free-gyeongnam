## 목적

이용자가 고른 다크모드와 언어가 새로고침 후 사라지는 문제를 고친다.

## 발견 경위

이슈 #21의 파동 효과 토글을 만들다가 토글 상태가 저장되지 않는 것을 발견했다.
원인을 좁히던 중 같은 구조를 쓰는 테마와 언어에도 같은 문제가 있음을 확인했다.
토글보다 먼저 고쳐야 하는 기존 버그이므로 별도 작업 단위로 분리했다.

## 역할과 변경

- 사람: 자율 진행 권한을 위임했다.
- Claude Code: 브라우저에서 저장·새로고침·재확인을 자동으로 수행하는 점검
  스크립트로 재현하고, 두 이펙트의 실행 순서를 원인으로 특정한 뒤 수정했다.

## 원인

설정을 읽는 이펙트는 `requestAnimationFrame` 안에서 동작하고, 저장하는 이펙트는
마운트 직후 동기로 실행된다. React는 커밋 직후 이펙트를 실행하고 rAF 콜백은
그다음 페인트 직전에 실행되므로 **저장이 항상 먼저** 일어난다.

그래서 초기 상태(`light` / `ko`)가 저장값을 덮어쓰고, 뒤이은 읽기는 이미
덮어써진 값을 읽는다. 저장값 자체가 훼손되므로 다음 방문에도 계속 기본값이 된다.

## 판단 근거

읽기 이펙트에서 rAF를 걷어내는 방법도 있었지만, rAF는 이 저장소가 lint 규칙
(`react-hooks/set-state-in-effect`)을 지키려고 쓰는 패턴이라 그대로 두었다.
대신 저장 쪽에 `hydrated` 게이트를 두어 순서를 보장했다.

화면에 적용하는 부분(`dataset.theme`, `lang`, `colorScheme`)은 게이트 위에 남겨
첫 페인트 동작이 달라지지 않게 했다.

## 검증

- 브라우저에서 `theme=dark`, `locale=en` 저장 → 새로고침 → DOM과 저장값 모두 유지 확인
- 수정 전에는 두 값 모두 기본값으로 되돌아가는 것을 같은 방법으로 재현
- 읽기와 저장의 순서를 검사하는 회귀 테스트 추가
- `npm run lint`, `npm run typecheck`, `npm test`(12 pass), `npm run build:vercel` 통과

이 저장소의 기존 테스트도 같은 방식이라 형태를 맞췄다.
