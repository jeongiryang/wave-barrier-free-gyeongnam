# PR-088 — 교통 provider와 route 오케스트레이션 분리

## 목적

단일 route handler에 공공교통, ODsay, Kakao 자동차 경로, health/config와 응답
조합이 함께 있던 서버 책임을 제공자·정책 경계로 분리한다.

## 변경

- KORAIL·TAGO 조회와 context 정규화를 `public-context`로 분리
- ODsay 대중교통 파싱과 Kakao 자동차 경로 파싱을 provider별 모듈로 분리
- 좌표 검증·거리 계산, route 응답 타입, health/map config를 독립 모듈로 분리
- route handler를 validation, 병렬 provider orchestration, graceful fallback에 집중
- 서버 아키텍처 테스트가 각 provider 경계를 직접 확인하도록 보강

## 안전성

각 provider는 기존 timeout과 오류 격리를 유지한다. 한 공급자 실패는 빈 결과로
격리되고, 사용할 수 있는 다른 결과 또는 직선 미리보기는 계속 반환된다.

## 검증

- `npm run lint`
- `npm run typecheck`

- `git diff --check`

## 영향

동일 요청 안의 독립 provider를 병렬 조회해 waterfall을 줄인다. DB, 인증,
환경변수 이름, migration 변경은 없다.
