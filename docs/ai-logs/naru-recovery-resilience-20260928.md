- 작성: Codex, 사용자 정이량의 장애 복구·4070 Ti 예비 서버 재가동 요청.

- 범위: 운영 연결 복구, 전용 런타임 자동 복구, 안전한 진단, 하드웨어별 모델 비교. 전체 제출 기능 전수 합격 판정은 아니다.

## 장애와 대응

당일 점검에서 available=false 후 true가 되었지만 실제 질문은 503이 두 번 발생했다(13.846초, 11.545초). 조사 시 Mint 게이트웨이와 모델은 살아 있었다. 기존 코드가 예외를 버려 최초 장애의 정확한 원인은 확정하지 못했다. 모델이 꺼졌거나 네트워크가 원인이라고 단정하지 않는다.

중지했던 Windows 예비 런타임을 재가동하고 기존 운영 fallback 설정으로 연결했다. 교수님 주 게이트웨이를 잠시 중지한 실제 운영 검사에서 GET available=true 1.800초, POST 200 2.512초로 통영 settings 제안이 반환됐다. finally에서 주 게이트웨이를 복구했다.

- Mint: 사용자 systemd 감독 서비스 설치·enable, linger=yes. 모델 API 부재 시 daemon → API → 설치된 전용 모델 순으로 복구한다. 게이트웨이는 기존 systemd Restart=on-failure를 유지한다.
- Windows: 기존 시작프로그램의 숨김 PowerShell 실행기를 재시작 루프로 바꾸고 감독기를 교체했다. 전용 Ollama와 게이트웨이 부재 시 복구하고 모델을 예열한다. Windows 로그인이 필요한 기존 시작프로그램 방식이다.
- 양쪽 문맥 16384·동시 생성 1로 통일. Windows 예열 16K/요청 8K 불일치를 없앴다.
- 정상 처리 중인 포트·타인 모델을 강제 종료하거나 모델을 반복 적재하지 않는다. 점유된 채 응답하지 않는 상태는 안전하게 기록하며 자동 강제 종료하지 않는다.
- 진단은 단계·범주·상태 코드만 기록한다. 토큰·주소·질문·응답 원문을 기록하지 않는다. Windows 자식 stderr도 허용 목록으로 축약하고 로그 크기를 제한한다.
- 운영 API에서 primary/fallback 사용과 실패 단계를 구분한다. 출력 검증, 스트림 시작 뒤 재실행 금지, 기존 timeout/fallback 범위는 유지했다.
- 일일 Gmail 점검 지침은 예비 서버 활성 상태를 반영했다. 자동 점검은 읽기 전용이며 스스로 재시작하지 않는다. 공모전 감시는 일시정지를 유지한다.

## 실제 검증

- Mint 감독기 SIGKILL 후 systemd 자동 재시작: PID 변경, NRestarts=1, active. 모델과 게이트웨이 유지.
- Windows 감독기 및 전용 게이트웨이 종료 후 wrapper/감독기가 둘 다 새 PID로 복구. Ollama 모델은 유지, 로그 healthy.
- 실제 모델 사진 검사: 합성 행사 포스터의 날짜/시간 추출, 최종 16K에서 양쪽 성공(주 4.09초, 예비 4.83초). 사진에서 추출한 내용은 검토 대상으로 표시하며 직접 일정 변경을 실행하지 않았다.
- Production 실제 API 검사: 의도 3.172초, 실제 장소 ID를 포함한 일정안 3.918초, 지역·개수 요청 5.171초 성공(복구 후 기준 main).
- Production 실제 브라우저: 통영 요청 → 실제 후보 12곳 표시. 원래 창원으로 복원 요청 → 창원 12곳 표시. 담은 사화공원과 날짜 보존. 영구 여행 저장·장소 추가는 하지 않았다.
- 관련 최종 단위 검사 46/46, 그 안의 Python 감독기 15개 및 사진 게이트웨이 8개 통과. 앞선 전체 단위 1864/1864, lint 오류 0, typecheck/build/performance 통과. 최종 CI 결과는 PR 체크에 남긴다.

## 제한·복귀

실제 OS 재부팅·로그아웃 시험은 운영 중단을 피하고자 하지 않았다. Mint linger 및 enabled와 프로세스 복구를 검증했으며 Windows는 로그인 후 시작된다. 두 PC의 동시 정전/학교망 단절은 이중화로 해결되지 않는다. 모델 의미 품질 검사는 제한된 합성 사례로 전체 사용자 질문의 정답을 보장하지 않는다.

독립 코드 리뷰에서 P0/P1은 발견되지 않았다. P2 제한: Mint는 이미 로드된 동일 모델의 문맥 크기를 강제 변경하지 않으며, 모델 로딩 도중 감독기가 죽으면 진행 중인 CLI 소유권을 잃어 로드 명령을 중복 시작할 여지가 있다. 이번 강제 종료 시험은 모델 적재 완료 상태에서 실행했다.

호스트별 변경 전 supervisor 및 시작 설정 사본을 전용 런타임에 보존했다. 복귀 시 새 감독기를 중지하고 사본을 복원한 후 하나만 실행한다. 웹 변경은 이 PR을 revert하는 PR로 기존 CI/CD를 통과시킨다. 비밀 설정과 내부 접속 정보는 저장소에 넣지 않았다.
