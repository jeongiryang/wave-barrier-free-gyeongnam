# PR-093 — 관광 계획·공유 복원·HTTP 라우팅 분리

## 목적

관광 API handler가 여행 계획 생성, 공유 일정 복원과 action별 HTTP 응답까지
동시에 소유하던 구조를 도메인 책임별로 분리한다.

## 변경

- 공식 관광·무장애 데이터 기반 계획 생성을 `plan-builder`로 이동
- content ID 기반 공유 일정 복원을 `shared-plan-restoration`으로 이동
- `handler`는 method/key 검증과 photo/crowd/enrichment/plan action 라우팅에 집중
- trips handler가 계획 생성·복원 도메인을 직접 import하도록 변경
- 서버 경계와 공유 일정 복원 회귀 테스트 갱신

## 안전성

공식 데이터 실시간 조회, 편의근거 우선 정렬, content ID 복원과 조건 fallback,
action별 상태 코드와 cache 정책을 유지한다.
