## Owner 요청과 역할

Owner는 프론트 개편 후 모든 조작 기능을 사용자·심사위원 관점에서 직접 확인하고 기존 테마로 통합하도록 승인했다. 별도 화면 승인 대기 없이 PR 병합·운영 배포까지 진행하며 필수 validate는 우회하지 않는다. 이 PR은 기존 기능 화면을 정리하는 단위다. 승인된 24개 후보 구현과 마지막 전수 회귀·제출 전 점검은 계속된다.

Codex가 최신 main/PR/Production을 확인하고 통제된 응답으로 날짜·순서·저장·보관·계정 편집·투표·초대·댓글·제보 메뉴·지도·주변 검색·내보내기·사진 코스의 화면과 조작을 검사했다. 독립 QA 에이전트가 320/390px의 기본/개발용 dark 화면을 별도로 검사하고 재현 가능한 문제를 전달했다. 실제 계정 정보 수정, 개인 메시지, 실제 커뮤니티 게시·신고는 하지 않았다.

## 변경과 발견 근거

- 장소 상세, 경로 비교, 커뮤니티 폼/댓글, 지도 도구, 여행 보관함의 이전 파란 패널을 Horizon 의미 토큰으로 통일했다. 조작 라벨 14px, 입력 16px, 보조 정보 12px를 기준으로 하고 계정 날짜·시간을 한 그룹으로 묶었다.
- 모바일 검색 요약: Production 캡처에서 필요한 편의 칸이 카드 밖에 배치됐다. 이전 flat header의 nth-child grid 규칙이 새 문장형 헤더에 적용되는 원인을 제거했다. 초기/선택 후 320/390/960/1440px의 버튼 경계를 검사한다.
- 지도: 고정 제목 아래 첫 약국 버튼이 가려지는 경로를 320/390px에서 재현했다. 실제 cascade의 지도 높이를 도구막대 하단+344px로 확보하고 제목의 실제 높이를 ResizeObserver로 측정해 스크롤 여백에 반영했다. 수정 후 패널 높이 328px, 도구막대 간격 8px 이상, 44px 닫기 버튼 실제 hit 확인.
- 초점: 검색 직후 하단 설정에 초점을 옮기면 queued results heading focus와 80ms scroll이 초점을 빼앗았다. 요청 당시 초점과 비교해 이미 옮긴 초점을 보존하고 focusin 시 남은 스크롤을 취소한다. 독립 재현 3회 수정 확인, 정상 검색의 제목 초점 이동도 유지.
- 개발용 dark의 댓글 저장/취소·장소 해제 버튼 대비 문제는 배경/전경 토큰을 짝지어 수정했다. 공개 영어·dark 옵션 비활성 정책은 유지한다.

## 검증

- lint 오류 0, 기존 경고 12; typecheck 성공.
- 단위 테스트 800개 성공. 검색 대기/결과 직후 focusin 취소 회귀 추가.
- Vercel 빌드 및 성능 예산 성공: CSS gzip 68.48/70KiB, Planner 초기 JS 173.84/270KiB. 예산·의존성·lockfile·CI 설정 변경 없음.
- 최종 변경 영역 브라우저 34개 성공(지도 도구/주변 15개 결과/고정 제목/조건 요약/단계 이동/커뮤니티 대비). 장소 상세 10개, 계정 편집·여행 보관함 등 별도 조작도 확인했다.
- 초기 로컬 검사 도중 CSS HMR이 결과 상태를 초기화한 실패는 소스 고정 재실행으로 구분했다. 반복된 footer focus 실패는 테스트를 우회하지 않고 위 실제 원인을 수정했다.
- 독립 QA: 장소 상세·경로 비교·계정/보관·커뮤니티·지도에서 가로 넘침/대비 위반 없음, 지도 ResizeObserver 오류 없음, 검색 요약 5개 버튼 모두 카드 내부·48px 이상. 통제된 fixture 범위의 PASS이며 전체 실제 API/인증 완료를 뜻하지 않는다.
