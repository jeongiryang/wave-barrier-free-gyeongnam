# 심사용 운영 데이터: 실제 여행집에서 열기

사용자는 심사위원이 배포된 서비스의 실제 버튼을 눌러 여행 기능을 판단할 수 있도록 운영 DB에 충분한 시연 자료를 원했다. 별도 `/demo` 화면과 브라우저 전용 데이터만으로는 새 방문자의 실제 여행집이 비어 있었다.

## 적용 범위

- Production CD migration `020_judge_demo_trips.sql`이 읽기 전용 공개 계획 5개를 `judge_demo_trips` 테이블에 멱등 삽입한다. 창원·통영·진주·거제·김해, 총 15개 장소 참조다.
- DB에는 시연용 제목·지역·선택한 편의 조건·계획 메모·장소 ID·일차·체류/휴식 설정만 저장한다. 방문 사실, 시설 상태, 운영시간, 날씨, 축제, 이동시간, 사진, API 응답은 넣지 않는다.
- `/travel-book`에서 계획을 고르면 공식 `/api/wave?action=places`가 해당 ID를 다시 조회한다. 누락·오류·지역 불일치가 있으면 저장하지 않는다. 모두 조회되면 현재 방문자의 로컬 여행집에 사본을 담아 기존 메모·상태 변경·여행 비교·프로필 요약·플래너 복원 버튼을 그대로 사용할 수 있다. 원본 운영 행은 심사위원의 클릭으로 바뀌지 않는다.
- 공식 API 응답을 받지 못하면 해당 사본 담기는 실패한다. 시연 데이터를 공식 정보처럼 대체하지 않는다.

## 운영 확인 항목

CD migration 성공 후 공개 `/api/judge-demo-trips`에서 5개 계획이 조회되고 `/travel-book`에 나타나는지 확인한다. 서로 다른 두 계획을 사본으로 담아 비교·메모·상태 변경을 확인하고, 한 계획의 `이 일정 다시 열기`로 플래너에 실제 API 장소가 표시되는지 확인한다. 브라우저를 새로 열면 운영 DB 원본은 다시 보여야 하며 방문자 사본은 그 브라우저에만 남는다.
