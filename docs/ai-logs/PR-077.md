## 목적

`PlannerPage`가 여행 조건뿐 아니라 plan API 요청, abort, loading·error와 자동 재조회
상태까지 직접 관리했다. 검색 lifecycle과 조건 상태를 독립 controller로 이동한다.

## 역할 구분

- 사람: 남은 대형 책임 경계를 모두 점진 분리하고 검증·병합·배포까지 완료하도록 위임
- AI: 조건·검색 controller 설계와 이동, 회귀 테스트와 PR 처리

## 구현

- `usePlannerPlan`이 접근성 프로필, 지역, 테마와 plan 결과 상태를 소유한다.
- 이전 plan 요청을 abort하고 stale response가 UI를 덮지 않도록 controller 경계를 유지한다.
- URL 지역 초기화, 조건 toggle, 공식 데이터 실패 문구와 첫 경로 연결 계약을 모았다.
- Planner page는 route·audio callback을 실행 옵션으로 전달하고 자동 재조회 시점만 조율한다.
