# PR-191 — 어두운 화면에서 로그인·가입 안내가 배경에 묻히던 문제

## 목적

어두운 화면에서 로그인·가입 안내 글자가 대비 1.02까지 떨어져 읽을 수 없던
문제를 고친다.

## 원인

`account-auth.css`에는 다크 테마 규칙이 하나도 없었다. 표면 색이 흰색 계열로
고정돼 있어 어두운 화면에서도 밝은 패널이 그대로 남는다.

```css
.auth-journey-preview > span { background: rgba(255,255,255,.64); }
.password-field button      { color: var(--ink); background: #f4f9fb; }
```

`.auth-trust`는 반대 방향이다. `account-community.css`가 배경만 어둡게 바꾸고
글자색 `#496d7e`는 밝은 화면 값 그대로 두었다.

측정값:

| 대비 | 색 | 글 |
| --- | --- | --- |
| 1.02 | `#94b3c4 on #a5aeb3` | 안내 보조 설명 |
| 1.09 | `#45aeea on #a5aeb3` | 번호 01·02·03 |
| 2.02 | `#e8f5fb on #a5aeb3` | 안내 제목 |
| 1.04 | `#e8f5fb on #f4f9fb` | 비밀번호 "보기" |
| 2.33 | `#496d7e on #0d3546` | 계정 보안 안내 |

## 변경

- `app/styles/account-auth.css` — 어두운 화면 규칙 추가.
- `e2e/auth-dark-contrast.spec.ts` — 두 테마에서 실제 대비 측정 2건.

## 측정 (axe-core, WCAG 2 AA, 어두운 화면)

| 화면 | 수정 전 | 수정 후 |
| --- | --- | --- |
| `/login` | 14건 | 2건 |
| `/register` | 14건 | 2건 |

남은 2건씩은 `.auth-header-action`·`.auth-submit`로 PR #189가 고친다.

## 설계 판단

**표면을 어둡게 하고 글자는 토큰에 맡겼다.** 밝은 패널을 그대로 두고 글자만
어둡게 하면 화면 전체와 섞이지 않아 눈에 튄다.

**`.auth-card`·`.account-popover`는 건드리지 않았다.** `community.css`의 다크
규칙이 이미 덮는다. 같은 선택자를 두 파일에서 정의하면 한쪽만 바뀐다.

**입력칸도 확인했다.** 흰 배경 고정이라 의심했지만 실제로는 어두운 화면에서
대비 11.70으로 정상이었다. 빈 폼에서는 axe가 잡지 못하는 자리라 직접 타이핑해
확인했다.
