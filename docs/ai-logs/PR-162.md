# PR-162 — 지역 표식이 등장 중에 앵커를 벗어나던 문제

## 목적

랜딩의 경남 18개 지역 표식이 페이지가 열릴 때 제자리에서 커지지 않고,
최대 21.7px 밀린 자리에서 미끄러져 들어오던 문제를 고친다.
위치가 곧 정보인 지도에서 표식이 잘못된 자리에 착지해 보이는 결함이다.

## 원인

`app/styles/landing-regions.css`의 표식은 두 가지를 함께 쓰고 있었다.

```css
transform: translate(-50%,-50%);        /* 앵커에 중심 맞추기 */
animation: regionArrival .65s both;     /* @keyframes { from { scale: .35 } } */
```

`scale`은 개별 CSS 속성이라 `transform`보다 **먼저** 적용된다. 그래서 실제 행렬이
`scale(s) × translate(-50%,-50%)`가 되고, 중심을 맞추는 -50% 오프셋까지 함께
줄어든다. 표식은 자기 앵커에서 `(1 - s) × 크기/2` 만큼 밀린다.

브라우저에서 직접 잰 값(1440×960, 거제 표식):

| 애니메이션 상태 | 앵커 이탈 |
| --- | --- |
| scale 0.35 | dx 21.7px · dy 11.0px |
| scale 0.83 | dx 5.6px · dy 2.8px |
| scale 1 | 0px |

같은 파일의 hover 규칙(`transform: translate(-50%,-50%) scale(1.18)`)은 이미
올바른 형태였다. 등장 애니메이션만 어긋나 있었다.

## 변경

- `@keyframes regionArrival`이 개별 `scale` 대신
  `transform: translate(-50%,-50%) scale(...)`을 쓴다. 중심 오프셋이 확대와
  분리돼 어느 시점에 재도 앵커가 고정된다.
- `animation-fill-mode`를 `both`에서 `backwards`로 바꿨다. 애니메이션은 `transform`을
  건드리므로, `forwards`까지 남기면 끝난 뒤에도 그 값이 hover·active의 확대를
  덮어쓴다. `to` 상태가 표식의 기본 상태와 같아 `forwards`는 필요 없다.
- `e2e/landing-regions.spec.ts` — 등장 애니메이션을 초반(100ms) 구간에 세워 두고
  18개 표식의 앵커 이탈을 재는 단언을 추가했다.

## 설계 판단

**타이밍이 아니라 원인을 고쳤다.** 기존 e2e는 850ms를 기다린 뒤 위치를 쟀는데,
마지막 표식은 `544ms 지연 + 650ms`로 약 1194ms에 끝난다. 대기 시간을 늘리면
테스트는 통과하지만 사용자가 보는 미끄러짐은 그대로 남는다. 앵커를 고정하면
애니메이션 중 어느 프레임에서도 위치가 정확해져 대기 시간과 무관해진다.

**회귀 테스트를 시간에 의존시키지 않았다.** Web Animations API로 애니메이션을
`currentTime = 100`에 일시정지시켜 재므로, 머신 부하와 무관하게 같은 상태를 잰다.

## 검증

이 저장소 경로에 한글이 있어 dev 서버가 뜨지 않으므로, 추적 파일을 ASCII 경로로
복사해 브라우저 검사를 실행했다.

- `npm run lint` 통과 (경고 0)
- `npm run typecheck` 통과 (오류 0)
- `npm test` 통과 (108/108)
- `npm run build:vercel` 통과
- `npm run test:e2e` 통과 (22/22, desktop 1440×960 · mobile Pixel 7)
- 새 단언이 결함을 실제로 잡는지 확인: 수정 전 CSS에 새 테스트를 적용하면
  `Expected: < 1 / Received: 21.723...`으로 실패한다.
- hover 확대비를 직접 측정해 1.180(기대 1.18)을 확인했다. `backwards` 전환이
  hover를 덮지 않는다.

## 결과와 제한

기존 e2e `landing-regions.spec.ts`는 CI에서 통과했지만 로컬 병렬 실행에서
2회 연속 실패했다(축이 X·Y로 번갈아 바뀜). 프레임이 밀릴수록 애니메이션이 덜
끝난 상태에서 재기 때문이며, 이번 수정으로 그 흔들림도 함께 사라진다.

지도 이미지와 표식 좌표값 자체는 건드리지 않았다. 좌표 정확도는 이 PR의 범위가
아니며 `data-region-x/y` 기준 정합성만 확인했다.
