## 목적

PR #67에서 공통 디자인·접근성 보정을 분리한 뒤에도 191KB였던 `app/globals.css`에서 랜딩·플래너·지도·데이터 화면의 연속된 제품 스타일 블록을 별도 경계로 옮긴다.

## 역할 구분

- 사람: W.A.V.E의 안전한 추가 점진 분리와 검증·PR·병합·배포 권한 위임
- AI: cascade 경계 감사, 코드·테스트·문서 변경, 로컬 검사, PR 작성과 배포 확인

## 구현

- `Marketing landing`부터 파일 끝까지 이어지는 제품 화면 스타일과 버전별 보정을 `app/styles/product-experience.css`로 분리했다.
- `app/layout.tsx`에서 기본 전역 스타일 직후, 디자인 시스템·접근성 보정 전에 불러와 기존 cascade를 그대로 유지했다.
- 공통 스타일 테스트 묶음과 import 순서 검사를 새 파일 경계에 맞게 확장했다.
- 디자인 시스템 문서에 기본 전역 스타일과 제품 화면 스타일의 책임을 명시했다.

## 검증

- 분리 전 `app/globals.css`와 분리 후 `globals.css + product-experience.css`를 합친 결과가 바이트 단위로 동일함
- `npm run lint`: 성공
- `npm run typecheck`: 성공
- `npm test`: 60/60 성공
- `npm run build:vercel`: 성공 (`nodejs22.x`, CSS 산출물 해시 유지)
- `npm audit --omit=dev --audit-level=high`: 취약점 0건
- `git diff --check`: 성공

## 결과와 제한

- CSS 선언과 cascade가 동일하므로 의도된 시각·동작 변경은 없다.
- `app/globals.css`는 191,247바이트에서 52,008바이트로 줄고, 제품 화면 스타일의 후속 분리는 `product-experience.css` 안에서 안전하게 진행할 수 있다.
