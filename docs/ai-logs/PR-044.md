# PR #44 AI 작업 로그

## 요청

- 실제 사용자와 심사자가 신뢰할 수 있도록 제품·데이터 연동·접근성 품질을 전수 점검한다.
- 발견한 치명적이거나 오해를 부르는 문제는 보고에 그치지 않고 수정한다.

## 발견

- 기존 W.A.V.E 적합도는 편의정보가 전혀 확인되지 않아도 최소 36점을 만들었다.
- 관광사진 유무와 카드 노출 순서가 접근성 점수에 영향을 줘 동일 시설도 화면 위치에 따라 점수가 달라질 수 있었다.
- 실시간 API 실패 시 보여 주는 예시 장소에도 근거 없는 84~92점이 표시됐다.
- 지도에서는 이 값을 별점으로 환산해 공식 평가처럼 오인할 여지가 있었다.

## 변경

- 점수를 `선택한 편의조건 중 공식 데이터에서 긍정적으로 확인된 비율`로 재정의했다.
- 공식 편의정보가 한 항목도 확인되지 않으면 숫자를 생성하지 않고 `판단 보류`로 표시한다.
- 사진, 카드 순서와 고정 최소점수를 계산에서 제거했다.
- 추천 카드·상세 모달·지도·공유 여행 화면을 같은 표현과 타입으로 통일했다.
- 실패 시 예시 데이터의 임의 점수를 제거했다.
- 계산 로직을 순수 함수로 분리하고 무근거·부분근거·전체근거·비정상 입력 테스트를 추가했다.

## 판단

- 정보 확인률은 데이터 범위, 편의조건 일치율은 긍정 근거 비율로 서로 분리했다.
- 미확인은 부정으로 단정하지 않지만 추천 점수로 포장하지도 않는다.
- 일치율은 공식 인증이 아니며 방문 전 운영기관 확인이 필요하다는 안내를 유지했다.

## 검증

- lint, typecheck, test, Vercel production build
- 실제 API의 근거 없음·부분 근거 응답
- 추천 카드·상세·지도·공유 화면의 nullable 점수 회귀
- 비밀정보·GPS·원본 공공데이터 저장 여부
