## 목적

창원에서 담은 장소가 진주·하동 등 다른 지역을 조회한 뒤 날짜별 일정에서 사라지는 데이터 손실을 막는다. PDF 사용자 제보와 현재 구현을 대조해 원인이 장소 ID를 현재 지역 응답에만 다시 결합하는 방식임을 확인했다.

## 역할 구분

- 사람: PDF 사용자 제보 제공, 전체 반영 요청, 제품 방향 승인
- AI: PDF 전수 검토, 현재 코드 대조, 이슈 #230 작성, 데이터 모델·UI·복원 경로 수정, 테스트와 PR 작성

## 검증

- `npm run lint` 통과
- `npm run typecheck` 통과
- `npm test -- --runInBand` 225건 통과
- `npm run build` 통과
- `npx playwright test e2e/itinerary-board.spec.ts --project=desktop-chromium`은 로컬 브라우저 바이너리가 없어 실행하지 못함. 동일 시나리오는 GitHub CI의 데스크톱·모바일 브라우저 검사에서 확인한다.
- 최소 스냅샷에 지도 좌표·원본 설명·상세 응답이 포함되지 않는 단위 테스트를 추가했다.

## 결과와 제한

- 선택한 장소의 이름·지역·주소·공식 사진 URL·편의근거 요약만 이 기기에 보관한다.
- 현재 지역 공식 응답이 있으면 최신 장소 객체를 쓰고, 이전 지역 장소는 좌표 없는 최소 스냅샷으로 일정에 표시한다.
- 좌표가 없는 스냅샷으로 실제 경로를 요청하지 않는다.
- 최종 결과와 병합 커밋은 CI·리뷰 완료 뒤 갱신한다.
