## 목적과 범위

2026-09-10 Owner가 제안 1~5 전체 구현을 직접 지시했다. 이 PR은 #350의 계정 여행 저장·다른 기기에서 이어하기·선택적 편의 조건 보관과 초대 기반 동행자 투표/의견을 구현한다. 기존 POST-RC 우선순위는 최신 Owner 지시로 앞당겼다. 카카오 공유/나에게 보내기 및 공식 택시 앱 연결은 다음 독립 PR로 이어간다.

- 기존 일정은 사용자가 ‘계정에 저장’을 누른 여행만 가져온다. 로그인만으로 자동 업로드·로컬 덮어쓰기하지 않는다.
- `/my-trips`에서 여러 기기에서 같은 저장본을 열고, 소유자가 날짜·순서·메모·상태를 변경 후 저장한다. 충돌은 409와 최신 불러오기/내 수정본 별도 저장으로 처리한다. 자동 백그라운드 동기화 또는 오프라인 영구 저장으로 과장하지 않는다.
- DB에는 공식 장소 ID, 사용자 작성 여행 필드만 저장한다. 관광 API 응답·사진·정밀 위치·건강 추론 데이터는 저장하지 않는다. 장소 표시는 현재 KTO 상세 API를 조회하고 실패/누락을 알린다. 편의 조건은 계정별 선택 저장·적용·삭제이며 동행자에게 공개하지 않는다.
- 초대 토큰은 32바이트 난수, DB에는 SHA-256만 저장, 7일 유효. 초대 열기만으로 참여하지 않고 로그인 및 표시 이름 입력 후 명시적 참여. URL fragment 토큰을 로그인 이동 URL에 넣지 않는다.
- 동행자는 장소 투표/의견만, 소유자는 일정 편집/초대 중지/참여 해제. 소유자가 참여자를 해제하면 기존 초대도 무효화한다. 본인·소유자만 의견 삭제. 서버 세션 기반 권한과 DB transaction으로 판단한다.
- 계정 여행 20개, 참여 여행 20개, 여행당 장소 12곳/7일/10명/100의견. DB 기반 사용자별 쓰기/초대/장소 조회 예산. 재시도는 수동, 저장 요청은 고정 UUID로 중복 방지.
- 새 public 011 migration은 CREATE IF NOT EXISTS만 포함, 기존 배포의 원자적 migration chain에 추가. 인증 스키마와 기존 사용자를 변경하지 않는다. 탈퇴 정리에 여행·참여·투표·의견·편의·호출 예산을 포함한다.
- 새 기능 사용법 `/guide`, 도움말 투어·계정 메뉴·내 일정·계정 관리 진입 연결. 비로그인 핵심 여행 설계 유지.
