## 목적

팀원이 GitHub Issue를 제출하거나 PM triage가 다시 필요할 때, 사람이 Work 채팅에 Issue를 복사해 전달하지 않아도 GitHub Actions가 published PM Workspace Agent를 호출하게 한다.

## 역할 구분

- 사람(PM, `jeongiryang`): 실제 Product Owner / PM / Release Authority, Human Gate와 최종 판단
- PM Workspace Agent: PM Assistant / Orchestrator. Issue triage·Acceptance Criteria·agent handoff·compliance/release state·Notion sync
- AI 작업: Workspace Agents API 공식 계약 확인, public repo 신뢰 경계 설계, dispatcher workflow 구현

## 검증

- OpenAI Workspace Agents API가 published API channel의 `agtch_...` ID, bearer Workspace Agent access token, `conversation_key`, `Idempotency-Key`를 지원하는 공식 계약 확인
- Issue body/comment를 Dispatcher prompt에 직접 삽입하지 않음
- `AGENTS.md`, `.wave/`, `CLAUDE.md`, #288을 Issue보다 먼저 읽도록 trigger input에 고정
- trusted collaborator의 opened/reopened만 자동 호출
- 외부 Issue는 권한 있는 사람이 `status:triage`를 명시적으로 부여한 뒤 호출 가능
- 같은 Issue는 `wave-github-issue-<number>` conversation key 사용
- GitHub run id 기반 idempotency key 사용
- API 202 Accepted만 확인하고 Agent 결과는 GitHub/Notion side effect로 남기도록 설계
- Secret 누락 시 #294 경고 후 정상 종료, 값 자체 출력 없음
- 저장소 CI 결과를 PR에서 확인

## 결과와 제한

- 실제 활성화에는 #294의 `WAVE_PM_AGENT_TRIGGER_ID`와 `WAVE_PM_AGENT_ACCESS_TOKEN` 설정이 필요함
- 사용 중인 ChatGPT workspace에서 published Workspace Agent API channel/access token 기능이 제공되지 않으면 PM 실행기만 별도 API 기반 Orchestrator로 교체해야 하며 GitHub state contract는 유지 가능
- Agent run의 최종 응답 본문은 API에서 직접 회수하지 않고 GitHub/Notion 갱신을 결과로 사용함
