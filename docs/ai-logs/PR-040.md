# PR #40 AI 작업 로그

## 요청

- PR별 시맨틱 태그와 릴리즈를 정확한 과거 병합 커밋에 생성한다.
- 릴리즈가 완성되기 전 다른 PR이 잘못된 다음 버전을 만들지 않게 한다.

## 발견한 문제

- 기본 `GITHUB_TOKEN`은 과거 커밋에 포함된 `.github/workflows/ci.yml` 변경 때문에 태그 push를 거부했다.
- 필요한 `Workflows` 쓰기 권한은 워크플로의 `permissions` 항목으로 기본 토큰에 추가할 수 없다.
- 백필이 미완료인 상태에서 일반 Release가 실행되면 현재 유일한 `v0.1.0` 다음인 `v0.1.1`을 새 PR에 잘못 붙일 수 있다.

## 변경

- 백필을 자동 push 트리거에서 명시적인 `workflow_dispatch`로 전환했다.
- `Contents: read/write`, `Workflows: read/write` 권한의 fine-grained token을 `RELEASE_GITHUB_TOKEN` Secret으로 받도록 구성했다.
- checkout과 백필 API·git push가 같은 전용 토큰을 사용한다.
- 일반 자동 릴리즈는 전체 백필 기준인 `v0.7.5`가 존재하기 전에는 성공 종료하며 릴리즈 생성을 건너뛴다.
- PR #39의 확정 SHA를 고정하고 이 PR을 `v0.7.5`로 추가했다.

## 안전 검토

- 전용 토큰이 없으면 백필은 첫 단계에서 명확한 오류로 중단된다.
- 기본 워크플로 토큰은 다시 `contents: read` 최소 권한으로 낮췄다.
- 일반 CI·CD와 프로덕션 환경변수는 변경하지 않았다.
