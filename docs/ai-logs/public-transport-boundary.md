# 공공교통 제공처 경계 AI 작업 로그

- 작성자: jeongiryang / Codex Engineering·QA
- 범위: Refs #277 #282. 인증키 선택과 실행하지 못한 도착정보의 상태.
- 상태: 로컬 검증, 미병합·미배포.

## 근거와 수정

공통 helper가 TAGO → KORAIL → 공통 키 순서로 하나를 골라 모든 제공처에 보냈다.
전용 키가 서로 다를 때 KORAIL 요청에 TAGO 키가 사용됐고, 한 제공처만 설정해도
다른 제공처 요청을 실행했다. 실제 TypeScript 모듈을 합성 fetch로 실행해 재현했다.

제공처를 필수 인자로 전달하고 자기 전용 키 또는 공통 공공데이터 키만 사용한다.
키가 없는 제공처는 호출하지 않으며 health 설정 판정도 두 제공처를 함께 확인한다.
정류장 조회 실패로 실행할 수 없는 도착정보에는 의존 실패를 전파한다. 정류장 빈 결과는
오류로 바꾸지 않고 실제로 도착 API를 호출하지 않았다고 설명한다.

## 운영 제한

Production `34e6021`의 KORAIL/TAGO 지연과, 호출하지 않은 도착정보가 ready인 응답을
확인했다. 이 변경이 현재 상류 timeout 원인을 해결했다고 주장하지 않는다. 특히 운영은
공통 키를 쓰는 것으로 알려져 있어 전용 키 충돌 재현과 운영 장애 원인을 구분한다.
새 배포 후 제공처별 응답·실패 복구·도착정보 실제 조회를 다시 확인해야 한다.
필수 사람 승인 3건·008 점검·#309 보안 통합과 유료 모델 API 차단을 유지한다.
