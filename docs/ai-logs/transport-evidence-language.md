# 교통 조회 근거와 한·영 상세 화면

## 범위와 의존성

Issue #251, #265, #275, #277, #282, #285, #286의 교통 상세 범위다.
부모 #326의 지도 검색/경로/일정 변경과 #316 9792cbf의 엄격한 공공교통 응답 검증을 합성했다.
운영 적용·전체 Issue 완료·Release GO를 의미하지 않는다.

## 재현과 수정

- 조회 실패, 실제 조회 0건, 미조회, 근거 없는 과거 ready 상태가 같은 빈 결과로 표시됐다.
  서버에 queryStatus/resultCount를 추가하고 UI는 각 상태와 재조회 행동을 구분한다.
- 도착시간 누락을 운행 중으로, 정류장 수 누락을 정류장 접근 중으로 표현했다.
  누락/유효한 0을 구분하고 시간·정류장 수 미확인으로 표시한다.
- 철도 지역/터미널 목록을 운행 확인으로 표현했다. 목록·열차 계획·실제 승차권의 범위를
  구분하고 KORAIL 조회일과 선택한 여행 날짜/구간이 다름을 명시한다.
- 교통 상세, 이동수단 필터, 공식 예매 안내를 한국어/영어로 제공한다. 원문 정류장명은
  lang 속성과 원문 안내를 제공한다. 예약/결제는 외부 제공기관에서 진행한다.
- 재조회 때 context가 비면서 버튼이 unmount되어 포커스를 잃었다. 패널을 유지하고
  중복 Enter를 막되 pending 버튼의 포커스를 유지한다. 응답 실패도 재조회할 수 있다.
- 320px 텍스트 잘림과 viewport 변경 후 화면 밖에 남는 focused 버튼을 재현했다.
  줄바꿈과 기존 focus 가시성 observer를 재사용했다. 포커스를 새로 빼앗지 않으며
  휠/터치/포인터 이동 후에는 자동 스크롤 추적을 중단한다.
- 상세 모듈은 열 때만 로드한다. 로드 실패는 일정 편집을 남겨 두고 새로고침을 안내한다.

## Production 검사 계약

기존 KORAIL ready는 실제 호출이 없어도 통과했고, TAGO 도착정보는 검증된 실제 0건도 실패했다.
새 검사는 설정 여부뿐 아니라 엄격한 parser를 거친 queryStatus=success와 정수 resultCount를
필수로 요구한다. 정류장/지역/터미널 목록은 양수 기록을 요구한다. 현재 도착정보와 KORAIL만
실제 요청이 성공한 0건을 허용한다. 미조회/오류/근거 없는 legacy ready는 통과하지 않는다.
실제 fetch→parser→snapshot→응답 근거→Production 판정 경계를 합성 fetch로 검증한다.
타임아웃·재시도 횟수·검사 항목 수는 유지한다. old Production 34e6021에는 새 근거가 없어
이 계약으로 성공을 주장할 수 없다. 키 존재/HTTP 200/로컬 fixture를 실연동 성공으로 세지 않는다.
