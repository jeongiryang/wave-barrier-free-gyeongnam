# PR #39 AI 작업 로그

## 요청

- 과거 병합 PR별 시맨틱 버전 태그와 GitHub Release를 모두 생성한다.
- 생성된 릴리즈와 태그 SHA가 실제 PR 병합 이력과 일치하는지 검증한다.

## 발견한 문제

- PR #38의 제한적 교정은 잘못된 `v0.1.1` 태그와 릴리즈를 정상 삭제했다.
- 그러나 Actions의 `GITHUB_TOKEN`은 Releases API가 과거 커밋에 새 태그까지 함께 만들려는 요청을 `403 Resource not accessible by integration`으로 차단했다.
- 같은 토큰으로 현재 커밋의 릴리즈를 만드는 것은 성공했으므로, 제한은 과거 SHA의 묵시적 태그 생성 경로에 있었다.

## 변경

- 릴리즈가 없는 버전은 먼저 로컬 lightweight tag를 정확한 병합 SHA에 만든다.
- `actions/checkout`이 저장한 동일 `GITHUB_TOKEN` 인증으로 해당 태그만 origin에 push한다.
- 원격 태그 SHA를 다시 읽어 예상 SHA와 일치한 경우에만 기존 태그를 대상으로 GitHub Release를 생성한다.
- Releases API 요청에서 과거 SHA의 묵시적 태그 생성을 유발한 `target_commitish`를 제거했다.
- PR #38의 병합 SHA를 고정하고 이 PR을 `v0.7.4`로 추가했다.

## 안전 검토

- 워크플로 권한은 기존의 `contents: write`만 유지한다.
- force push를 사용하지 않으며, 기존 태그가 다른 SHA면 즉시 실패한다.
- 생성 후 원격 태그 SHA를 재검증한다.
- Secret과 배포 환경변수는 변경하지 않았다.
