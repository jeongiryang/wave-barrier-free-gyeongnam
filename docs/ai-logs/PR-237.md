## 목적

실제 Production 빌드의 RSC 자산 manifest와 gzip 전송량을 기준으로 공개 랜딩의 인증 SDK, 안내형 플래너의 숨은 지도, 원격 이미지와 hover 사진 요청을 지연한다. 커뮤니티와 사진 코스의 느리거나 순서가 뒤바뀐 응답은 timeout·abort·요청 식별자로 격리하고, 실패 뒤에도 UI가 로딩 상태에 고착되지 않도록 복구 경계를 둔다.

## 역할 구분

- 사람: 마감 전 성능·안정성 점검 범위와 우선순위 제시, 최종 승인
- AI: 기준 빌드 측정, 코드·테스트·CI 예산 구현, 정적·Production 빌드 검증

## 구현 경계

- 커뮤니티 요청은 기본 12초 timeout, 상위 signal 전달, `aborted|timeout|network|invalid|http` 오류 종류와 `finally` 정리를 한 API 경계에서 처리한다. 목록·상세·랜딩 미리보기는 이전 요청을 취소하고 현재 controller만 상태를 갱신한다.
- 댓글·좋아요·삭제·신고·운영 처리도 네트워크 예외 뒤 버튼과 상태가 복구되며, 랜딩 미리보기는 실패를 빈 목록으로 가장하지 않고 재시도 동작을 제공한다.
- 사진 코스 공식정보 요청은 stop별 controller, 12초 timeout, 요청 identity를 사용한다. 파일 재선택·초기화·이름 또는 지역 수정·unmount 시 기존 응답이 최신 편집을 덮지 못한다.
- 모든 실제 `<img>`에 고유 크기, `loading="lazy"`, `decoding="async"`를 명시했다.
- 지역 사진은 180ms hover intent 뒤 요청하며 이탈 시 미완료 요청을 취소한다. 사용자 이탈과 실제 10초 timeout을 구분해 timeout은 fallback으로 끝나고 다시 시도할 수 있다.
- touch contract는 selector가 사라지면 숨김으로 간주해 건너뛰지 않고 즉시 실패한다.
- CI는 실제 빌드 manifest에 대해 CSS 70 KiB gzip, 랜딩 155 KiB gzip/520 KiB raw, 플래너 270 KiB gzip, 최대 chunk 110 KiB gzip을 제한하며 랜딩 인증과 플래너 지도 청크의 eager 포함을 별도로 금지한다.

## 검증

- `npm run lint` 통과

## 결과와 제한

- 초기 비용 감소는 인증 SDK와 숨은 지도라는 실측 상위 비용에 집중했고, 광범위한 CSS 재배치는 하지 않았다.
- 브라우저 네트워크 수치는 E2E 사양과 Production manifest로 고정했지만 실제 Web Vitals는 배포 Preview/Production에서 별도로 수집해야 한다.
- 성능 예산은 현재 실측값 대비 약 10~31%의 빌드 변동 여유를 둔다. 기능 추가로 초과하면 무조건 수치만 올리지 말고 새 초기 의존성의 필요성을 먼저 검토한다.
