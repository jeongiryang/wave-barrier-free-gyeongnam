# PR-165 — 부드러운 스크롤이 움직임 줄이기 설정을 무시하던 문제

## 목적

플래너의 자동 화면 이동 7곳이 `prefers-reduced-motion: reduce`를 무시하고
언제나 애니메이션으로 스크롤하던 문제를 고친다. CLAUDE.md가 명시한
"애니메이션은 `prefers-reduced-motion: reduce`에서 멈춘다"를 어기고 있었다.

## 원인

CSS는 이미 올바르게 되어 있었다. `app/styles/place-dialog.css`의 reduced-motion
블록이 `scroll-behavior: auto !important`를 전역으로 건다. 브라우저에서 확인해도
`getComputedStyle(document.documentElement).scrollBehavior`가 `auto`로 나온다.

문제는 CSSOM View 명세다. `scrollIntoView`에 **명시적으로** 넘긴 `behavior`는
CSS `scroll-behavior`보다 우선한다. 코드가 `behavior: "smooth"`를 그대로
넘기고 있었으므로 CSS가 무엇을 걸든 소용이 없었다.

## 브라우저 측정 (reduced-motion 적용, 1440×960)

"이곳까지 길찾기"를 누른 뒤 40ms 간격으로 `window.scrollY`를 12번 샘플링했다.

| | 서로 다른 위치 수 |
| --- | --- |
| 수정 전 | 7 (애니메이션이 그대로 돎) |
| 수정 후 | 1 (즉시 이동) |

## 변경

- `lib/reduced-motion.js` — `prefersReducedMotion`, `scrollBehavior`,
  `scrollToSection`. 이동을 시작하는 쪽에서 설정을 읽는다.
- 호출부 7곳을 `scrollToSection(...)`으로 교체했다.
  `PlannerHeader`, `RecommendationCarousel`, `SituationImpactPanel`,
  `usePlanRequest`, `usePlannerImpactAction`(2곳), `usePlannerPointActions`.
- `tests/reduced-motion.test.mjs` — 순수 함수 단위 테스트 4건.
- `e2e/reduced-motion-scroll.spec.ts` — 실제 스크롤 궤적으로 확인. 설정을 켜면
  즉시 이동, 끄면 부드러운 이동이 유지되는지 양쪽 다 고정한다.

## 설계 판단

**CSS를 더 세게 거는 대신 코드에서 읽었다.** 명세상 JS 인자가 CSS를 이기므로
스타일시트로는 이 문제를 고칠 수 없다. 선택지는 호출부마다 조건문을 넣거나
헬퍼 하나로 모으는 것뿐이고, 7곳에 같은 조건문을 흩는 것은 다음 호출부에서
다시 빠뜨리기 쉽다.

**`lib/`에 두어 단위 테스트가 가능하게 했다.** `document`·`window`가 없는
node 테스트 환경에서도 안전하게 기본값을 돌려주며, 주입 가능한 인자를 남겨
DOM 없이 동작을 고정할 수 있다.

**끈 사용자만 바뀐다.** 기본 설정에서는 부드러운 이동이 그대로 유지되는지도
e2e로 함께 고정했다.

랜딩·커뮤니티에는 자동 스크롤 호출부가 없어 이번 범위에 포함되지 않았다.
