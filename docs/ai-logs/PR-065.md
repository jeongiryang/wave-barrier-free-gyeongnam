# PR #65 · RouteMap 책임 경계 분리

## 발견

`components/RouteMap.tsx`가 React 지도 화면과 함께 공통 route 타입, Kakao SDK
선언·script 수명주기, 주변 카테고리, URL 정제, 측정 계산, 혼잡 표현, 1600px
이미지 렌더링까지 한 파일에서 관리하고 있었다. Planner 도메인도 UI 컴포넌트에서
route 타입을 가져와 지도 표현 변경의 영향 범위가 불필요하게 넓었다.

## 구현

- `features/routing/types.ts`: Planner와 지도가 공유하는 route·place·UI 상태 타입을 분리했다.
- `features/routing/kakao-sdk.ts`: Kakao 타입 선언, 중복 script 방지, 12초 timeout과
  실패 후 재시도 가능한 SDK 수명주기를 분리했다.
- `features/routing/map-utils.ts`: 안전한 이미지 URL, popup HTML escape, 거리·반경·면적
  계산과 관광 집중도 표현을 독립 함수로 옮겼다.
- `features/routing/export-route-image.ts`: 1600×1000 공유 이미지를 만드는 Canvas 동작을
  지도 렌더링 컴포넌트 밖으로 분리했다.
- 주변 장소와 레이어 정의를 `features/routing/constants.ts`로 옮겼다.
- Planner hook과 util은 UI 컴포넌트가 아니라 routing domain 타입을 직접 사용한다.
- `RouteMap.tsx`는 820줄/약 52KB에서 562줄/약 37KB로 줄었다.
- 새 경계를 다시 합치지 않도록 repository 회귀 테스트를 추가했다.

## 역할 구분

- 사람: 지도 UI와 Planner 비즈니스 로직의 결합을 줄이고 독립 테스트 가능한 경계를 만들라는 기준 위임
- 도구: 책임 감사, routing feature 분리, 전체 회귀·빌드·배포 검증

## 배포 영향과 제한

- 지도 UI, 공급자 우선순위, API 요청, GPS 비저장 정책과 route schema는 변경하지 않는다.
- Kakao 실패 시 OpenStreetMap fallback과 이미지 내보내기 결과를 기존과 동일하게 유지한다.
- 지도 provider 렌더링 effect 자체는 callback 의존성이 높아 이번 안전한 단위에서 억지로
  adapter화하지 않았다. 후속 변경은 이 feature 경계를 기반으로 점진적으로 진행한다.
