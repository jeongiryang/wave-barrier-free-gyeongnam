# 카카오 로그인과 계정 메일 연결 AI 작업 로그

- PR: 생성 후 #351에 링크와 최종 배포 결과 기록
- 작성자: jeongiryang / Codex
- 최종 상태: 로컬 구현·필요 검사 완료, CI와 운영 활성화 검증 대기
- AI 도구: Codex, 로컬 Node/Playwright, 인증된 관리자 브라우저, GitHub CLI

## 목적

관리형 Neon Auth가 지원하지 않는 카카오 로그인을 기존 계정과 같은 DB·UUID로 연결한다. 이메일 로그인·비밀번호 복구·탈퇴를 함께 유지하며 새 제공자 연결에 필요한 실제 메일을 연결한다. PDF 시안은 이미 #449에 독립 병합됐으며 이 PR은 인증 작업이다.

## 역할 구분

- 사람: 로그인, 개인 개발자 비즈 앱·아이콘 저장, Google 앱 비밀번호 생성과 Vercel SMTP_PASS 입력, 현재 작업 병합·배포 권한 부여.
- AI: 실제 스키마·권한·해시 형식 조사, 기존 키/Secret 전달과 callback·웹훅 등록, 추가형 DB 마이그레이션, 구현·문서·검사·PR. 비밀값은 소스·문서·로그에 기록하지 않았다.

## 검증

- 실제 Better Auth와 격리 SQLite를 사용한 기존 UUID/독립 생성 scrypt 해시 로그인, 일회용 재설정과 세션 폐기, 카카오 email scope/state/연결·해제, 자동 이메일 병합 금지, 취소된 세션의 callback 거부, 이메일 탈퇴 확인.
- 실제 외부 제공자 응답을 흉내 낸 통합 테스트는 운영 Kakao 성공의 증거가 아니다. Gmail 검사도 실제 전송 없이 SMTP 인증하도록 CD 승격 전 단계에 연결했다.
- 로컬 단위 검사 784개, typecheck/lint/build/성능 예산 통과. 기존 lint 경고 13개, 오류 0개. 프로덕션 CSS 약 69.99 KiB로 70 KiB 예산 유지.
- 로그인·복구·계정 관리 Playwright 14개 통과(8.9초). 초기 개발 서버에서 변경된 의존성의 오래된 캐시로 실패한 두 실행을 중단한 뒤 Vite `--force`로 재시작하여 해결했다. 소스나 테스트 기준을 완화하지 않았다.
- 빌드된 화면을 시험용 계정 응답으로 1440/960/390px에서 확인했다. 카카오 버튼 실패 복구, 연결 상태·OAuth 전용 계정 관리, 모바일 넘침 없음. 실제 운영 로그인을 의미하지 않는다.
- DB 추가 SQL COMMIT 후 사용자 6명·계정 6개 보존, 새 인덱스/테이블 존재 확인. 사용자 데이터 복사나 비밀번호 변경 없음.
- 최초 PR CI는 새 lockfile과 기존 불변 배포 해시 차이로 bootstrap 단계에서 거절됐다. 다른 실행기/경계 파일 16개 해시는 모두 일치했다. 검토한 lockfile과 이를 포함한 불변 commit으로 배포 해시를 갱신했으며 workflow/test의 예상 pin만 함께 바꿨다. 권한·격리·실행 명령·검사·실패 기준은 유지했다. Python bootstrap 변조 거부 검사와 CI 계약 검사 통과.

## 결과와 제한

- Production 승격 전 동일 SHA CI와 인증 DB/SMTP preflight, 승격 후 운영 페이지·실제 제공자 왕복 결과를 PR/#351에 기록한다. 확인 전 완료로 표시하지 않는다.
- 전환 시 새 쿠키 때문에 다시 로그인해야 한다. 기존 계정이 있으면 이메일 로그인 후 계정 관리에서 명시적으로 카카오 연결한다.
- Gmail 개인 계정 제한, ODsay 하루 30건, 그 외 외부 API 용량은 `docs/api-launch-risk-20260910.md`와 #365에 기록했다. 불필요한 실제 경로 재검사는 없다.
- 관리형 Auth의 데이터 보존 종료, 법적 위치정보 판단, 공모전 제출 GO는 별도 미완료 상태로 기록한다. 공모전 공식 Notion/OT 영상 조사 결과는 #11에 남겼다.
