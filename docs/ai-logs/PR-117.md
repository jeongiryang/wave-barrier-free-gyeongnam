# PR-117 — 여행 계획 query와 응답 모델 분리

## 목적

관광 계획 builder에 입력 query 해석, 공식 데이터 요청, 접근성 우선 정렬, 일정 설명, provider 상태 생성이
함께 있던 구조를 orchestration과 순수 도메인 모델로 분리한다.

## 변경

- 지역·테마·언어·접근성 조건과 검색 매개변수 생성을 `plan-query`로 이동
- 접근성 근거 우선 정렬을 `sortPlacesByEvidence`로 분리
- 추천 장소·중심 관광지·연관 관광지·코스를 일정 설명으로 만드는 로직을 `buildPlanStops`로 분리
- provider provenance 상태와 live/partial/fallback 판정을 `buildPlanStatuses`로 분리
- builder는 공식 provider 요청 순서와 최종 응답 조합에 집중

## 안전성

공식 근거가 있는 후보 우선 정렬, 근거 부족 후보의 판단 보류, 지역·언어 fallback, partial provider 상태,
가짜 장소를 만들지 않는 정책과 기존 API 호출 범위를 유지한다.
