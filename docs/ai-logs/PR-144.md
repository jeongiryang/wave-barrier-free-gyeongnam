# PR-144 — 잔여 클라이언트 책임 경계 정리

## 목적

점진적 모듈화 이후에도 남아 있던 파동 캔버스 수명주기·렌더링 엔진 결합,
경로 hook의 endpoint 조립, 환경설정 카탈로그와 번역 데이터 결합을 분리한다.

## 변경

- 파동 효과의 React ref/effect 수명주기와 imperative canvas engine을 분리
- 경로·관광 집중 요청 URL과 응답 타입을 planner data service로 이동
- locale 목록·Beta 상태·모션 문구를 제품 번역 사전에서 분리
- Auth, Community, Planner, 공유 여행의 내부 route 링크를 Next `Link`로 통일
- 새 경계를 고정하는 planner·repository·production 회귀 테스트 보강

## 설계 판단

- `app/planner/page.tsx`는 controller 조합과 feature section wiring만 담당하므로
  추가 wrapper로 쪼개지 않았다.
- 큰 번역 사전, 파동 엔진, provider adapter는 크기보다 단일 책임이 명확해진
  데이터/도메인 모듈이므로 더 작은 임의 파일로 분해하지 않았다.
- CSS는 이미 token/base와 feature별 stylesheet로 분리되어 있어 기존 cascade
  경계를 유지했다.

## 안전성

파동의 reduced-motion, viewport·visibility 정지, resize와 pointer cleanup을
유지했다. 경로 AbortSignal과 stale-response 차단, private origin 비전송 정책도
그대로 유지한다.
