# PR 120 — 플래너 조건과 여행 계획 요청 수명주기 분리

## 목적

- 하나의 훅에 섞여 있던 여행 조건 상태와 네트워크 요청 수명주기를 독립 책임으로 분리한다.
- 조건 선택 UI를 변경할 때 공식 관광 데이터 요청·취소 로직에 미치는 영향을 줄인다.
- 플래너 페이지의 공개 인터페이스는 유지해 기능 회귀 없이 점진적으로 구조를 개선한다.

## 변경

- `usePlannerCriteria`가 접근성 조건, 지역, 테마와 URL 지역 복원을 관리한다.
- `usePlanRequest`가 계획 요청, 중복 요청 취소, 오류·안내 상태와 결과 수명주기를 관리한다.
- `usePlannerPlan`은 두 책임을 조합하는 얇은 파사드로 축소했다.
- 구조 정책 테스트가 분리된 구현 파일까지 검증하도록 갱신했다.

## 위험과 대응

- 공개 반환 형태를 유지해 기존 플래너 화면과 컨트롤러 호출부를 변경하지 않았다.
- 요청마다 `AbortController`를 교체하고 unmount 시 취소해 오래된 응답이 최신 조건을 덮지 않게 했다.
