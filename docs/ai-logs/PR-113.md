# PR-113 — 공유 여행 화면 분리

## 목적

공유 여행 route가 URL 식별자, 35초 request 수명주기, 복원 상태, 장소·일정 UI와 footer까지
한 파일에서 처리하던 구조를 trips feature 경계로 분리한다.

## 변경

- 공유 여행 응답 계약을 `features/trips/types`로 이동
- API 요청·malformed response 처리를 client data layer로 이동
- timeout·abort·retry·파생 날짜를 `useSharedTrip` controller로 이동
- hero·복원 안내·장소 목록·날짜별 일정을 표현 컴포넌트로 분리
- route를 SharedTripScreen composition만 담당하도록 축소하고 회귀 테스트 갱신

## 안전성

35초 timeout, unmount abort, malformed JSON 복구, 최신 공식 정보 재조회 안내, 정보가 사라진 장소의
fallback·제외 구분과 accessible loading/error 상태를 유지한다.

## 영향

공유 API·request 수명주기·장소 카드·일정 렌더링을 독립적으로 변경하고 테스트할 수 있다.
