# PR-100 — 공유 여행 영속화 경계 분리

## 목적

공유 일정 API가 스키마 준비, 요청 정규화, 일정 복원·저장, 접근성 제보까지 한
handler에서 처리하던 구조를 데이터·도메인 action·HTTP 경계로 분리한다.

## 변경

- Neon 연결과 `itineraries`·`place_feedback` 스키마 준비를 `database.ts`로 이동
- 공유 조건 정규화와 최소 저장 payload 구성을 `payload.ts`로 이동
- 공유 일정 조회·복원과 저장을 `itinerary-actions.ts`로 이동
- 접근성 제보 검증·저장을 `feedback-handler.ts`로 분리
- `handler.ts`는 메서드 라우팅과 사용자용 장애 응답만 담당
- worker와 구조 회귀 테스트를 새 경계에 맞게 갱신

## 안전성

기존 Origin·Fetch Metadata·본문 크기 검증, 공식 ID 기반 최신 데이터 복원,
30일 만료, 최소 payload 저장, 제보 길이 제한과 오류 문구를 그대로 유지한다.

공유 일정 정책, DB 스키마, 접근성 제보를 서로 독립적으로 변경하고 테스트할 수 있다.
