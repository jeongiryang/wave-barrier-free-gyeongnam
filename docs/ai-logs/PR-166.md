# PR-166 — 상류 장애 응답이 CDN에 30분 캐시되던 문제

## 목적

한국관광공사 API가 잠깐 흔들려 502를 돌려준 응답이 Vercel 엣지에 30분 동안
고정되던 문제를 고친다. 상류가 복구돼도 사용자는 계속 실패 화면을 봤고,
새로고침도 재시도 버튼도 소용이 없었다.

## 원인

`server/shared/http.ts`의 `json()`은 세 번째 인자 `cache`만 보고 캐시 헤더를
정했다. 상태 코드는 보지 않았다.

```ts
"cache-control": cache ? "public, max-age=300, s-maxage=1800" : "no-store",
```

관광 사진·혼잡도 핸들러는 성공과 실패를 같은 자리에서 만들어 낸다.

```ts
// server/tourism/handler.ts:21, 48
return json({ ... }, result.ok ? 200 : 502, true);
```

실제 함수로 확인한 값:

```
json(_, 200, true) → "public, max-age=300, s-maxage=1800"
json(_, 502, true) → "public, max-age=300, s-maxage=1800"   ← 실패가 30분 캐시
json(_, 503, true) → "public, max-age=300, s-maxage=1800"
```

## 변경

- `lib/http-cache.js` — `cacheControlHeader(cacheable, status)`. 2xx·3xx만 캐시하고
  나머지는 `no-store`를 돌려준다.
- `server/shared/http.ts` — `json()`이 이 정책을 쓴다.
- `tests/http-cache.test.mjs` — 400·403·404·413·429·500·502·503이 캐시 요청을
  무시하는지 고정한다.

수정 후:

```
json(_, 200, true) → "public, max-age=300, s-maxage=1800"
json(_, 502, true) → "no-store"
json(_, 503, true) → "no-store"
```

## 설계 판단

**호출부가 아니라 `json()`에서 막았다.** 두 호출부에 조건을 넣어도 되지만,
성공·실패를 한 표현식에서 만들어 내는 형태가 남아 있는 한 다음 핸들러에서
같은 실수가 반복된다. 상태 코드는 이미 `json()`에 있으므로 판단에 필요한 정보가
전부 모이는 자리다.

**정책을 `lib/*.js`로 뺐다.** 이 저장소는 테스트가 필요한 정책을 `.js`로 두고
서버 모듈이 가져다 쓴다(`lib/trips/write-budget.js` → `server/trips/write-budget.ts`,
`lib/community/moderation.js`, `lib/deployment/production-env.js`). CI의 Node
22.13에서는 `node --test`가 `.ts`를 바로 읽지 못하므로, 이 관례를 따라야
동작 자체를 단위 테스트로 고정할 수 있다.

**성공 응답의 캐시는 그대로 뒀다.** 실시간 조회 부담을 줄이는 의도적인 설정이며
이 PR의 범위가 아니다.

  영향을 줄 수 없다.

200 응답 캐시는 그대로다.
