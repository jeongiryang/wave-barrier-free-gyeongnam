# PR-189 — 테마가 뒤집는 배경 토큰에 글자색이 따라가지 않던 문제

## 목적

어두운 화면에서 대비 1.11의 글자를 없앤다. 흰 글자가 밝은 배경 위에 남아
사실상 보이지 않는 상태였다.

## 원인

다크 테마는 토큰의 의미를 뒤집는다.

| 토큰 | 밝은 화면 | 어두운 화면 |
| --- | --- | --- |
| `--ink` | `#06304a` (어두운 글자색) | `#e8f5fb` (밝은 색) |
| `--white` | `#fff` | `#04202f` (어두운 색) |

29개 규칙이 배경만 토큰으로 두고 글자색은 흰색으로 고정하고 있었다.

```css
.landing-start { color: #fff; background: var(--ink); }
```

밝은 화면에서는 짙은 배경 + 흰 글자로 맞지만, 어두운 화면에서는 밝은 배경 위
흰 글자가 된다.

## 측정 (axe-core, WCAG 2 AA)

| 화면 | 어두운 화면 전 | 후 | 밝은 화면 전 | 후 |
| --- | --- | --- | --- | --- |
| `/` | 31건 | **0건** | 7건 | **0건** |
| `/community` | 10건 | **0건** | 0건 | 0건 |
| `/community/new` | 0건 | 0건 | 0건 | 0건 |
| `/planner` · `/photo-course` | 0건 | 0건 | 0건 | 0건 |
| `/login` · `/register` | 14건씩 | 12건씩 | 0건 | 0건 |

로그인·가입에 남은 12건씩은 `account-auth.css`에 다크 규칙이 없어서 생기며
별도 작업 단위(PR #191)에서 다룬다.

## 변경

- `--ink` 배경: CSS 13개 파일, 29개 선언에서 `color: #fff` → `color: var(--white)`.
- `--blue` 배경: `--on-blue` 토큰을 새로 두고(밝은 화면 `#fff`, 어두운 화면
  `#04202f`) 17개 파일, 32개 선언을 옮겼다. 기본 동작 버튼이 여기 해당한다.
- `tests/theme-contrast.test.mjs` — 패턴 재발 방지 5건.
- `e2e/dark-theme-contrast.spec.ts` — 두 테마에서 실제 대비 측정 2건 (기본 동작 버튼 포함).
- `e2e/theme-contrast-sweep.spec.ts` — 5개 화면 × 두 테마에서 axe 대비 위반이
  0건인지 고정 2건.
- 어두운 화면에서도 밝게 남는 작은 표면(기능 미리보기 카드 안 패널, 커뮤니티
  푸터, 선택한 지역 칩)의 안쪽 글자를 어둡게, 어두운 표면 위 흐린 보조 문구는
  밝게 옮겼다.
- 밝은 화면에서 4.5:1에 못 미치던 보조 문구 3종(`.preview-note`,
  `.access-preview > footer`, `.landing-scroll`)의 색을 조정했다.

## 설계 판단

**개별 색 대신 짝이 되는 토큰을 썼다.** 규칙마다 다크 오버라이드를 추가하면
29개 블록이 늘고 다음에 또 빠진다. `--white`는 이미 `--ink`의 반대쪽으로
정의돼 있어 테마가 바뀔 때 함께 뒤집힌다.

**밝은 화면 결과는 그대로다.** `--white`가 밝은 화면에서 `#fff`이므로 기존
렌더링이 바뀌지 않는다. e2e가 양쪽을 모두 검사한다.

## 결과와 제한

로그인·가입 화면(어두운 화면 12건씩)은 PR #191에서 다룬다. 두 PR을 함께
반영하면 검사한 7개 화면이 두 테마 모두 0건이 된다.

이 검사는 axe-core가 계산할 수 있는 대비만 본다. 사진 위에 얹은 글자, 그라디언트
배경, 그리고 화면에 보이지 않는 상태(패널을 열어야 나오는 요소)는 포함되지
않는다.
