# PR-189 — 어두운 화면에서 흰 글자가 밝은 배경에 묻히던 문제

## 목적

어두운 화면에서 대비 1.11의 글자를 없앤다. 흰 글자가 밝은 배경 위에 남아
사실상 보이지 않는 상태였다.

## 원인

다크 테마는 토큰의 의미를 뒤집는다.

| 토큰 | 밝은 화면 | 어두운 화면 |
| --- | --- | --- |
| `--ink` | `#06304a` (어두운 글자색) | `#e8f5fb` (밝은 색) |
| `--white` | `#fff` | `#04202f` (어두운 색) |

29개 규칙이 배경만 토큰으로 두고 글자색은 흰색으로 고정하고 있었다.

```css
.landing-start { color: #fff; background: var(--ink); }
```

밝은 화면에서는 짙은 배경 + 흰 글자로 맞지만, 어두운 화면에서는 밝은 배경 위
흰 글자가 된다.

## 측정 (axe-core, WCAG 2 AA, 어두운 화면)

| 화면 | 수정 전 | 수정 후 |
| --- | --- | --- |
| `/` | 31건 | 19건 |
| `/community` | 10건 | 6건 |
| `/login` | 14건 | 13건 |
| `/register` | 14건 | 13건 |
| `/planner` · `/photo-course` | 0건 | 0건 |
| 합계 | 69건 | 51건 |

`#ffffff on #e8f5fb`(1.11) 18곳이 완전히 사라졌다.

## 변경

- CSS 13개 파일, 29개 선언에서 `color: #fff` → `color: var(--white)`.
- `tests/theme-contrast.test.mjs` — 패턴 재발 방지 3건.
- `e2e/dark-theme-contrast.spec.ts` — 두 테마에서 실제 대비 측정 2건.

## 설계 판단

**개별 색 대신 짝이 되는 토큰을 썼다.** 규칙마다 다크 오버라이드를 추가하면
29개 블록이 늘고 다음에 또 빠진다. `--white`는 이미 `--ink`의 반대쪽으로
정의돼 있어 테마가 바뀔 때 함께 뒤집힌다.

**밝은 화면 결과는 그대로다.** `--white`가 밝은 화면에서 `#fff`이므로 기존
렌더링이 바뀌지 않는다. e2e가 양쪽을 모두 검사한다.

## 결과와 제한

남은 51건은 원인이 달라 별도 작업 단위로 남긴다.

- `#ffffff on #45aeea` (2.47, 4곳) — 기본 동작 버튼. `--blue`가 어두운 화면에서
  밝아지는데 글자는 흰색 고정.
- `#94b3c4 on #a5aeb3` (1.02, 6곳) — 로그인·가입 미리보기의 하드코딩된 회색.
- `#e8f5fb on #eef6f9` 계열 (1.01~1.04, 5곳) — 반대 방향. `--ink` 글자에
  밝은 배경 고정.
- `#78929d on #0a2e3d` (4.34, 5곳) — 4.5에 조금 못 미침.

밝은 화면에도 7건(3.05~4.22)이 남아 있다.
