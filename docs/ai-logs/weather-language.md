## 원인과 수정

- 클라이언트의 typed fetch가 실제 응답 검증을 대신했다. current=null 같은 잘못된 HTTP200이
  플래너 화면을 깨뜨렸다. weatherResponse가 날짜/필수 수치/배열/범위를 검사하고 미확인 상태로 보낸다.
  실제0도·0강수·미확인 날씨 코드는 보존한다. 가짜 맑음/0도/예보를 만들지 않는다.
- 날씨 실패 화면에 독립 재조회가 없었다. 날씨만 다시 조회하며 추천/일정은 재실행하지 않는다.
  pending 중 버튼의 DOM과 이름을 유지하고 aria-busy/aria-disabled와 별도 상태 안내를 제공한다.
  중복 Enter를 차단하고 조회 후에도 포커스·저장 장소가 유지된다.
- 첫 예보를 무조건 오늘로 불렀다. 실제 날짜와 한국 시간 기준, 조회 시각을 표시한다.
  예보 범위 밖의 현재 날씨를 여행 날짜 예보로 표현하지 않는다.
- 날씨/준비 문구와 일정 영향·대안 행동을 한국어/영어로 제공한다. 원문 장소명·알 수 없는
  준비 문구는 언어 속성과 원문 안내를 남긴다. 집중률은 예측이며 실제 방문자 수가 아님을 유지한다.
- 밝은 화면에 고정된 옅은 글자색을 테마 토큰으로 바꾸고 긴급 배지 대비3.45:1을 수정했다.
  날짜별 예보는 이름 있는 키보드 스크롤 영역이다. 재조회 포커스는 기존 가시성 observer를 재사용한다.
- 날씨 상세 코드는 열 때만 읽는다. 모듈 실패 시에도 일정을 사용할 수 있고 새로고침을 안내한다.
