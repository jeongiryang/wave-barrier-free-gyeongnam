# PR-083 — Planner 화면 feature section 분리

## 목적

Planner route가 모든 화면 markup과 상호작용을 직접 소유하지 않도록 조건, 추천,
상황, 이동, 결과·근거 영역을 feature component 경계로 분리한다.

## 변경

- `PlannerConditionsPanel`: 출발지·지역·테마·날짜·편의 조건
- `RecommendationWorkspace`: 추천 카드, 빈 상태, 보관함, 날짜별 일정
- `TravelSignalsPanel`: 날씨, 일정 영향, 방문·수요, 테마별 공공데이터
- `NavigationWorkspace`: 교통 데이터, 지도, 출발·도착 선택, 경로 비교
- `PlannerResultsPanel`: 일정, 오디오 해설, 공유, 추천 근거
- `PlannerServiceStatus`: 사용자용 데이터 이용 상태
- 지도 장소 변환을 `usePlannerActions`의 domain adapter로 이동
- 제품 테스트가 route와 feature component의 결합 결과를 검증하도록 갱신

## 결과

`app/planner/page.tsx`는 약 51KB에서 약 10KB로 줄었고, route-level controller wiring,
큰 화면 구성, 상세 dialog 연결에 집중한다. 기능별 UI와 상호작용은 서로 독립적으로
탐색하고 변경할 수 있다.
