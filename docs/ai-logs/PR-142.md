## 목적

한국관광공사 공식 무장애 정보로는 지금 현장의 계단·단차·경사로 상태를 알 수
없다. 사용자가 촬영한 현장 사진을 Gemini VLM으로 판독해 그 빈칸을 보완하되,
공식 데이터와 섞이지 않게 분리해 표시한다.

## 역할 구분

- 사람: 기능 요구사항 정의, 데이터 정책 기준(공식·VLM 분리, 키 비커밋),
  Gemini API Key 발급과 환경 변수 입력, 최종 승인
- AI: 기존 구조 조사, 서버·클라이언트·테스트·문서 작성, 네 가지 검사 실행,
  dev 서버 렌더링 확인, PR 작성

사람이 키를 직접 넣기로 한 결정에 따라 AI는 키 값을 생성하지 않았고
`.env.local`에 쓰지 않았다. `.env.example`과 README에 변수 이름만 안내했다.

## 구현 판단

기존 구조를 먼저 확인하고 그에 맞췄다.

- **의존성 0개 추가.** 저장소가 모든 외부 제공자를 SDK 없이 `fetch`로 부르므로
  Gemini도 REST로 붙였다.
- **판정 로직을 `lib/accessibility-vision.js`에 순수 함수로 분리.**
  `node --test`가 TypeScript를 빌드 없이 읽지 못하므로, `lib/trip-impact.js`
  패턴을 따라야 인증키 없이 검증할 수 있다.
- **사용자 유형은 기존 6종 재사용.** `wheel/senior/baby/pregnant/visual/hearing`.
  새 유형을 만들지 않았다.
- **기존 접근성 점수를 건드리지 않았다.** 이번 기능의 목적은 새 점수가 아니라
  현장 정보 제공이다.
- **사진 EXIF 제거를 필수 경로로 두었다.** 스마트폰 사진의 GPS가 서버로 나가면
  저장소의 위치정보 규칙이 깨진다. 캔버스 재인코딩으로 픽셀만 남긴다.

## 결과와 제한

- 병합 커밋: 미병합(검토 대기)
- **실제 Gemini 키와 TourAPI 키가 없어 스캐너 결과 화면을 1440px·960px에서
  눈으로 확인하지 못했다.** 결과 UI는 CSS 규칙과 단위 테스트로만 확인했다.
  키를 넣고 실제 사진으로 한 번 확인해야 한다.
- 실제 모델 응답에 대한 integration test는 없다. 키 없는 환경에서 전체
  테스트가 실패하지 않도록 단위 테스트만 두었다.
- 판정 규칙(요소별 이용자 영향)은 고정 표다. 현장 데이터가 쌓이면 조정이
  필요할 수 있다.
- 후속 작업 후보: 판독 결과를 기존 접근성 제보(`place_feedback`)와 연결해
  검수 상태를 부여하는 흐름. 이번 범위에서는 `accessibility_scan` 테이블에
  `verification_status`만 두고 승격 흐름은 만들지 않았다.
