## 목적

"조작 대상은 최소 44px"은 이 저장소가 스스로 정한 규칙이고(`CLAUDE.md`),
`experience-accessibility.css`에 그 규칙이 실제로 적혀 있다. 그런데 화면에서는
지켜지지 않고 있었다. 그 파일보다 **나중에 로드되는** 스타일시트가 같은 대상에
더 작은 `min-height`를 다시 적어 조용히 덮고 있었다.

재현한 값(1440px·390px 모두 동일):

| 조작 대상 | 눌리는 영역 | 적용된 min-height | 덮은 파일 |
| --- | --- | --- | --- |
| 계정 버튼 | 62×**42** | 42px | `account-auth.css`(27번) · `situation-identity-refinements.css` |
| 자세히 보기 | 89×**40** | 34px | `planner-service-status.css`(33번) |
| Kakao 재연결 | 95×**40** | 24px | `::after` 확장이 4px 모자람 |

`experience-accessibility.css`는 26번으로 로드된다. 27·33번이 뒤에 오면서
동일하거나 더 높은 특이도로 다시 적어 44px 규칙이 무력화됐다.

## 무엇을 어떻게 고쳤나

마지막(36번)에 로드되는 `mobile-interaction-hardening.css`에 옮겨 담았다. 이 파일의
헤더 주석이 이미 "작은 시각 요소는 유지하되 실제 조작 영역은 44px 이상 확보한다"고
적고 있어 의도가 정확히 일치한다. 폭과 무관한 계약이라 미디어 쿼리 밖에 뒀다.

- **계정 버튼 계열** — `min-height: 44px`. 순서로 이긴다(특이도 동일).
- **자세히 보기** — `.planner-service-status .tool-launch-status button`으로 특이도를
  맞췄다. 순서만으로는 `(0,2,1)` 대 `(0,1,1)`이라 이길 수 없었다.
- **Kakao 재연결** — 보이는 크기(79×24)는 그대로 두고 `::after`로 눌리는 영역만
  넓혔다. `inset: -8px -8px -14px`.

마지막 하나는 **아래로만** 넓혔다. 좁은 폭에서 이 배지는 명령 바 바로 아래 9px
간격에 놓이도록 이미 자리를 잡아 뒀고(`map-workspace.css`의 주석이 그 계산을
적어 두었다), 명령 바가 `z-index: 510`으로 위에 있어 위로 넓힌 만큼은 그 바가
먹는다. 실제로 위로 넓혔을 때 390px에서 41px에 그쳤다. 옆으로도 넓히지 않았다.
가로는 이미 95px이고, 더 넓히면 오른쪽 도구 막대의 클릭을 가로챈다.

## 검증

**계산된 스타일이 아니라 실제로 눌리는 영역을 쟀다.** `min-height`만 읽으면 이번
같은 덮어쓰기를 놓치고, 박스 크기만 재면 `::after`로 넓힌 영역을 놓친다. 중심에서
`elementFromPoint`로 바깥으로 넓혀 가며 판정이 유지되는 범위를 센다.

```
npm run lint          통과
npm run typecheck     통과
npm test              165 pass / 0 fail
npm run build:vercel  성공
npx playwright test   86 passed / 0 failed
```

새 테스트를 **먼저 `origin/main`에 돌려 실패를 확인**했고, 위 표의 네 줄을 그대로
이름과 함께 짚어 냈다.

| 테스트 | origin/main | 이 브랜치 |
| --- | --- | --- |
| `e2e/touch-target-contract.spec.ts` | 4건 위반으로 실패 | 4 pass |

**눈으로 확인** — 1440px·960px·390px에서 헤더·서비스 상태 줄·지도 배지를 찍어
비교했다. 시각 변화는 계정 버튼 2px뿐이고, 지도 배지는 그대로다. 세 폭 모두 문서
가로 넘침 없음.

## 결과와 제한

측정하다 잘못된 결론을 한 번 냈다. 처음에 `Kakao 재연결`의 클릭 높이를 1px로 재고
"버튼이 덮여 눌리지 않는다"고 판단했는데, 그 버튼이 화면 밖(y=2845)에 있어
`elementFromPoint`가 null을 돌려준 것이었다. 스크롤해서 다시 재니 40px이었다.
회귀 테스트에는 `scrollIntoViewIfNeeded`를 넣었고, 중심조차 눌리지 않는 경우는
"덮여 있다"고 따로 구분해 보고하도록 했다.

**범위 밖으로 남긴 것**

- 본문 속 인라인 링크(푸터·설명문)는 44px 미만이지만 WCAG의 인라인 예외에
  해당해 손대지 않았다.
- Leaflet이 직접 그리는 확대·축소 버튼(30×30)은 외부 라이브러리 마크업이라
  별도 판단이 필요하다.
- `experience-accessibility.css`의 44px 목록 전체를 이 파일로 옮기지는 않았다.
  지금 실제로 덮이고 있는 세 대상만 다뤘다. 나머지는 측정 결과 44px을 지키고 있다.
