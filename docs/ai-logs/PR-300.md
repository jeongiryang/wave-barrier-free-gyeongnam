## 목적

구현 Agent와 독립된 read-only AI QA Reviewer를 모든 trusted same-repo PR에 적용해 Codex 구현 PR과 팀원 PR을 동일한 제품·보안·접근성·데이터 진실성 기준으로 재검토한다.

## 권한 구조

- 정이량: Repository Owner / Product Owner / PM / Release Authority
- 팀원: Contributor
- 구현 Agent/Codex: 코드 생성
- Independent QA: 코드 수정·GitHub approval 없이 review evidence만 생성
- deterministic CI: 실제 test/build/audit 판정
- PM Assistant: QA/CI 결과를 GitHub/Notion 상태로 정리

## 주요 보안 결정

- public repo에서 fork/untrusted PR은 OPENAI_API_KEY를 사용하는 QA에서 제외
- trusted same-repo + OWNER/MEMBER/COLLABORATOR + non-draft만 실행
- PR branch의 정책 파일이 아니라 base commit의 `AGENTS.md`, `.wave/*`, `CLAUDE.md` snapshot을 authority로 사용
- PR title/body/diff/code는 untrusted review material로 명시
- Reviewer는 `sandbox: read-only`, `drop-sudo`
- secret-bearing review job에서 repository install/build/test script 실행 금지
- QA 결과 publish는 별도 GitHub write job
- AI QA는 GitHub APPROVE를 제출하지 않음

## 출력/환류

- `VERDICT: PASS|FAIL|NEEDS_HUMAN`
- `SEVERITY: P0|P1|P2|P3|NONE`
- Findings/Evidence/Required actions/Limitations
- HEAD SHA marker로 동일 HEAD comment 중복 최소화
- machine labels `qa:ai-pass`, `qa:ai-fail`, `qa:ai-needs-human`
- PM Workspace Agent가 설정돼 있으면 QA 결과를 직접 trigger해 GitHub/Notion 후속 상태를 재평가

## 검증

- 기존 Repository CI에서 workflow/YAML 및 저장소 회귀 검증
- 실제 QA runtime smoke는 merge 및 `OPENAI_API_KEY` 설정 뒤 trusted test PR에서 수행
- PASS는 merge approval 또는 Release GO가 아님을 PR comment와 prompt에 고정
