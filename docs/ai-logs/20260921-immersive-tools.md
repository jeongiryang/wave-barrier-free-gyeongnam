# 소개 화면과 나루 여행 도구 통합

- 작성자: jeongiryang / Codex
- 상태: 로컬 검증 완료 · CI 및 배포 대기

## 목적

승인된 Design B의 지역 카드·여행 설계·일정 지도·발견 섹션 흐름을 맞추고, 걷기·휴식·여행 당일·일정 점검을 같은 여행 상태를 유지하는 나루 내부 도구로 이동한다. 노트북/QHD/UHD 콘텐츠 폭, 장식 손글씨, 낮은 강도의 배경 빛을 적용한다. 마지막 소개 섹션은 문구만 남긴다. 인트로 애니메이션은 수정하지 않는다.

## 기능 보존

- 단일 PlannerToolProvider의 방문한 도구 호스트만 지연 마운트하고, 대화상자가 닫혀도 입력과 실행 취소 상태를 보존한다.
- 장소가 없으면 지역·여행지 찾기로, 장소는 있지만 날짜가 없으면 날짜 설정으로 연결한다. 기존 해시 링크와 화장실 찾기 이벤트는 나루 내부로 연결한다.
- 장소 상세를 열 때 나루를 잠시 닫고 동일 도구로 복귀한다. 지도 전환은 기존 지도와 같은 상태를 사용한다.
- 카카오 T 실행만 일시 비활성화한다. 로그인·공유·나에게 보내기 동작은 유지한다.
- 공식 관광지 사진·축제 날짜·미확인 정보는 임의 생성하지 않는다. 축제 미리보기는 기존 공공정보 API로 조회하며 실패 시 조회 링크를 제공한다.
- Nanum Pen Script와 Caveat는 공식 Google Fonts 저장소의 SIL OFL 서체를 필요한 장식 문자열로 축소하여 자체 호스팅한다. 인접 라이선스를 보존한다.

## 검증

- 타입 검사 통과
- 단위 검사 1,599개 통과 (소개 카드 수와 섹션 순서 등 변경된 UI 계약 갱신)
- ESLint 오류 없음; 기존 및 이미지 관련 경고 유지
- 독립 브라우저 QA: 랜딩 132개, 1366/2560/3840 및 960/390 레이아웃, 날짜 미설정·탭/닫기 후 입력 보존·장소 상세 복귀·화장실 첫 마운트·지도 구간 연결 통과
- 지도 68개 데스크톱 및 19개 모바일 대상 검사를 완료하고 발견된 구식 진입점과 HMR 간섭을 구분해 해당 실패를 재검했다. 좌표·요청 횟수·늦은 응답·개인정보 경계는 유지했다.
- 중첩 편집 Escape, 접근성 탭 관계, 밝은 설정에서 나루 내 텍스트 대비, 이전 hash/back/forward 동작의 실제 회귀를 수정했다. 최종 결함 재검 10/10, 모바일 핵심 8/8 통과.
- 기존 2D 지도와 손글씨 서체를 눈으로 확인했다. 인트로 관련 파일은 변경하지 않았다.
- Vercel 빌드 및 성능 예산 통과: CSS gzip 84.83 KiB, 랜딩 초기 JS gzip 141.98 KiB, Planner 253.33 KiB. 최신 main의 #664 축제 팝업을 합친 뒤, 렌더링 소스에 없는 이전 community-controls, condition-first-details, theme-grid, place-card, naru-proposal 등의 선택자와 closing CTA 스타일을 제거했다. 동적 클래스와 인트로는 유지했으며 예산은 올리지 않았다.
- 전체 CI·배포 및 Production 검증은 대기 중이다. 브라우저 검사는 합성 제공처 응답을 사용했으며 실제 로컬 모델 연동의 새 검증 결과가 아니다.

## 전체 CI 후속 수정

- 전체 16개 브라우저 shard의 실패를 수집한 뒤 묶어서 수정했다. 나루로 이동한 도구와 배경 화면의 직접 편집 사이에서 실제 닫기·재진입을 사용하도록 기존 검사를 이관했다. 증거·요청 횟수·늦은 응답·실행 취소 검증은 유지했다.
- 실제 발견한 회귀: 대안 적용 후 native dialog 닫힘보다 이른 초점 이동, 도구/저장 탭 래퍼의 높이 제약 누락, 접힌 소개 영역으로 향하는 도움말. 각각 닫힘 후 일정 초점, 독립 도구 스크롤, 닫힌 disclosure 가시성 검사로 수정했다.
- 최종 재검: 선택·취소·브라우저 뒤로가기 12개, 경로 근거 8개, 나루/포인터/출발 언어 44개, 필터 재조회 10개, 랜딩 대비·스크롤·핵심 흐름 14개, 도움말·날씨 28개, 출발 준비 6개 통과. 소스 변경 중 HMR로 실패한 검사는 소스 고정 후 다시 확인했다.
- 타입/ESLint 오류 없음, 단위 1,599개 및 Vercel 빌드/기존 성능 예산 재통과. 실제 운영 배포와 모델 확인은 아직 완료로 기록하지 않는다.
