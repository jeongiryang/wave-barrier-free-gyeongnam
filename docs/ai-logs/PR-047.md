# PR #47 AI 작업 로그

## 발견

- 여행지·출발지를 빠르게 바꾸면 이전 경로 요청이 나중에 도착해 최신 선택 결과를 덮어쓸 수 있었다.
- 지역·테마·언어·날짜에 따른 확장 데이터와 장소 검색도 이전 요청을 취소하지 않아 느린 응답이 최신 화면 상태와 섞일 가능성이 있었다.
- 새 여행 계획을 생성할 때 이미 진행 중인 이전 여행지 경로 요청이 계속 남았다.

## 변경

- 경로·혼잡도, 확장 데이터, 장소 검색마다 전용 `AbortController`를 두고 새 요청 전에 이전 요청을 취소한다.
- 응답 적용 전 현재 요청과 일치하는지 다시 확인해 취소 시점과 응답 시점이 겹쳐도 오래된 데이터가 반영되지 않게 한다.
- 취소된 요청이 로딩·오류·빈 상태를 덮어쓰지 않도록 최신 요청만 상태를 정리한다.
- 새 계획 생성과 컴포넌트 해제 시 남아 있는 관련 요청을 모두 중단한다.

## 검증

- 경로·확장·장소 검색의 취소 및 최신 요청 가드 회귀 테스트
- lint, typecheck, test, Vercel production build
