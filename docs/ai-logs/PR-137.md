# PR 136 — 여행 공유와 접근성 제보 상태 분리

## 목적

- 서로 다른 저장 정책과 API를 사용하는 여행 공유와 현장 정보 제보를 독립 기능으로 분리한다.

## 변경

- `useTripSharing`: 일정·선택 조건의 공유 저장, 링크 상태와 클립보드 복사를 담당한다.
- `useAccessibilityFeedback`: 선택 장소의 접근성 정보 제보 입력과 전송 상태를 담당한다.
- `usePlannerParticipation`은 두 기능을 조합하는 파사드가 됐다.
- 저장·공유 정책 테스트가 분리된 훅을 함께 검증한다.

- `npm run lint`

## 안전성

- 공유 데이터에는 출발지 좌표가 아니라 라벨만 포함하며 기존 30일 공유 계약을 유지했다.
- 접근성 제보는 선택된 장소와 5자 이상의 사용자 입력만 전송한다.
