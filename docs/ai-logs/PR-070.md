## 목적

PlannerPage가 출발지와 개인정보 경계, 경로 요청 취소, 혼잡 조회, 교통 제공기관,
경로 정렬 상태까지 직접 소유하고 있었다. 경로 domain의 상태와 부수효과를 하나의
controller hook으로 이동해 화면 orchestration과 분리한다.

## 역할 구분

- 사람: 남은 대형 책임 경계를 모두 점진 분리하고 검증·병합·배포까지 완료하도록 위임
- AI: Planner 상태 감사, route controller 설계·이동, 회귀 테스트와 PR 처리

## 구현

- `useRoutePlanning`이 출발지, 목적지, 경로·혼잡 요청, 제공기관·운행 문맥과 요청 취소를 소유한다.
- 기존 `useRouteView`를 controller 내부에 합성해 경로 상태의 feature 경계를 완성했다.
- 현재 위치 좌표가 서버 요청으로 넘어가지 않는 기존 정책을 hook 안에서 유지했다.
- 출발 거점을 바꾼 직후 이전 출발지명이 안내문에 남던 stale label을 명시적 인자로 제거했다.
- PlannerPage는 경로 API와 AbortController를 직접 다루지 않는다.
