# PR #60 · 계정·여행자 커뮤니티와 제품 소개 경험 완성

## 발견

프로덕션은 여행 설계 기능이 풍부했지만 첫 화면이 핵심 가치를 충분히 설명하지 못했고,
과거 Safe Browsing 오탐 대응으로 공개 계정 진입점이 제거되어 기존 Neon Auth를 사용할
수 없었다. 관광지의 공식 접근성 근거와 실제 여행자 경험을 이어 주는 제품 흐름도 없었다.
플래너 페이지는 요청·타입·상수·경로 계산·상세 UI를 함께 소유해 변경 영향이 컸다.

## 구현

- W.A.V.E 전용 `/login`, `/register`와 헤더 계정 메뉴를 기존 Neon Auth로 복원했다.
- 공개 열람, 로그인 기반 글·댓글·좋아요·본인 수정/삭제를 제공하는 여행자 커뮤니티를 추가했다.
- Neon Postgres migration, 서버 세션 권한 검증, same-origin·본문 크기·입력 길이 방어를 적용했다.
- 관광지 상세에서 공식 근거와 사용자 경험을 구분해 관련 커뮤니티로 연결했다.
- 랜딩을 조건 → 추천 근거 → 일정 → 이동 → 상황 대응 → 커뮤니티의 제품 스토리로 확장했다.
- 첫 방문 인트로를 단축하고 모션 감소 설정을 유지했다.
- 경로 순서 최적화와 설명을 독립 모듈·테스트로 분리하고, 플래너 요청 계층·타입·상수·유틸·장소 판단 UI를 기능 경계로 옮겼다.
- PR 작성자 담당자, 작성자 외 협업자 리뷰어, 기존 라벨 지정 규칙을 저장소 정책과 템플릿에 반영했다.
