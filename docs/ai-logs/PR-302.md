## 목적

CD 성공 직후 실제 W.A.V.E Production에서 읽기 전용 API·브라우저 smoke를 실행해 배포 완료와 실제 사용자-facing 정상 상태 사이의 간극을 자동 검증한다.

## 안전 설계

기존 전체 E2E는 계정·커뮤니티 write flow를 포함할 수 있으므로 Production에 그대로 실행하지 않는다.

별도:
- `playwright.production.config.ts`
- `e2e-production/smoke.spec.ts`

를 사용해 읽기 전용 공개 화면만 검사한다.

Production QA에서 회원가입/로그인/비밀번호/계정 변경, 후기/댓글/좋아요/신고/제보, migration, 기타 사용자 데이터 write를 수행하지 않는다.

## 검증 범위

- `/api/health` 200 + checkedAt
- 기존 `npm run check:production`
- desktop/mobile 실제 Production 랜딩
- visible planner link와 실제 planner 진입
- `/planner`, `/travel-book`, `/community` 공개 렌더링
- HTTP/runtime error 문구
- page-level horizontal overflow
- uncaught pageerror
- serious/critical axe violation
- reduced-motion 진입

## 권한 분리

- Production verify job: PM Workspace Agent access token 없음
- PASS notify job: 앱/테스트를 실행하지 않고 PM Workspace Agent에 결과만 handoff
- FAIL: Automation Failure Router가 GitHub Issue로 환류
- 정이량: 최종 PM / Release Authority. Production QA PASS만으로 GO 선언 금지

## 검증

이 PR 자체는 Repository CI에서 typecheck/lint/unit/E2E/build/performance 회귀를 통과해야 한다. 실제 Production runtime smoke는 merge 후 성공한 CD에서 실행한다.
