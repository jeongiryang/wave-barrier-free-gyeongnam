## 목적

팀원이 GitHub Issue를 제출하면 사람의 프롬프트 중계 없이 자동으로 PM triage queue에 들어가고, lifecycle status 변경에 따라 Engineering/QA/Human queue로 라우팅되는 Agent 상태 머신의 입구를 만든다.

## 역할 구분

- 사람(PM, `jeongiryang`): 제품 정책, priority override, human gate, Release GO
- 팀원: Contributor로 Issue/PR/Review 제출
- PM Agent: `status:triage`에서 재현/중복/정책/공모전 영향과 Acceptance Criteria를 확인
- Engineering Agent: `status:ready-for-dev` 이후 구현
- QA Agent: review/QA 상태에서 독립 검증
- AI 작업: lifecycle/agent/priority label 계약과 GitHub Actions router 구현

## 검증

- 최신 main `34e6021265b16d046dca24feaa3ec2101fc977e2`에서 분기
- 기존 `issue-triage.yml`은 수정하지 않고 신규 `automation-issue-router.yml`만 추가
- 새/reopened Issue는 `status:triage + agent:pm`으로 초기화
- 제목 `[P0]`~`[P3]`를 priority label로 반영하고 명시가 없으면 `priority:untriaged`
- 이미 priority label이 있으면 덮어쓰지 않음
- status label 이벤트에서 status별 agent queue 동기화
- `status:*`와 `agent:*`는 각각 하나의 active label을 유지
- `status:blocked-human`에서 `human-gate`를 추가하고 다른 상태로 전환하면 제거
- router가 추가한 agent label은 status 이벤트가 아니므로 자기 증식 loop 없음
- 필요한 custom label은 없을 때만 생성
- 저장소 CI 결과를 PR에서 확인
