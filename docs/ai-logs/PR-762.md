# 핵심 여정 검사 분리 — 2026-09-29

## 사용자 지시와 변경 범위

Owner가 승인한 로컬 화면을 최우선으로 통합하고, 제출 기능설명서의 기능을 보존한 채 검증·병합·배포한다. 이 후속 변경은 검사 코드와 빠른 검사 목록에 한정하며 앱 화면·기능·CSS를 수정하지 않는다.

## 발견한 문제

#761의 후보 `742f9f7`은 CI와 전체 Release Audit(브라우저 2,542개 통과, 기존 중복 뷰포트 제외 2개)을 통과했다. 동일한 파일 트리의 squash main `e1bead1`에서는 긴 여행 설계 검사 하나가 45초를 넘긴 뒤 재시도 통과하여 불안정 실패가 됐다. CI가 실패했으므로 CD는 실행되지 않았다.

실패 trace에서 검색·상세 초점·담기·시간 설정·수동 경로 선택·장소 삭제/재담기·새로고침 복원이 모두 완료됐다. 실제 조작 누적 후 최종 복원 확인이 최초 이동 기준 43.15초에 끝났고, axe의 부분 분석 완료 뒤 결과 집계용 페이지 초기화 중 전체 시간 제한에 걸렸다. 단일 버튼 고장이나 무한 대기로 판정하지 않았다.

## Codex의 수정과 독립 검토

- 검색부터 저장·설정 변경·삭제/재담기·새로고침 복원·전체 페이지 접근성 검사까지의 연속 여정을 유지한다.
- 수동 경로 선택 뒤 늦은 자동 응답이 도착하는 경쟁 검사는 별도 새 브라우저 컨텍스트에서 실제 UI로 일정을 만들어 수행한다. 저장소 주입으로 준비 과정을 우회하지 않는다.
- 분리한 여정을 `harness/quick-tests.json`에도 추가해 빠른 CI의 기능 범위를 유지한다. 기기당 빠른 여정 수는 27→28이다.
- 45초 제한, 재시도 횟수, fail-on-flaky, skip, 접근성 판정 기준을 변경하지 않는다.
- 구현 담당과 별도 검토자가 기존 검사 항목의 보존을 대조한다. 최종 실행 결과와 정확한 후보·main의 CI/CD 링크는 후속 PR 본문에 기록한다.

환경변수·DB·Production 앱 코드의 변경은 없다. 배포는 새 main의 필수 CI가 모두 성공한 뒤 기존 GitHub Actions CD 경로로만 진행한다.
