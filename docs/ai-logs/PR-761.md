# PR #761 — 로컬 승인 UI 우선 통합과 제출 기능 보존

## 사람의 결정

Owner는 2026-09-29 현재 로컬 UI를 최우선으로 반영하고, #745·#755·#758·#760은 그 이후에 통합하되 겹치는 부분은 로컬을 우선하라고 지시했다. 제출 기능설명서의 기능 보존, CSS gzip 한도 상향, 기존 원안 왜곡의 재발 방지도 명시했다. 이 범위의 구현·검증·병합·배포 진행을 승인했다.

## Codex의 변경

- 승인 로컬을 `0388daa`와 `backup/owner-local-20260929`로 보존한 뒤 통합했다.
- PR별 채택·충돌·대체 범위와 원인 분석은 [통합 기록](../integration-local-first-20260929.md)에 정리했다. #755를 원문 그대로 병합한 것으로 표시하지 않는다.
- 나루 안에서 조건·장소·일정을 편집해도 같은 상태와 초안이 유지되도록 연결했다. 최신 시설 조회와 담기 판단을 일치시키고, 세 장 이미지의 붙여넣기·확대·삭제·실패 후 복구를 보존했다.
- 재현된 키보드 viewport, 글자 확대, 지도 도구 전환, 날짜 입력 초점, 중첩 화면 글자 대비 오류만 승인 디자인 위에서 수정했다.
- 이전 문구·탭·장식 버튼을 강제하던 검사는 현재 사용자 승인 경로로 갱신했다. 기능·상태·실패 복구 검증을 삭제하거나 skip하지 않는다. 제출본 6쪽의 ‘격자 또는 목록’을 둘 다 필수라고 확대 해석하지 않는다.
- CSS gzip 한도는 109→200 KiB. 다른 성능·보안·접근성 기준은 유지한다.
- 전체 감사에서 재현한 검색 완료 초점·단계 이동 스크롤·사진 로딩 중 클릭 유실·짧은 나루 본문 공간을 최소 수정했다. 애니메이션/resize의 실제 완료 전에 검사하던 사례는 기존 렌더 대기를 사용하며 사용자 승인 모션과 같은 접근성 기준을 유지한다.

## 검증 구분

Codex 구현 검증과 별도 에이전트의 상태·상세·나루·접근성 QA를 구분했다. 로컬 합성 API 검사, 실제 제공처 검사, GitHub CI, Release Audit, 배포 검증은 서로 대체하지 않는다. 최종 결과와 정확한 커밋·실행 링크는 통합 기록과 PR 본문에 갱신한다. 현재 이 로그 작성 시점에는 검증 중이며 병합·배포 완료를 뜻하지 않는다.

실제 휴대전화·화면낭독기는 사용자의 현재 환경에서 확인할 수 없으며, 브라우저 모바일 viewport·touch·키보드·접근성 자동 검사와 동일시하지 않는다.
