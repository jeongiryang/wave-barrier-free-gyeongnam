# PR-195 — 움직임 줄이기 토글이 어두운 화면에서 읽히지 않던 문제

## 목적

모든 화면에 있는 환경설정의 "동작 효과" 토글이 켠 상태에서 대비 1.02로
사실상 보이지 않던 문제를 고친다. 움직임 줄이기 설정 자체가 접근성 기능이다.

## 원인

```css
.preference-row.motion-toggle[aria-pressed="true"] { background: #e9f8fb; }
```

`html[data-theme="dark"] .preference-row { background: #0d3546 }`가 이미 있지만
상태 선택자 쪽 구체성이 (0,3,0)으로 더 높아 밝은 배경이 이긴다. 그 위에
`--ink`(어두운 화면에서 밝은 색) 글자가 얹혀 1.02가 된다.

랜딩의 "지금 선택한 지역" 칩도 같은 이유로 1.23이었다.

## 왜 지금까지 못 잡았나

axe-core는 배경을 확정하지 못하면 위반이 아니라 `incomplete`로 넘긴다.
반투명 배경이 겹친 자리가 많아 그 보류가 크고, axe 기준으로는 이 자리가
0곳으로 보였다.

## 변경

- `app/styles/preferences.css`, `app/styles/landing-explorer.css` — 두 곳의
  표면과 글자색을 어두운 화면에 맞췄다.
- `e2e/contrast.ts` — 조상 배경을 알파 합성해 실제 색으로 대비를 재는 도구.
- `e2e/site-chrome-contrast.spec.ts` — 랜딩·커뮤니티·글쓰기·사진코스에서 두
  테마 모두 4.5 미만이 없는지, 동작 효과 토글이 켠 상태에서 읽히는지.

## 앞선 실수와 정정

처음 만든 측정 도구는 반투명 배경을 불투명 흰색으로 취급해, 어두운 배경 위
밝은 글자를 위반으로 잘못 셌다. 그 수치로 CSS를 고치던 중 발견해 해당 변경
62줄은 커밋하지 않고 폐기했다.

이번 도구는 검사 자체를 먼저 검증한다. 표본 셋을 심고 확인했다.

| 표본 | 기대 | 결과 |
| --- | --- | --- |
| `#8a9aa2 on #7f8f96` (1.15) | 잡음 | 잡음 |
| `#0a2233 on #ffffff` (16.8) | 안 잡음 | 안 잡음 |
| `#e8f5fb` on `rgba(255,255,255,.05)` over `#062736` | 안 잡음 | 안 잡음 |

배경 이미지가 끼면 색만으로 판단할 수 없어 건너뛴다. 못 잡는 자리가 있음을
전제한 검사다.

어두운 73곳이다(axe 기준으로는 양쪽 0곳). 섞으면 나머지 화면의 회귀를 잡지
못하므로 이 PR의 검사 대상에서 제외하고 별도 작업 단위로 남긴다.
