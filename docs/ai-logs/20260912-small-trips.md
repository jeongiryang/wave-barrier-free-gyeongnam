# 작은 코스와 짧은 나들이

- 작성자: jeongiryang
- AI 도구: Codex, Node/Playwright
- 범위: Owner가 승인한 기능 후보19·20. 전체 조작 감사·회귀 분석/리팩토링·제출 전 검토는 후속으로 유지.

## 결과

일정 편집의 ‘한 장소에서 코스 이어 담기’에서 저장한 장소를 기준으로 식사·휴식·관광 후보를 비교하고 한 곳만 이어 담는다. 같은 편의조건, 실제 공개 관광지, 거리, 미확인 선택, 기존 날짜와 고정 순서를 지킨다. 미리보기와 변경되지 않은 추가 건의 되돌리기를 제공한다. 휴식 장소가 실제 좌석·운영을 보장한다는 주장은 하지 않는다.

‘짧은 나들이’는 여행 조건 첫 화면에서 별도로 진입한다. 편의조건을 URL 밖의 한 시간짜리 세션 초안으로 전달하며 실제 활성 일정에는 쓰지 않는다. 조건→세 곳씩 후보 비교→한두 곳 일정 확인의 세 화면으로 나눴다. 공개 출발·복귀 장소, 날짜·시각,1–6시간과 체류15–120분을 고른다. 이동과 복귀를 포함한 거리 기반 추정이 시간 안에 들어오는 선택만 저장 단계로 이어진다. 장소의 공식 이용시간은 기존 명시적 조회로 확인한다.

별도 outing 지문으로 기존 여행 아카이브와 구분해 저장하고, 이미 저장한20개를 자동 삭제하지 않는다. 저장 차단·손상 데이터는 성공으로 표시하지 않는다. 출발·복귀 기준과 예상 시각은 여행 메모로 보존하며, 전체 설계로 다시 열 때 출발 거점을 다시 선택하도록 안내한다. 날짜/체류/귀가 제한은 기존 여행 스키마에 보존한다. 계정 저장은 기존 명시적 로그인 동작을 재사용한다.

## 데이터와 검사

새 유료 제공처·자동 후보 검색·전 후보 경로 조회·개인 GPS 전송 없음. 기존 plan/visit-info의 제한과 캐시, 오류·취소 경계를 사용한다. 같은 조건에서도 후보 목록은 공공 API의 제한된 검색 결과이며 전 지역의 완전한 목록이라고 주장하지 않는다.

순수 모델4건으로 편의 부정/미확인/거리/유효 ID/자정/시간 초과/반환 이동과 별도 아카이브 보존을 확인했다. 첫 focused E2E에서 SSR 준비 전에 입력이 지워지는 신규 결함을 inert 경계로 수정했고, innerText와 textContent를 혼용한 테스트를 실제 가시 텍스트 비교로 고쳤다. 최종 필수 검사·독립 QA·exact-head CI 및 실제 Production은 진행 중이며, 완료 전 구현/배포 성공을 단정하지 않는다.

독립 QA에서 remote Image shim이 style을 전달하지 않아 후보 사진이400px로 늘어나는 문제를 확인했다. 원래 unoptimized였던 이 이미지 한 곳만 native img로 전환해 실제180px 높이·crop·둥근 모서리를 적용했다. 전역 스타일과 다른 사진은 변경하지 않았다. 수정 후 type/lint/build/performance와 focused E2E8건 PASS. 전체 단위871건 PASS 결과도 보존한다.

추가 독립 QA의 부분 응답 안내 누락도 수정했다. 조건 화면뿐 아니라 후보와 일정 확인 화면에 제공처의 일부 정보 누락 안내를 유지한다. 새 후보 E2E는 실제 이미지180px/16px과 두 단계에서 부분 안내가 보이는지도 확인한다.

Hosted CI에서 새 코스 도구가 추가되면서 기존 대안 도구 테스트의 `#itinerary > .place-evidence` 선택자가 두 개를 가리키는 것을 확인했다. 네 개 시나리오의 공통 진입 선택자만 실제 ‘장소·날짜 대안 비교’ summary로 한정했다. 제품 동작·기존 assertion·coverage·timeout은 바꾸지 않았다.
