# PR-145 — 로그인 복귀 경로 오픈 리다이렉트 차단

## 목적

`/login?next=`, `/register?next=` 값이 외부 도메인으로 해석되는 경로를 막는다.
이 저장소는 과거 헤더 모달형 로그인 폼이 Google Safe Browsing에서 피싱으로
오탐된 이력이 있어(#12), 로그인 화면이 외부 사이트로 사용자를 넘기는 통로는
가장 먼저 닫아야 한다.

## 문제

`safeAuthReturnPath`는 문자열 앞부분만 검사했다.

```js
value.startsWith("/") && !value.startsWith("//") ? value : "/community"
```

`//`는 막지만 `/\`는 통과한다. WHATWG URL 파서가 백슬래시를 슬래시로
정규화하므로 브라우저는 이 값을 다른 출처로 해석한다.

```
"/\evil.example"  ->  통과  ->  https://evil.example/
```

이 값은 `useAuthForm`의 로그인 성공 후 `router.push(next)`와, 이미 로그인한
사용자에게 보여 주는 `<a href={auth.next}>계속하기</a>`로 그대로 들어갔다.

## 변경

- `lib/auth/return-path.js`를 새로 만들고 문자열 접두사 검사 대신 **실제로
  해석해 출처를 비교**한다. 같은 출처일 때만 `pathname + search + hash`를 반환하고
  아니면 `/community`로 떨어진다.
- `features/auth/validation.ts`는 이 모듈을 재수출한다. 호출부(`useAuthForm`,
  `AuthForm`)는 변경하지 않았다.
- 저장소 규칙 중 자동 검증 대상 항목을 `docs/main-sync-review-policy.md`로 옮기고,
  개별 도구용 작업 지침 파일 `CLAUDE.md`는 `.gitignore`에 넣어 저장소에서 제외했다.

## 설계 판단

- 검증 로직을 `.js`로 둔 것은 이 저장소의 기존 방식이다. `lib/accessibility-score.js`,
  `lib/community/validation.js`, `features/planner/optimization/visit-order.js`처럼
  순수 함수를 `.js`로 두면 번들러 없이 `node --test`가 직접 실행할 수 있다.
  기존 소스 문자열 단언만으로는 이번 우회를 잡을 수 없었다.
- 허용 목록 방식(`/planner`, `/community`만 허용)도 검토했지만, 앞으로 늘어날
  내부 경로마다 목록을 고쳐야 해서 출처 비교를 선택했다.
- `CLAUDE.md`를 제외하면 이를 읽던 정책 테스트 3개가 깨진다. 규칙을 지우는 대신
  저장소에 남아야 할 항목을 문서로 옮기고 테스트를 그 문서로 돌렸다.

## 영향과 제한

- API 응답, DB 스키마, 인증 방식, 환경 변수, migration 변경 없음.
- 정상 복귀 경로(`/planner`, `/community?category=review`)의 동작은 그대로다.
- 이 변경은 앱 내부의 복귀 경로만 다룬다. Neon Auth가 자체적으로 처리하는
  리디렉션은 이 함수를 거치지 않는다.
