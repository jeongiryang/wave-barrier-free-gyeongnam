## 목적

질문형 플래너에서 완성한 여행이 공유 링크·사진 코스·커뮤니티 사이에서 끊기는
문제를 해결한다. 계정이나 서버 저장을 요구하지 않는 로컬 여행집을 만들어 여행 전
준비와 여행 후 기록을 하나의 흐름으로 잇는다.

## 역할 구분

- 사람: 역대 공모전 수상작의 기능·소개 방식과 UI/UX를 W.A.V.E에 맞으면 기존
  화면을 고수하지 않고 적극 적용하도록 승인했다.
- AI: Issue #227 데이터 경계 설계, 로컬 저장 모델·플래너 보관·여행집 UI·진입점,
  문서·테스트 구현과 CI·Production 검증을 수행한다.

## 구현

- 플래너 일정을 `여행집에 보관`해 최대 20개 로컬 카드로 관리한다.
- 같은 날짜·장소 조합은 중복 생성하지 않고 순서·일정만 최신화한다.
- `갈 여행 / 다녀온 여행`, 1,200자 메모, 날짜별 동선을 제공한다.
- 저장한 장소 ID·날짜·시각을 기존 플래너 로컬 키로 복원한다.
- 사진 코스 복원과 여러 장소 여행 후기 초안으로 연결한다.
- 랜딩을 `어떤 여행 → 왜 맞는 장소 → 어떻게 이동 → 무엇을 남길까`의 질문 흐름으로
  확장하고 주요 헤더에 여행집 진입점을 추가한다.

## 개인정보·접근성

- 서버 API·DB·migration·인증 변경 없음
- 공식 관광사진 HTTPS URL만 표지로 허용
- 사용자 원본 사진·EXIF GPS·장소 좌표·정확한 출발지·계정 정보 비저장
- 여행당 12개 장소, 전체 20개 여행, 메모 1,200자 제한
- 손상된 로컬 값·날짜·배정을 정규화하고 범위 밖 값은 기본 날짜로 복구
- 44px 조작 영역, 두 단계 삭제, 키보드·동작 감소·다크 테마·모바일 UI 적용

로컬 환경에는 Playwright Chromium 실행 파일이 없어 브라우저 테스트가 시작되지
않았다. 새 데스크톱·모바일 시나리오를 추가했으며 GitHub CI의 설치된 Chromium 결과를
병합 조건으로 사용한다.

CI #588에서는 제품 화면의 `내 기기 안에만 보관해요.`와 테스트의 기대 문구
`이 기기에만 보관해요.`가 달라 데스크톱·모바일 각 1건이 실패했다. 여행집의 보관,
새로고침, 카드 렌더링과 나머지 149건은 통과했으며, 테스트를 실제 개인정보 안내
문구에 맞춘 뒤 전체 CI를 다시 실행한다.
