# PR-097 — 커뮤니티 HTTP action 경계 분리

## 목적

catch-all API route가 게시글·댓글·좋아요의 인증, 입력 검증, 소유권 확인과 DB
호출을 모두 직접 처리하던 구조를 action 계층으로 분리한다.

## 변경

- 공통 no-store 응답, 인증 상태와 소유권 오류를 `http` 모듈로 이동
- 게시글 목록·상세·CRUD 요청 처리를 `post-actions`로 이동
- 댓글 작성·수정·삭제 요청 처리를 `comment-actions`로 이동
- 좋아요 요청 처리를 `engagement-actions`로 이동
- catch-all route는 URL·method dispatch와 최종 오류 경계에 집중
- API route와 action 계층의 보안 정책 회귀 테스트 보강

## 안전성

session 기반 identity, same-origin/Fetch Metadata/body-size 검증, 서버 소유권 확인,
rate limit, status code와 no-store 응답을 유지한다.

## 검증

- `npm run lint`
- `npm run typecheck`
- `npm test` (66/66)
- `npm run build:vercel`
- `npm audit --omit=dev --audit-level=high`
- `git diff --check`

## 영향

API URL, method, 응답 형식, DB schema와 사용자 커뮤니티 흐름은 변하지 않는다.
