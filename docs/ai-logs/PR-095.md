# PR-095 — 커뮤니티 데이터 저장소 경계 분리

## 목적

스키마 준비, 게시글·댓글·좋아요 CRUD와 소유권 검증이 한 저장소 파일에 섞여
있던 커뮤니티 서버 계층을 엔터티별로 분리한다.

## 변경

- Neon 연결과 idempotent schema 준비를 `database`로 이동
- 게시글 목록·상세·CRUD를 `posts-repository`로 이동
- 댓글 CRUD와 rate limit을 `comments-repository`로 이동
- 좋아요의 중복 방지와 집계를 `likes-repository`로 이동
- 서버 소유권 확인을 `ownership`으로 이동
- API 입력 타입을 커뮤니티 서버 타입 모듈로 이동
- 기존 route import 호환을 위해 `repository` facade 유지
- DB·권한 경계 회귀 테스트 보강

## 안전성

session 기반 사용자 ID, 서버 소유권 검증, 작성 rate limit, duplicate like 방지,
외래키 cascade와 runtime DDL 정책을 유지한다.

## 검증

- `npm run lint`
- `npm run typecheck`
- `npm test` (65/65)
- `npm run build:vercel`
- `npm audit --omit=dev --audit-level=high`
- `git diff --check`

## 영향

API 응답, DB schema, migration과 사용자 커뮤니티 동작은 변하지 않는다.
