## 역할 구분

- 정이량: 실제 PM/Product Owner/Release Authority, 최종 Submission GO와 실제 제출

- Judge Agent: Submission Agent와 독립적으로 감점·불일치·시연 실패 가능성 검토
- Compliance Agent: 공식 제출/양식/마감/데이터 활용 requirement 제공

## 진실성 계약

Source hierarchy:
1. Production / Post-Deploy QA
2. latest main / CI / API inventory
3. official compliance source
4. repository docs
5. generated copy

다음은 항상 구분:
- KTO vs 외부 API
- 공식 정보 vs 여행자 제보
- 미확인 vs 없음/가능
- 장소 편의 vs 이동 경로 접근성
- 실제 로그인 필요/불필요 범위
