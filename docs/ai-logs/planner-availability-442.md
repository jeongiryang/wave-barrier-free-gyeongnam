# 편의·활동 선택 단계의 검색 결과 안내

- Issue: #442
- 작성자: jeongiryang / Codex
- 사람: 지역 선택 이후 두 조건 단계에 건수를 표시하도록 요청. 변경 관련 검증과 실제 화면 확인을 유지하고 별도 버그 수정은 후순위로 지정.
- AI: 현재 추천 범위 조사, 건수 API·선택 UI·필요한 회귀 검사 구현.

## 결과

편의와 활동 선택 아래에 현재 검색 결과 수를 표시한다. 최대 12개 후보를 다루는 기존 추천의 조회·중복 제거·편의 근거 기준을 사용하며 지역 전체 총수로 표현하지 않는다. 편의 선택은 받은 근거에서 재계산하므로 추가 API 호출이 없다. 지역/활동 변경은 450ms 후 조회하고 이전 요청은 취소한다. 완전한 성공 결과만 5분간 메모리에서 재사용하며 실패/부분 결과는 재확인을 제공한다. 저장 일정·최종 추천 요청을 바꾸지 않는다.

신규 조회는 KTO 목록과 상세만 사용한다. 사진·날씨·오디오·교통 API를 추가 호출하지 않는다. 최대 4개 활동×2개 목록 서비스×5개 창원 구역(40개 목록 요청)과 12개 상세 요청이 가능하다. 이는 실제 계정 한도와 다르며 #365 전수 조사에서 신규 호출량 영향도 기록한다. HTTP 성공 캐시는 기존 300초/1800초 정책을 사용하고 부분/실패는 no-store다.

## 검증

- 관광 응답·신규 건수 계약 11개 PASS: 중복 제거, 실제 편의 근거, 실패/부분 결과 및 캐시 경계.
- lint: 오류 0, 기존 경고 13. typecheck 및 Vercel 빌드/성능 예산 확인.
- 관련 브라우저 4개: 편의/활동 전환·추가 조회 없는 편의 재계산·오류/부분/정상 0건·재확인, 관련 영역 axe와 가로 넘침.
- 1440/960px 및 모바일 실제 렌더링을 캡처하고 확인.
- 첫 브라우저 실행은 fixture 기본값이 전체 보기여서 단계 이동 버튼을 찾지 못했다(2 PASS/2 FAIL). guided fixture를 명시해 4 PASS. test.use의 reducedMotion 타입은 contextOptions로 수정.
- 최신 Owner 지시에 따라 로컬 전체 제품 회귀를 중복 실행하지 않음. 필수 hosted validate와 배포 확인은 별도 진행.

## 범위

카카오 로그인·지도 범위·저장 문구는 별도 MVP 작업이다. 전체 API의 실호출 성공이나 출시 최종 GO를 선언하지 않는다.
