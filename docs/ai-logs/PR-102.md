# PR-102 — 커뮤니티 클라이언트 controller 분리

## 목적

커뮤니티 목록·상세 화면이 API 수명주기, 인증 이동, mutation 상태와 JSX를 함께
소유하던 구조를 controller hook과 view로 분리한다.

## 변경

- 검색·카테고리·관광지 필터·pagination과 목록 요청을 `useCommunityBoard`로 이동
- 상세 조회, 좋아요, 글 삭제, 댓글 작성·수정·삭제를 `useCommunityDetail`로 이동
- 상세 view를 `features/community/components`로 이동해 domain 경계를 완성
- page와 커뮤니티 UI 회귀 테스트를 새 경계에 맞게 갱신

## 안전성

비로그인 공개 읽기, 보호된 참여 시 로그인 후 복귀, 본인 소유 UI, 요청 timeout,
빈 상태와 오류 복구, 접근 가능한 form·live state를 유지한다. 서버 권한 검증은 기존
community server action 경계에서 계속 강제한다.

## 검증

- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npm run build:vercel`
- `npm audit --omit=dev --audit-level=high`
- `git diff --check`

## 영향

목록·상세 UI를 수정할 때 fetch와 mutation 정책을 건드리지 않아도 되고, 각 사용자
흐름의 상태 수명주기를 독립적으로 테스트할 수 있다.
