## 목적

출시 직전 운영 화면을 다시 점검하면서 실제 여행자 게시물과 함께 공개되던 예시 게시물을 제거한다. 실제 사용자 데이터는 보존하고, 과거 마이그레이션을 수정하지 않으면서 신규 환경과 기존 환경에서 동일한 공개 결과를 만든다.

## 역할 구분

- 사람: 출시 마감 범위 승인, 운영 계정·모바일 기기 확인, 공모 제출 정보 입력과 최종 제출 승인
- AI: 운영 화면 감사, 예시 게시물 식별, 공개 조회 방어선과 비파괴 마이그레이션 구현, 사용자 문구·문서 정리, 회귀·빌드·성능·보안 검증, PR 작성

## 변경

- 목록·검색·장소 연결·상세 조회의 여섯 공개 질의에서 `wave-seed` 작성 글을 제외한다.
- `006_retire_community_seed.sql`에서 기존 예시 행을 삭제하지 않고 `hidden` 상태로 전환한다.
- CD가 001~006 전체 마이그레이션 적용 결과를 검증하도록 배포 게이트를 확장한다.
- 샘플 전용 타입·배지·스타일과 개발용 안내 문구를 제거한다.
- README, 도움말, 약관, 시연 문서를 실제 여행자 게시물 기준으로 맞춘다.

## 결과와 제한

- 실제 사용자 게시물·댓글·좋아요는 변경하거나 삭제하지 않는다.
- 조회 방어선은 마이그레이션 적용 전에도 예시 글의 재노출을 막고, 마이그레이션은 기존 행을 보존해 제한된 롤백이 가능하다.
- 현재 로컬 Node 24와 vinext 개발 서버 조합에서는 기존 React 중복 로딩 오류로 Playwright 서버가 시작되지 않았다. 프로덕션 빌드는 통과했으며 저장소 표준 Node 22 GitHub Actions E2E를 최종 기준으로 삼는다.
- 실제 계정 가입·로그인, 실제 모바일 기기, 비공개 브라우징, 운영 Secret과 공모 제출 정보는 담당자가 운영 환경에서 최종 확인한다.
