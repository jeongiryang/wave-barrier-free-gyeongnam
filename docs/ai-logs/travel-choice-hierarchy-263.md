## 목적과 역할

Owner가 디자인·실제 사용 화면 개선, 검증 후 머지·배포, PR마다 알림을 위임했다. AI는 기존 이슈와 PR 요구, 실제 코드, 렌더링 및 검사를 대조했다. 승인 리뷰 대기는 면제됐지만 실패·대기 중 필수 CI는 우회하지 않는다. 구독 밖 모델 호출, 새 Preview, 설치·lockfile 변경, provider 정책·DB 변경은 없다.

여행지를 고를 때 사진·장소·확인된 편의·일정 추가를 순서대로 읽고, 지도에서는 출발·도착/내 위치/추가 도구/확대부터 선택하도록 한다. 추천 정책, 저장 ID, 오래된 결과의 추가 차단과 근거 부족 장소의 별도 탐색 정책은 유지한다.

## 구현

- 지역을 사진 아래 본문으로 옮기고 제목, 확인된 편의 최대 3개, 미확인·불일치 개수, 주요 추가/제거 동작을 구분했다. 상세에는 모든 원문 항목을 유지한다. 항목별 근거 없는 과거 자료의 요약 문자열을 확인된 편의로 승격하지 않는다.
- 번역된 동작과 한국어 장소명을 `aria-labelledby`와 원문 `lang`으로 연결했다. 저장·제거, 상세 열기/닫기 및 초점 복귀를 유지한다. 화면 밖 카드의 숨은 동작 이름이 문서 폭을 늘리지 않도록 버튼을 위치 기준으로 삼는다.
- 기본 지도 제어 4개, 펼친 상태 총 11개. 지도/스카이뷰·주변·지도 표시·로드뷰·이미지·페이지 링크 7개가 추가 영역에 남는다. 제공처별 사용 가능 여부와 기존 핸들러는 유지한다.
- 추가 영역 Escape와 중첩 패널 Escape를 구분한다. 패널을 닫을 때 원래 버튼이 숨겨졌으면 보이는 지도 도구 버튼으로 돌아온다. CSS 확대 fallback의 중첩 닫기는 테스트하며 실제 브라우저의 native fullscreen 동작을 대신 보장하지 않는다.
- 상태·재연결 제어를 정상/대체/복구 상태 공통 레이아웃으로 배치했다. 좁은 화면의 패널 최대 높이는 실제 도구 하단 위치로 계산해 도구를 가리지 않는다. 제목도 내용과 함께 스크롤한다. 기존 지도 재배치/표식 여백 계산을 유지한다.
- 접근로의 완만함이나 출발 안전을 단정하는 문구를 없앴다. 다국어 항목은 관광정보의 언어 선택으로 설명한다. 신규 편의나 언어 지원 범위를 약속하지 않는다.
- 사용하지 않는 카드 선택자만 제거했다. 성능 예산은 늘리지 않는다.

## 검증과 발견 이력

- 카드: 한국어/영어 × 밝은/어두운 테마 × desktop/mobile, 항목별 근거, 최대 노출 개수, 과거 자료, stale 결과 차단, 저장/제거, 키보드, axe. 최초 새 테스트의 지역 변경은 결과를 지우는 기존 정책과 달랐으므로 활동 변경으로 stale 상태를 재현했다. 코드 정책을 바꾸지 않고 8개 재검증 PASS.
- 지도: 280/390/620/768/900/960/1024/1440px, 별도 기존 패널 검사의 320~2560px, 실제 Leaflet 날짜별 지도, SDK 상태·재연결·주변 검색·로드뷰·저장/공유·언어·초점 회귀.
- 첫 지도 검증에서 768px 버튼 잘림/상태 겹침을 수정했다. 이어 발견된 390px 문서 17px 넘침은 카드의 숨은 동작 이름 배치가 원인이었다. 최종 지도 기본/추가/중첩 초점 12개 PASS.
- 확장 256개 검사 중 245 PASS/11 실패를 기록했다. 영문 복구 버튼 겹침, 모바일 지도 설정 패널의 도구 가림을 수정했다. 기존 fullscreen 언어 검사는 안쪽 추가 영역을 먼저 닫는 전제를 명시했다. 개발 서버 소스 변경과 겹친 navigation/context 중단은 통과로 간주하지 않고 고정 소스에서 다시 실행한다.
- 후속 84개 중 82 PASS/2 실패는 뒤에서 적용되는 모바일 패널 높이 규칙까지 보정했다. 실패한 base/layer 선택 복구 4개 재검증 PASS. 최종 전체 관련 회귀 결과는 아래에 추가한다.
- 고정 소스의 다음 256개는 240 PASS/16 실패였다. 작은 패널의 고정 제목이 키보드 초점 대상을 가리는 실제 결함을 확인했다. 유효하지 않던 버튼 `font` 선언을 14px/1.35로 고치고, 데스크톱 drawer의 상태를 도구 위에 배치했다. 모바일 제목은 내용과 함께 스크롤되도록 바꿨다. DOM 측정값은 즉시 반영하되 SDK 재배치 debounce와 원래 범위 계약은 유지한다. 수정 후 지도 표시·주변 검색·15개 결과 키보드 탐색·도구 70개 PASS. 중간 측정/scroll-padding만의 시도는 60 PASS/10 실패로 충분하지 않았으며 최종 해결 근거로 사용하지 않는다.
- 실제 로컬 브라우저의 대체 지도와 원래 비활성 제어를 확인했다. 1440/960/390px 지도 및 960px 여행지 카드 캡처를 직접 검토했다. 지도 stub의 빈 캔버스는 실제 지도 증거가 아니며, 카드 테스트의 해안 사진은 레이아웃 fixture다. 실제 관광지 사진 출처로 사용하지 않는다.
- 최종 소스 타입 검사 PASS, lint 오류 0/기존 경고 13, unit 708 PASS, Vercel 빌드와 기존 예산 PASS. CSS gzip 69.89/70 KiB, Landing 초기 JS 121.37/155 KiB, Planner 초기 JS 268.93/270 KiB. SDK 단위 fixture에 실제 DOM의 위치/스타일 인터페이스를 반영했고 기존 pan/scroll/날짜 교체 계약을 보존했다.
- 실제 로컬 1280×720 브라우저에서 OSM 지도 타일, 접힌/펼친 도구와 이미지 패널의 상태·버튼 분리 배치를 직접 확인했다. 출발/도착 선택이나 GPS·제공처 재시도, 공유·다운로드는 실행하지 않았다. 이후 남은 Chromium 186개와 새 작업의 WebKit 결과는 완료 후 기록한다.
- 남은 Chromium 186개 PASS로 해당 시점의 관련 256개 전체가 통과했다. 첫 WebKit 20개는 17 PASS/3 실패: 영문 2개는 스크롤로 숨은 헤더를 `Control+Home`으로 되돌린다는 Chromium 전제였으며, 실제 설정 버튼 초점→화면 내 위치 확인→Enter 경로로 수정했다. 모바일 확대 1개에서는 ResizeObserver 전달 중 CSS 쓰기가 observer loop를 일으켰다. 쓰기를 다음 animation frame으로 옮기고 cleanup에서 예약 frame도 취소한다. 오류 무시·overlay 숨김·assertion 완화는 없다. 이 마지막 변경의 영향 검사는 별도 결과로 남긴다.
- 저장된 카드에서도 보이는 문구와 접근성 이름이 모두 ‘일정에서 빼기’/‘Remove from itinerary’를 포함하도록 맞췄다. 체크 표시와 눌림 상태는 유지한다.

### 최종 소스 결과

- Chromium 영향 검사 124/124 PASS (2.7분): 카드, 도구, 중첩 Escape/오류 0, 실제 Leaflet 날짜별 fit, 지도 표시/재연결/열린 패널, 언어 전환, 이미지/공유 복구, 주변 검색/15개 결과 키보드 탐색. 앞서 관련 256개 통과 후 frame/라벨 최종 변경에 해당하는 부분을 재검증했다.
- WebKit desktop/mobile 20/20 PASS (1.9분): 여행지 카드·지도 도구 및 CSS 확대 fallback. 같은 viewport를 포함해 모든 assertion을 유지했다. 실물 iOS/Safari 또는 실제 보조공학 전체 검증을 뜻하지 않는다.
- 다시 실행한 lint/typecheck/unit 708/build/performance 모두 PASS. lint 기존 경고 13, 오류 0. 최종 Planner 초기 JS 268.91/270 KiB, CSS 69.89/70 KiB, Landing 초기 JS 121.37/155 KiB.
- 최종 실제 로컬 지도와 960px 카드, 390px 마지막 주변 결과, WebKit 영문 어두운 카드의 문구/조작 배치를 직접 검토했다. fixture 이미지는 실제 장소의 사진으로 주장하지 않는다. 요소 캡처에는 고정 헤더가 포함될 수 있으며 별도 픽셀 기준선으로 등록하지 않는다.
- 최신 main `73f0914` ancestry와 diff whitespace 확인. 새 HEAD의 hosted CI와 실제 Production은 PR 생성 후 별도 확인한다.
