# PR #63 · Planner 상태와 부수효과 책임 분리

## 발견

`app/planner/page.tsx`가 관광지 추천 화면뿐 아니라 보관함 저장, 날짜 배치,
방문 순서 계산, 장소 검색 요청 취소, 경로 필터·정렬, 오디오 재생 상태와
스크롤 연출까지 직접 소유하고 있었다. 특히 기기 보관함은 저장값을 읽는
`requestAnimationFrame`보다 빈 초기 상태 저장 effect가 먼저 실행될 수 있어
기존 선택을 덮어쓸 가능성이 있었다.

## 구현

- `useTripSelection`: 기기 보관함, 날짜 배치, 방문 순서 최적화와 설명을 한 경계로 묶었다.
- 저장소 hydration 완료 전에는 쓰지 않도록 해 기존 보관 장소가 초기 빈 배열로 덮이지 않게 했다.
- `useLocationSearch`: 검색 입력·결과·loading과 AbortController 수명 주기를 분리했다.
- `useRouteView`: 교통수단 필터, 시간·요금·환승·도보 정렬과 활성 경로 계산을 분리했다.
- `useAudioGuide`: 재생·탐색·진행률·대본 상태와 이벤트 처리를 분리했다.
- `usePlannerChrome`: 스크롤 헤더와 reveal observer를 분리하고 남은 animation frame도 정리한다.
- PlannerPage는 1,011줄/약 75KB에서 885줄/약 68KB로 줄고 직접 `useState` 책임은 49개에서 31개로 줄었다.
- 요청 취소와 구조 경계를 확인하는 회귀 테스트를 새 훅 위치에 맞게 보강했다.

## 역할 구분

- 사람: Planner를 기능 경계로 점진 분리하고 기존 동작을 유지하라는 제품·아키텍처 기준 위임
- 도구: 상태 흐름 감사, 리팩터링, 저장 경쟁 수정, 회귀·빌드·배포 검증
