# 서비스 소개 하단 복구와 나루 연결·사진 입력

- 작성자: jeongiryang / Codex
- 범위: 사용자 승인 항목 1–4. GitHub PR 검증 후 기존 Production CD로 배포한다.
- 사람: 네 가지 개선 및 배포 승인. AI: 코드·서버 변경, 독립 QA, 검증과 릴리스 진행.

## 수정

하단 사진까지 숨기던 `.landing-cta:not(.is-visible) > *` 규칙을 제거했다. 사진과 글은 기본적으로 보이고 텍스트 묶음만 화면 진입 시 한 번 부드럽게 나타난다. 모션 감소·관찰 API 미지원 시에도 내용은 보인다. 최종 사진 위 흰 글자와 어두운 스크림을 유지하고 더 이상 쓰이지 않는 강조어 애니메이션을 정리했다.

나루는 연결 재확인, 재열기, 네트워크 복구를 지원한다. 이전 상태 확인 요청의 실패가 새 대화의 성공을 덮어쓰지 않는다. 서버 상태 확인 제한을 3.5초에서 8초로 조정하고 비밀값 없는 실패 분류만 기록한다.

실제 운영 대상은 `wave-barrier-free-gyeongnam.vercel.app`이다. 별도 `wave` 프로젝트의 환경 변수 부재를 실제 서비스의 원인으로 해석했던 이전 진단은 잘못됐다. 기존 운영 프로젝트에는 AI 환경 변수가 있고, DSW에는 WAVE 소유 전용 Tailscale Funnel과 정상 모델이 이미 있었다. 운영 API는 수정 전에도 available false/true를 번갈아 반환했으며 직접 연결은 정상 응답했다. 일시적 경로 지연 가능성은 확인했지만 단일 원인을 확정하지 않았다. 새 ngrok 계정이나 타인의 네트워크 설정은 사용하지 않았다.

사진 첨부는 브라우저에서 크기·메타데이터를 정리해 같은 출처 API와 인증 게이트웨이를 거친다. 사진에서 읽은 내용은 확인용이며 서버에서 일정 변경을 차단한다. 사진을 보관하거나 일반 대화 이력으로 재전송하지 않는다. 읽은 내용을 사용자가 확인·수정해 다음 요청을 작성한다. 도움말·개인정보 안내도 갱신했다. 상세 경계는 [사진 입력 기록](../naru-photo.md)에 있다.

앞선 작업의 미커밋 지도 정리도 보존했다. 지도 해제 시 클릭·영역 변경 리스너와 그리기 모드를 정리하며 관련 단위 회귀가 통과했다.

## 검증

- 전체 단위 검사 1,251개 통과. 사진 ICC 회귀 추가 후 관련 검사 17개 통과.
- 전체 lint: 오류 0, 기존 경고 15. 타입 검사 통과, 보안 감사 취약점 0.
- Vercel 빌드와 성능 예산 통과: CSS gzip 69.85KiB, 랜딩 초기 JS gzip 136.09KiB.
- 하단·기존 스토리 회귀 PC/모바일 10개 통과. 기존 대비·스토리 검사도 담당자 검증 통과.
- 독립 연결 복구 회귀 6개, 사진 UI·접근성·실패 복구 4개 통과. 합성 API 응답을 이용한 경계 검사다.
- DSW 게이트웨이는 기존 파일을 백업한 뒤 문법 확인·교체·전용 서비스 재시작 완료. 다른 GPU 작업은 변경하지 않았다.
- 실제 무료 Gemma 4 26B 비전 호출: 시험용 한글 포스터의 행사명·날짜·시간·장소·무료 여부를 6.4초에 인식, HTTP 200 / local-vision / proposal null. 모든 현장 사진의 정확도를 보장하는 결과는 아니다.

최종 PR CI·CD·운영 핵심 흐름의 결과는 해당 PR의 릴리스 확인 기록에 추가한다. 배포 전 로컬 검증을 운영 완료로 표시하지 않는다.
