## 목적

플래너에 `role="tablist"`이 세 곳 있었다. 셋 다 역할만 붙고 그 역할이 약속하는
동작은 없었다. 보조기술은 "탭 1/6"이라고 읽어 주고 사용자는 화살표로 옮겨 다닐 수
있다고 기대하는데, 눌러도 아무 일도 일어나지 않는다. 안내받은 조작이 통하지 않는
쪽이 역할이 아예 없는 것보다 나쁘다.

먼저 재현했다.

```
tablist "교통수단별 결과 필터": 탭 6개 · aria-controls 0개 · 탭순서에 6개
tablist "이동수단별 예상 시간": 탭 4개 · aria-controls 0개 · 탭순서에 4개
문서 전체 tabpanel: 0개
ArrowRight: "전체" -> "전체" (변화 없음)
Home/End 후 선택: "전체" -> "전체"
```

## 셋을 같은 방법으로 고치지 않았다

세 곳의 성격이 달라서, 각각 실제 동작에 맞는 역할로 바꿨다.

| 대상 | 실제 성격 | 처리 |
| --- | --- | --- |
| `ThemeExplorer`의 `.layer-tabs` | 고정 목록 + 바로 아래 패널 하나 | **진짜 탭 목록.** 패턴을 마저 구현 |
| `RouteComparisonPanel`의 `.route-mode-sections` | 예상 시간이 오면 **빠른 순서로 재정렬** | 선택 버튼 묶음으로 |
| `TransportModeSelector`의 `.transport-mode-filter` | 고른 값이 **세 곳**을 함께 바꿈 | 선택 버튼 묶음으로 |

**재정렬되는 목록은 탭이 될 수 없다.** 확인 과정에서 찾은 사실이다. 이동수단
요약은 예상 시간이 도착하면 빠른 순서로 다시 정렬된다(바로 아래 안내 문구가
그렇게 말한다). 실제로 ArrowRight로 `자동차`를 고르는 순간 `자동차`가 목록 맨
앞으로 이동했다. 화살표로 "옆 탭"에 간다는 약속을 지킬 수 없는 구조다.

**교통수단 필터는 가리킬 패널이 없다.** 고른 값이 예매 안내·운행정보 패널·경로
목록 세 곳을 함께 바꾼다. `aria-controls`가 가리킬 대상이 하나로 정해지지 않는다.

둘 다 저장소에 이미 있는 필터 관례(`community-tabs`, `profile-grid`)와 같은
`role="group"` + `aria-pressed`로 맞췄다. 색만으로 상태를 말하지 않는다는
디자인 규칙도 이쪽이 더 잘 지킨다.

남은 하나(`ThemeExplorer`)는 고정 카탈로그에 패널이 하나라 진짜 탭 목록이 맞다.
여기만 WAI-ARIA Tabs 패턴을 마저 구현했다.

- ← → ↑ ↓ 로 이동, 양 끝에서 반대편으로 감김
- Home / End 로 처음·끝
- 로빙 tabindex — 탭 목록 전체가 Tab 한 번에 걸린다(전에는 8번)
- `aria-controls` ↔ `id` / `role="tabpanel"` ↔ `aria-labelledby` 양방향 연결

키 계산은 `lib/a11y/tablist.js`에 순수 함수로 뒀다. DOM 없이 `node --test`로
검증할 수 있어야 해서다.

## 기존 테스트 두 개를 함께 고쳤다

- `e2e/planner-redesign.spec.ts` — `.route-mode-sections [role='tab']`와
  `getByRole("tab", …)`로 요소를 찾고 있었다. 화면 동작은 그대로이므로 선택자만
  새 구조에 맞췄다.
- `e2e/map-tools-reachable.spec.ts` — `getByRole("button", { name: "공유" })`는
  이름 **부분 일치**라, 필터가 버튼으로 돌아오자 `기타 이동 · 항공·선박·공유 이동`이
  먼저 잡혀 지도 밖 요소를 집었다. 지도 도구 막대 안으로 범위를 좁혔다.
  전부터 느슨했던 선택자이고 화면 동작이 바뀐 것은 아니다.

## 결과와 제한

역할과 키보드 처리만 바꿨다. 화면에 보이는 것, 고를 수 있는 값, 눌렀을 때 일어나는
일은 그대로다. CSS는 전부 `.active` 클래스 기반이라 손대지 않았다.

**범위 밖으로 남긴 것**

- **이동수단 요약이 고르는 순간 재정렬되는 것 자체**는 그대로 뒀다. "빠른 순서로
  정렬"은 의도된 동작이고(#200), 방금 고른 항목이 눈앞에서 자리를 옮기는 것이
  혼란스러운지는 별도 판단이 필요하다. 다음 작업 단위 후보다.
- `PreferenceControls`의 `<details open>` 하이드레이션 불일치 경고가 콘솔에 남는다.
- 하이드레이션 전에 누른 조작이 먹지 않는 것은 SSR 화면의 일반적 성질이라
  제품 결함으로 보지 않았다. 새 e2e는 그 구간을 다시 눌러 넘긴다.
