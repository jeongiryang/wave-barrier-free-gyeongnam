## 목적

작업을 멈추지 않고 이어가는 방식과, 판단이 필요할 때의 기준을 규칙으로 남긴다.
AI가 한 단위를 끝낼 때마다 보고하고 대기하면 사이클이 끊기므로, 다음 단위를
스스로 찾아 이어가도록 명시한다.

## 역할과 변경

- 사람: 자율 진행 권한을 위임하고, 판단이 필요한 사항은 AI의 최우선 추천으로
  진행하도록 결정했다. 저장소 이슈를 프로젝트 제약에 맞게 반영하라는 방침도 정했다.
- Claude Code: 위 방침을 `CLAUDE.md`의 `## 자율 진행` 절로 옮기고, 작업 사이클
  (작업 → PR → 최신 main·이슈 확인 → 다음 작업)과 다음 작업 선정 우선순위
  (버그 → 접근성 → 이슈 → 품질 → 고도화)를 규칙으로 세웠다.

## 판단 근거

`main`은 승인 필요 룰셋(`protect main`, `REVIEW_REQUIRED`)으로 보호되어 있어
AI가 올린 PR은 스스로 병합할 수 없다. 승인 대기가 다음 작업을 막지 않도록,
다음 단위는 계속 `origin/main`에서 새로 따는 것을 기본으로 규칙에 명시했다.
선행 PR의 결과가 반드시 필요할 때만 그 브랜치 위에 쌓고 PR 본문에 선행 번호를 적는다.

## 검증

- `npm run lint` 통과
- 문서만 바뀌어 동작 영향 없음
- 최신 `main` 리베이스 후 #17(AI 작업 로그)과 #19(병합 직전 최신 main 검증)에서
  추가된 규칙이 함께 남아 있는지 확인했다. 세 규칙은 서로 충돌하지 않는다.

## 결과와 제한

규칙 문서이므로 실행 코드에 영향이 없다. `## 자율 진행`은 AI가 사람의 확인 없이
진행하는 범위를 넓히므로, 되돌리기 어려운 작업(외부 서비스 설정 변경, 데이터 삭제,
도메인·키 교체)은 규칙 안에서 명시적으로 예외로 두었다.
