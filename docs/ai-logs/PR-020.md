## 목적

작업을 멈추지 않고 이어가는 방식과, 판단이 필요할 때의 기준을 규칙으로 남긴다.
AI가 한 단위를 끝낼 때마다 보고하고 대기하면 사이클이 끊기므로, 다음 단위를
스스로 찾아 이어가도록 명시한다.

## 역할과 변경

- 사람: 자율 진행 권한을 위임하고, 판단이 필요한 사항은 AI의 최우선 추천으로
  진행하도록 결정했다. 저장소 이슈를 프로젝트 제약에 맞게 반영하라는 방침도 정했다.
- Claude Code: 위 방침을 `CLAUDE.md`의 `## 자율 진행` 절로 옮기고, 작업 사이클
  (작업 → PR → 최신 main·이슈 확인 → 다음 작업)과 다음 작업 선정 우선순위
  (버그 → 접근성 → 이슈 → 품질 → 고도화)를 규칙으로 세웠다.
- Codex: 최신 `main` 기준으로 diff를 다시 검토하고, 승인 대기 중 병렬 작업이
  충돌을 만들 수 있는 규칙과 “모든 오류를 찾는다”는 검증 불가능한 완료 조건을
  수정했다. 병합 권한이 위임된 작업은 새 CI 성공 후 끝까지 병합하도록 정리했다.

## 판단 근거

`main`은 승인 필요 룰셋으로 보호되어 있으나, 사용자가 관리자 바이패스 병합을
명시적으로 승인했다. 따라서 실패·대기 중 검사는 우회하지 않고 리뷰 요구만
바이패스하며, 선행 변경이 필요한 작업은 선행 PR 병합 후 최신 `main`에서 시작한다.

## 결과와 제한

규칙 문서이므로 런타임 코드에는 영향이 없다. `## 자율 진행`은 사용자가 승인한
작업 범위 안에서만 적용하며, 되돌리기 어려운 작업(외부 서비스 설정 변경, 데이터
삭제, 도메인·키 교체)은 규칙 안에서 명시적으로 예외로 둔다.
