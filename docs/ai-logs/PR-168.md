# PR-168 — 지도 상단 컨트롤이 서로 겹치던 문제

## 목적

Kakao 지도 연결이 실패했을 때 나타나는 "Kakao 재연결" 버튼의 오른쪽 35%가
지도 명령 바에 덮여, 그 자리를 누르면 지도 유형이 대신 바뀌던 문제를 고친다.
복구 수단이 가장 필요한 순간에 눌리지 않았다.

## 원인

두 요소는 같은 컨테이너 안에서 각자 절대 위치를 잡는다.

```css
.map-provider-badge { z-index: 500; position: absolute; top: 14px; left: 14px; }
.map-command-bar    { z-index: 510; position: absolute; top: 12px; right: 12px;
                      max-width: calc(100% - 150px); }
```

`150px`는 배지 자리를 비우려는 예약값인데, 대체 지도 상태에서는 배지에
"Kakao 재연결" 버튼이 붙어 왼쪽 **171px**를 차지한다. 21px이 모자라고,
명령 바가 위(z 510)에 있어 그만큼을 덮는다.

## 브라우저 측정

### 넓은 폭 — 클릭을 뺏김

재연결 버튼 위 5개 지점을 눌러 실제로 누가 받는지 확인했다.

| 폭 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 1440px | x=70%, 90% → **"지도"가 받음** | 5/5 지점 모두 재연결이 받음 |
| 1200px | x=70%, 90% → **"지도"가 받음** | 5/5 정상 |
| 960px | x=70%, 90% → **"지도"가 받음** | 5/5 정상 |

배지가 왼쪽에서 차지하는 폭은 모든 넓은 폭에서 171px로 일정했고, 명령 바
시작점이 138px여서 32px씩 겹쳤다. 수정 후 명령 바는 184px에서 시작한다.

### 좁은 폭 — 배지 윗변이 눌림

780px 아래에서는 배지가 아랫줄로 내려가지만, 명령 바가 y 12..68을 차지하는데
배지가 60px에 있어 윗변 8px이 그 아래로 들어갔다.

| 폭 | 수정 전 세로 겹침 | 수정 후 |
| --- | --- | --- |
| 780·768·700·390px | 8px | -8px (여백) |
| 620·560·480px | 7px | -9px (여백) |

## 변경

- `app/styles/map-workspace.css`
  - `.map-provider-badge.osm + .map-command-bar`에 `calc(100% - 196px)` 예약.
    재연결 버튼이 붙는 상태에서만 좁힌다. Kakao가 정상 연결된 상태에서는
    배지가 좁으므로 기존 150px 예약을 그대로 두어 명령 바를 넓게 쓴다.
  - 780px 아래 배지 `top: 60px → 76px`, 620px 아래 `58px → 74px`.
- `e2e/map-chrome-overlap.spec.ts` — 1920~768px 7개 폭에서 배지와 명령 바의
  겹침 면적이 0인지, 재연결 버튼 위 5개 지점이 모두 자기 클릭을 받는지 고정한다.

## 설계 판단

**상태에 따라 예약 폭을 다르게 했다.** 항상 196px를 비우면 Kakao가 정상
연결된 흔한 상태에서도 명령 바가 46px 좁아져, 가로 스크롤에 숨는 컨트롤이
늘어난다. 배지와 명령 바는 인접 형제이므로 `+` 선택자로 재연결 버튼이 붙는
상태만 좁힐 수 있다.

**매직 넘버를 테스트로 묶었다.** 196px·76px·74px은 측정에서 나온 값이라
배지 문구나 버튼 크기가 바뀌면 다시 틀어진다. 그래서 값을 검사하는 대신
"겹치지 않는다"와 "클릭을 뺏기지 않는다"를 7개 폭에서 고정했다. 값이 모자라면
테스트가 먼저 깨진다.

**구조 개편은 하지 않았다.** 배지와 명령 바를 한 flex 행으로 묶으면 매직
넘버가 아예 사라지지만, 두 요소의 위치 규칙이 세 파일 8곳에 흩어져 있고
`drawer-open`·전체화면 규칙까지 얽혀 있다. 별도 작업 단위로 남긴다.

## 결과와 제한

전수조사에서 함께 확인했지만 결함이 아니었던 것:

- **지도 명령 바 버튼끼리의 겹침** — 기하학적으로는 겹쳐 보이지만 실제로는
  가로 스크롤 영역 밖으로 잘린 버튼의 레이아웃 사각형이었다. 스크롤 영역과
  전체보기 버튼 사이에는 6px 간격이 있다.
- **랜딩 지역 표식 18개의 상호 겹침** — 390·360px에서 가장자리가 겹치지만
  중앙 클릭을 뺏기는 표식은 0건이었다.
- 커뮤니티·로그인·가입 화면과 몸통 가로 스크롤은 4개 폭 모두 정상이었다.

남은 관련 문제(이번 범위 밖):

- 지도 명령 바는 컨트롤 8개를 가로 스크롤에 담는데 스크롤바를 숨긴다
  (`scrollbar-width: none`). 390px에서 826px 중 203px만 보여 **약 75%의
  컨트롤이 아무 표시 없이 가려진다.** 별도 작업 단위가 필요하다.
- 랜딩 지역 표식의 높이는 32~34px로 CLAUDE.md의 44px 기준에 못 미친다.
  히트 영역만 넓히면 표식끼리 클릭을 뺏게 되므로 설계 판단이 필요하다.
