# PR-182 — 커뮤니티 검색어의 와일드카드가 그대로 새어 들어가던 문제

## 목적

검색어에 든 `%` `_` `\`가 ILIKE 와일드카드·이스케이프 문자로 해석돼, 사용자가
적지 않은 조건이 붙거나 목록 요청 자체가 실패하던 문제를 고친다.

## 원인

```ts
const pattern = `%${search}%`;
```

`cleanCommunityText`는 제어문자만 지우고 `%` `_` `\`는 통과시킨다.

| 검색어 | 실제 동작 |
| --- | --- |
| `진_시` | `_`가 한 글자 와일드카드 → 진주시·진해시가 함께 나온다 |
| `50%` | `%`가 아무 문자열 → 적지 않은 조건이 붙는다 |
| `100\` | 패턴이 이스케이프 문자로 끝나 Postgres가 거부(`22025`) → 목록 요청 실패 |

## 변경

- `lib/community/validation.js` — `communitySearchPattern(search)`.
- `features/community/server/post-read-repository.ts` — 이 함수만 쓴다.
- `tests/community-search.test.mjs` — 동작 7건.

## 설계 판단

**입력에서 지우지 않고 질의에서 이스케이프했다.** `%`를 검색어에서 빼면
"50%"를 찾은 사용자가 "50"을 찾은 것이 되어 여전히 사용자가 적지 않은 동작이다.

**패턴 조립을 한 함수로 모았다.** 질의가 다섯 갈래로 나뉘어 있고 모두 같은
`pattern`을 쓴다. 조립을 호출부에 두면 갈래가 늘 때 이스케이프가 빠진다.

Postgres가 거부한다는 것은 문서화된 동작이며, 이 PR은 그 패턴이 만들어지지
않도록 막는다.
