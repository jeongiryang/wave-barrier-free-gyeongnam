# 인트로 다시 보기의 시작 투명도

운영 PR #617 확인 중 자동 종료 후 다시 보기를 누르면 종료 fade 상태가 남아 본문이 잠깐 비치는 현상을 발견했다. 사용자는 인트로 중 뒤쪽 서비스 화면의 선노출 방지를 요구했다.

dialog가 닫힌 뒤 leaving 상태를 초기화한다. 첫 노출, 자동 종료 fade, 건너뛰기, 모션 감소, timer/renderer 정리는 유지한다.

회귀 검사는 자동 종료 후 실제 다시 보기 버튼을 누르고 재생 시작 opacity가 즉시 1인지 확인한다. 수정 전 0.0100174로 실패했고 수정 후 PC·모바일 인트로/첫 방문 26개 검사가 통과했다. 이 opacity 검사는 fade 완료를 기다리는 재시도를 사용하지 않는다. 독립 QA에서 새 P0/P1이나 lifecycle 회귀를 발견하지 못했다.

심사 계정의 새 비밀번호 입력·최종 가입은 운영 가입 화면에서 사용자의 진행을 기다리고 있다. 계정이 만들어졌다고 간주하지 않는다.

## 사용자 추가 요구: 가입 길이와 시험 게시글 정리

가입 ID는 4–12자, 새 비밀번호는 8–16자로 화면·서버·재설정·계정 변경에 일치시켰다. 기존 긴 비밀번호와 이전 ID의 로그인은 유지한다. username 플러그인의 displayUsername 대체 경로도 같은 신규 ID 규칙으로 검증한다. 기존 fixture는 새 가입·재설정 값만 변경하고 기존 긴 비밀번호 로그인 검사를 유지했다.

사용자가 지목한 공개 게시글 `오류 확인 테스트`와 `질문드립니다`의 본문을 읽고 개발 테스트 내용임을 확인했다. migration 016은 각 ID와 제목이 함께 일치하는 두 행만 hidden으로 바꾼다. 원본·댓글·좋아요를 삭제하지 않으며 다른 글은 변경하지 않는다. 공개 목록과 상세 조회에서 제외된다.

단위 검사 1,505개, 인증·계정·인트로 브라우저 검사 62개, 타입·lint(오류 0/기존 경고 14)·빌드·성능 예산 통과. 독립 QA가 지적한 displayUsername 우회는 수정 후 실제 native auth 10개 검사로 재검증했다. 운영 반영은 최종 CI와 Actions CD 성공 후 확인한다.
