## 목적

공개 런칭 전에 브라우저 상태 변경, 계정 프록시, 환경 변수와 공유 링크의 신뢰 경계를 한곳에서 검증한다. 외부 계정 생성이나 Production 설정 변경 없이 코드로 검증 가능한 범위만 강화한다.

## 역할 구분

- 사람: 출시 마감 범위 승인, 실제 Neon·Vercel Secret 관리, 최종 승인
- AI: 보안 감사, same-origin·본문 상한·URL 검증 구현, 환경 설정 fail-closed 처리, 자동 회귀 테스트와 CI 보안 감사 추가

## 검증

- 다른 Origin과 `Sec-Fetch-Site: cross-site` 상태 변경 요청이 403인지 확인
- `Content-Length`가 없는 64KB 초과 인증 본문이 413인지 확인
- 인증 성공·오류 응답에서 브라우저·CDN 캐시 지시자가 모두 비공개 `no-store`로 닫히는지 확인
- 인증 공급자 오류가 계정 존재 여부나 내부 문장을 구분해 노출하지 않는지 확인
- 공유 URL의 외부 origin·비 HTTP 스킴 차단 확인
- Neon Auth 승인 HTTPS 호스트와 Postgres TLS 연결 문자열 검증 확인
- 001~005 migration이 빈 데이터베이스에서도 정확한 순서의 단일 트랜잭션으로 구성되는지 확인
- 모든 쓰기 제한이 429, `Retry-After`, `retryAfter`, `no-store` 계약을 지키는지 확인
- `npm audit --omit=dev --audit-level=high`
- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npm run build:vercel`

## 결과와 제한

- 커뮤니티·인증·익명 저장의 브라우저 상태 변경 경계를 통합하고, migration·cron은 기존 Bearer 경계를 유지한다.
- Production 의존성 감사는 취약점 0건이다. 전체 감사의 개발 전용 `vinext` 하위 `image-size` High 2건은 패치 버전이 없고 beta 전환 시 Vercel 500 회귀가 확인된 상태라 강제 업그레이드하지 않는다.
- 실제 계정 생성·로그인, 빈 staging DB 실행, Secret 교체, CSP nonce 전환, 운영 WAF·분산 rate limit, 개인정보·약관 정책 승인은 배포 환경에서 별도로 확인한다.
