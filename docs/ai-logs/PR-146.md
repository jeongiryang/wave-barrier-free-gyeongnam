# PR-146 — 익명 저장 경로의 쓰기 예산

## 목적

로그인 없이 열려 있는 `POST /api/trips`와 `POST /api/feedback`이 무제한으로
Neon에 행을 넣을 수 있던 것을 막는다.

## 문제

커뮤니티 쓰기는 세션 인증과 작성자별 제한(글 5회/10분, 댓글 20회/10분)이 있지만
이 두 경로에는 둘 다 없었다. 방어는 `readTrustedJson`의 `Origin`과
`Sec-Fetch-Site` 검사뿐인데, 두 조건 모두 **헤더가 없으면 통과**한다.
브라우저가 아닌 클라이언트는 두 헤더를 보내지 않으므로 그대로 지나간다.

공유 여행 한 건은 최대 65KB JSONB다. 무료 티어 Neon에서 저장 용량이 차면
공유·제보 기능이 함께 멈춘다.

## 변경

- `lib/trips/write-budget.js` — 순수 함수로 예산 판정. 짧은 구간(1분)과
  긴 구간(10분)을 나눠 본다. 여행 공유 20/90, 접근성 제보 10/45.
- `server/trips/write-budget.ts` — 한 번의 질의로 두 구간을 세고, 넘으면
  `Retry-After` 헤더와 함께 429를 돌려준다.
- `INSERT` 직전에 확인하도록 `itinerary-actions.ts`, `feedback-handler.ts`에 연결.
- 세는 질의가 순차 검색이 되지 않도록 `created_at` 인덱스를 추가.

## 설계 판단

**요청자를 식별하지 않는다.** IP나 그 해시로 버킷을 나누면 훨씬 정확하지만,
이 저장소는 사용자 위치를 브라우저 밖으로 내보내지 않는 것을 원칙으로 삼고 있고
IP 보관은 새로운 개인정보 항목이 된다. 저장소 전체의 최근 쓰기량만 세는 방식은
개인을 식별하지 않고도 저장 용량을 지킨다.

그 대가는 분명하다. 한 사람이 창을 채우면 그동안 다른 사람의 저장도 막힌다.
이 선택은 **DB가 차서 기능이 영구히 멈추는 것보다 잠시 막히는 편이 낫다**는
판단이다. 429 응답이 재시도 시각을 알려 주므로 정상 사용자는 안내를 받는다.

한도는 실제 사용 규모를 넘겨 잡았다. 여행 공유는 1분에 20건, 10분에 90건까지
허용되므로 공모전 심사 중의 동시 시연에도 걸리지 않는다.

## 검증

- `npm run lint` 통과 (경고 0)
- `npm run typecheck` 통과 (오류 0)
- `npm test` 통과 (72/72, 신규 5건)
- `npm run build:vercel` 통과
- 신규 테스트가 예산 경계값, 잘못된 카운트 입력, 예산 확인이 `INSERT`보다 앞에
  있는지, 그리고 판정에 요청자 식별 헤더를 쓰지 않는지를 고정한다.

## 영향과 제한

- 정상 응답 형태는 변하지 않는다. 새로 생기는 것은 429뿐이다.
- 한국관광공사 응답을 저장하는 구조는 만들지 않았다. 기존 정책 그대로다.
- 만료된 공유 여행을 실제로 지우는 작업은 이 PR에 넣지 않았다. 별도 작업 단위다.
