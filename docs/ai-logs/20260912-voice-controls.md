# 음성·문자 일정 조작 AI 작업 로그

- 작성자: jeongiryang / Codex
- 목적: 승인된 마지막 기능 후보24를 기존 Horizon 일정 편집에 통합한다.
- 역할: Owner가 기능 구현·머지·배포를 승인했고, Codex가 구현과 필요한 확인을 수행한다. 독립 QA가 변경 기능을 별도로 검토한다.

## 구현

마이크는 직접 시작할 때만 한국어 한 문장을 듣는다. 정확한 현재 공개 장소 이름과 담기·빼기·정보·다음 장소 명령만 미리 보여주며, 확인한 뒤 한 장소를 조작한다. 같은 이름은 지역·주소를 보고 선택하고 문자 입력으로 같은 기능을 이용할 수 있다.

잘못된 날짜·고정 약속·미완료 장소 정보·최대12개를 보호한다. 되돌리기는 최신 상태가 같을 때만 한 장소의 기존 저장 순서·날짜·체류·휴식·목적과 자동/수동 순서를 복원한다. 전체 초기화나 계정·메시지 쓰기, 음성·명령문 저장, 새 유료 API를 추가하지 않는다. 사용 방법·개인정보 처리 안내와 API 위험 문서도 함께 갱신한다.

기존 Production Permissions-Policy의 전면 마이크 차단을 same-origin 요청 허용으로 바꾼다. 카메라 차단·외부 origin 마이크 금지는 유지되며 실제 녹음 시작에는 명시 버튼과 브라우저 권한이 필요하다. 열린 외부 details가 닫힌 내부 도움말까지 빼기 아이콘으로 표시하던 선택자는 직접 자식 summary에만 적용한다.

## 검증 상태

- 단위884개, 타입/lint(오류0,기존 경고12), Vercel 빌드·성능, 변경 기능 브라우저8개 및 헤더 경계23개 PASS. 1440/960/390/320 화면 및 axe 확인. 독립 QA 최종 재확인과 CI·Production 대기.
- 독립 QA에서 찾은 두 진입점 문제를 수정했다. hidden으로 유지되는 일정 단계에서 벗어나면 듣기를 중단하고 미확정 미리보기를 폐기한다. 장소 상세를 열 때 유지되는 명령 입력으로 복귀 대상을 잡아 Escape 후 키보드 초점이 돌아온다. 두 경로의 회귀 assertion을 기존 변경 기능 검사에 추가해 8개 모두 통과했다.
- 초기 두 검사 경로를 수정했다: select는 실제 combobox 접근성 이름으로 지정하고, 자동 정렬 시나리오는 실제 검색 결과가 있는 초기 상태로 구성했다. 검색 전 새 장소 명령이 거부되는 정상 동작을 우회하지 않았고 검사 조건·타임아웃은 유지했다.
- 실제 사용자의 마이크를 녹음하지 않는다. 합성 인식 이벤트와 문자 조작으로 명시 확인·취소·늦은 이벤트·미지원/거절 경계를 검증한다. 실제 기기 인식 정확도는 별도 제약이다.
- 전체 조작검수·회귀 분석/리팩토링·공모전 제출 전 점검은 Owner 지시로 다음 작업에 남긴다. 머지·배포 근거는 해당 PR에 기록한다.
