## 목적

`/planner`에서 문서 전체가 가로로 스크롤되는 문제를 없앤다.
960px(창 절반)에서 29px, 768px에서 33px, 390px에서 11px 밀려 있었다.

## 역할과 변경

- 사람: 정렬과 반응형을 고도화하라는 방침을 정했다.
- Claude Code: 뷰포트별 가로 넘침을 자동으로 재는 점검 스크립트를 만들어 원인
  요소를 특정하고, `.place-carousel`의 폭 기준을 뷰포트에서 컨테이너로 바꿨다.

## 원인

`.place-carousel`은 `width: calc(100vw - ...)`로 뷰포트 기준 폭을 잡고 있었다.
원래 `.places-section`이 화면 끝까지 흐르는 전체 폭 구역이어서 맞는 계산이었다.

#15에서 이 구역을 기능 단위 카드(`width: min(1560px, calc(100vw - gutter*2))` +
좌우 패딩)로 바꾸면서 컨테이너가 뷰포트보다 좁아졌는데, 캐러셀은 그대로
뷰포트 기준이라 카드 밖으로 삐져나갔다. #15가 만든 회귀다.

## 판단 근거

캐러셀을 단순히 `width: 100%`로 두면 카드 안쪽 패딩 때문에 카드 끝까지 흐르는
연출이 사라진다. 그 연출은 의도된 디자인이므로, 카드 패딩을 `--card-pad-x`
변수로 뽑아 음수 마진으로 그만큼만 빠져나가게 했다. 뷰포트 기준 계산이
사라졌으므로 앞으로 구역 레이아웃이 바뀌어도 같은 문제가 재발하지 않는다.

## 검증

- 960px에서 캐러셀이 카드 끝까지 흐르고 그 안에서 가로 스크롤되는 동작 유지 확인
- `npm run lint`, `npm run typecheck`, `npm test`(10 pass), `npm run build:vercel` 통과

## 결과와 제한

이번 변경은 추천 여행지 캐러셀에만 적용된다. 같은 점검에서 함께 발견한
나머지 항목은 별도 작업 단위로 남긴다.

- 헤더 내비게이션 링크의 높이가 21~31px로 WCAG 2.5.8 최소 크기(24×24)에 걸친다.
- Leaflet 확대·축소 버튼이 30×30으로 44px 기준에 못 미친다.
- `Kakao 재연결` 버튼이 79×24로 작다.
