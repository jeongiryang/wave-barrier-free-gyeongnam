## 목적

Owner가 지정한 최신 PDF 4쪽을 읽고 기능 화면을 같은 시각 구성으로 적용한다. 별도 디자인 PR로 병합·배포 확인 후 카카오 로그인과 ODsay 운영 한도 작업을 진행한다.

## 역할 구분

- 사람: 시안 전달, 구현 범위와 병합·배포 승인, 공개 한국어·밝은 테마 결정.
- AI: 첨부 확인, PDF 시각 비교, 기존 기능 위에 컴포넌트·스타일 적용, 핵심 브라우저 검증, PR 및 배포 확인.

## 검증

- `npm run typecheck`, `npm run lint`(오류 0, 경고 13), `npm test`(770개), `npm run build:vercel` 통과.
- 1440px·960px·390px 렌더와 데스크톱/모바일 핵심 7단계 흐름 확인. 기존 개발 전용 테마 복원 시 대비 회귀도 수정 후 양 기기 통과.
- 브라우저: 새 7단계 흐름의 저장·공유·날짜 변경·순서 변경·지도 로드 확인. 최종 CI 결과는 PR checks가 기준이다.
- 성능 검사에서 초기 CSS 75.41 KiB 초과를 발견해 현재 컴포넌트에서 쓰지 않는 이전 헤더·레일·지역 지도·카드 스타일을 정리했다. CSS 69.87 / 70 KiB, Planner 초기 JS 269.92 / 270 KiB로 통과. 성능 예산은 유지했다.
- 달력·일정·전체보기는 해당 화면을 열 때 로딩한다. 변경 후 지역·지도·공유/저장과 네트워크 경계의 브라우저 22개(데스크톱/모바일)를 확인했다.
- CI의 외부 사진 응답 대기를 없애기 위해 갤러리 이미지는 lazy로 요청하고 fixture UI 테스트의 사진 호스트를 고정했다. 실제 사진은 별도 로컬 브라우저에서 확인했다.
- 새 밝은 화면의 색상 토큰이 기존 세부 도구의 개발 전용 테마를 덮지 않도록 범위를 분리했다. 필수 키보드·저장·접근성 테스트를 유지하며 새 헤더/하트/단계에 맞춰 선택자를 갱신했다. 후속 로컬 전체 단위 테스트 770개 및 마지막 실패 항목 양 기기 12개 통과.
- 입력 날짜 변경이 기존 방문 날짜를 자동 덮어쓰지 않음을 확인했다.
- Hosted CI 후속에서 초기 저장 복원 중 조건 입력을 보호하고, 지연 로딩되는 전체보기의 제목을 먼저 유지해 단계 이동 초점을 보존했다. 긴 지도 도구가 좁은 화면의 패널을 가리지 않도록 캔버스 높이를 맞췄다. 정수 `clientWidth`와 소수점 텍스트 측정의 단위 차이는 실제 소수점 내부 너비 비교로 수정했다.
- 후속 핵심 브라우저 17개 및 남은 대비·지도·날짜 편집의 데스크톱/모바일 12개 통과. 최종 로컬 CSS 69.92 / 70 KiB, Planner 초기 JS 269.99 / 270 KiB, 타입 검사·단위 테스트 770개 통과. Hosted CI는 이 수정 커밋의 결과를 사용한다.

## 결과와 제한

디자인 변경에 인증 DB 이관이나 API 결제·키 변경을 섞지 않는다. `docs/design/planner-pdf-reference-20260910.md`에 시안과 실제 데이터의 차이를 기록한다. Production 성공 여부는 배포 SHA·화면 확인 후 별도로 기록한다.
