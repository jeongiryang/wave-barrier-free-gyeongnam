## 데이터·권한 경계

- 새 스키마: `014_travel_experience.sql`. Production 원자적 migration chain, 신규 환경 bootstrap, 예약 만료 정리와 계정 탈퇴 삭제에 연결했다.
- 현장 관찰은 선택값만 저장한다. 연락처·건강정보·GPS·원본 관광 API 응답은 저장하지 않는다. 공개 응답은 작성자 ID를 제외하며 작성자/장소별 최신 관찰만 집계한다. 24시간 뒤 예약 작업에서 삭제한다.
- 동행 payload는 기존 공개 일정 allowlist를 사용한다. 30일 만료, 256-bit 초대 비밀의 해시 저장, URL fragment 교환 후 HttpOnly/SameSite/경로 제한 쿠키, 초대 갱신/종료를 제공한다. 같은 역할의 초대는 공동 권한이다. 개인별 회원 관리가 필요한 경우 기존 계정 여행 참여 기능과 통합할 후속 설계가 필요하다.
- 모든 쓰기는 동일 출처·본문 크기·허용 값·권한을 검증한다. 일정 수정은 SQL revision compare-and-swap으로 동시 쓰기를 차단한다. 대기 제안/이동 기록/변경 이력 수와 쓰기 빈도도 제한한다.
- GPS는 위치 콜백 내부 거리 계산에만 쓰며, 여행여권에는 장소 ID·날짜·참여 방식·기기 근접 확인 여부만 저장한다. 공개 제보와 개인 기록을 구분한다.

- 로컬 전체 단위 검사: 1,269개 통과.
- 변경 핵심 브라우저 14개와 기존 일정 연속성 12개 통과(고유 26개), desktop/mobile. 1440·960·390px 넘침과 키보드 초점, 새 영역 axe 검사 포함.
- lint 오류 0, 기존 경고 14. TypeScript, Vercel build 통과.
- 의존성 보안 감사: 취약점 0.
- 성능 예산 유지: CSS gzip 69.99 KiB, 소개 초기 JS gzip 136.42 KiB, Planner 초기 JS gzip 204.62 KiB.
- 기능 브라우저는 합성 관광·현장·동행 API를 사용했다. 실제 DB 배포, 실사용자 로그인/초대 왕복, 현장 음원의 CORS/청취 품질, 실제 콜택시 접수는 검증 완료로 주장하지 않는다.
