## 참가 부문 확정, 운영·제출 검증 진행 중

참가 부문은 **① 웹·앱 개발 부문**이다. 사용자 확인, 2026-05-05 접수확인 메일,
2026-05-18 예비심사 합격 메일, 2026-07-31 1차 심사자료 안내와 공식 Notion을 대조했다.
과거의 **②-2 웹·앱 구현 부문 / 지정과제 1** 판단은 폐기됐다. 과거 커밋은 수정하지 않는다.
최종 심사 일부가 다른 부문과 통합된다는 안내는 참가 부문 변경을 뜻하지 않는다.

- 접수 서비스명: **사회적 약자 관광 편의 제공앱**. 최종 유형: **Web**, 특화 지역: **경상남도**.
- 사용자가 확정한 팀명: **WAVE**. 접수확인 메일에는 **W.A.V.E**로 적혀 있어,
  변경 불가인 원 접수 화면의 팀명과 대조해야 한다. 서비스 브랜드와 접수 팀명을 혼동하지 않는다.
- 1차 심사자료 제출 완료 화면·메일·접수번호는 확보하지 못했다. 미확인은 미제출 확정과 다르다.
- 현재 Production SHA는 `34e6021265b16d046dca24feaa3ec2101fc977e2`다.
  미병합 후보의 구현·테스트를 운영 완료로 표시하지 않는다.

이 문서는 공식 기능설명서를 대체하지 않는다. [공식 양식에 옮길 초안](submission/development-entry-draft.md)을 별도로 관리한다.

최신 제출 표·유의사항에서 대표 KTO API 1개의 운영계정 신청은 **선택 사항**이다.
기존 FAQ 표현과 차이를 기록하되, 의무로 단정하지 않는다. 활용한 KTO API 신청자별
인코딩·디코딩 인증키는 실제 제출 포털에서만 입력한다. 호출 이력과 서비스 내 표출을 모두 확인한다.
2026-06-24 KTO 데이터 담당 회신은 외부 API·AI API의 병행 사용을 허용하면서 데이터 출처의
명확한 구분을 요구했다. 이는 유료 모델 API 사용을 금지한 이 프로젝트 비용 정책을 바꾸지 않는다.

1차 심사 배점은 기획력 30·완성도 30·데이터 활용 20·발전성 20이다.
경남은 공식 RTO 특별상 나열 지역에 포함되지 않는다. 지역특화 가점과 RTO 특별상은 별개다.
공식 출처 표기는 `출처: ⓒ한국관광공사` 또는 `출처: ⓒ한국관광콘텐츠랩`으로 한다.
`TourAPI` 단독 표기나 공사 CI/BI의 임의 사용을 출처 표시로 대신하지 않는다.

## 코드와 안내의 위치정보 정합성

- 공개 출발 거점·사용자가 지도에서 선택한 지점 → W.A.V.E 경로 API → Kakao·ODsay.
- 브라우저 현재 위치 → 기기 메모리에서 별도 표시. 이 상태에서는 W.A.V.E 경로 API 호출을 차단.
- 지도 SDK·대체 타일의 표시 영역, 접속 IP, 사용자가 실행한 주변 검색의 지도 중심 좌표는
  지도 제공처가 처리할 수 있다. 따라서 **모든 위치가 기기 안에서만 처리된다**고 설명하지 않는다.
- 현재 위치 사용 전에 처리 안내와 브라우저 권한을 확인한다. 거부해도 공개 거점을 선택할 수 있다.
- 정밀 GPS는 공유 URL·공유 DB·저장 장소 목록에 넣지 않는다. 저장 장소의 좌표는 공개 관광지 좌표다.
- 구현상의 최소화와 법적 의무 충족은 별개다. 운영주체가 위치정보 신고·동의·약관 요건을
  [위치정보지원센터](https://www.lbsc.kr/) 등 공식 경로로 검토해야 한다.

## 핵심 기능설명서에 사용할 다섯 흐름

1. 지역·필요 편의·여행 취향 선택 → 사용자가 추천 조회 실행.
2. KTO 관광·무장애 항목의 확인됨·불일치·미확인 비교 → 장소 선택.
3. 날짜별 일정 추가·순서 편집 → 같은 날짜의 장소만 지도 표시.
4. 자동차·대중교통 응답, 날씨·혼잡 영향과 대안 비교 → 사용자 재선택.
5. 공유 링크·여행집 보관 → 방문 후 장소에 연결된 현장 후기.

이 목록은 **문서 초안 구조**다. 대안이 자동으로 접근 가능한 전체 경로를 보장한다거나,
저상버스·경사·승강기 운휴 정보가 모두 제공된다고 쓰지 않는다.
현재 조회한 한 구간과 일정 전체를 구분하고 미지원·미확인 범위를 명시한다.

## 최종 제출 전에 사람이 할 일

1. 원 접수 화면의 팀명(WAVE/W.A.V.E 차이)과 최종 제출 서비스명을 확인한다.
2. 참가자·팀 구성·이력과 위치정보 관련 의무를 확인한다.
3. 실제 연락 가능한 운영주체와 비공개 문의 이메일을 정한다. 임의의 이메일을 만들지 않는다.
4. 실제 메일 수신·탈퇴, 운영자 신고 처리, Neon 백업 복원을 계정 권한으로 확인한다.
5. 당사자·실물 모바일·화면 낭독기로 시연하고 결과를 기록한다.
6. 원 신청 계정에서 최종 PDF·URL·API 정보를 제출하고 접수 번호를 보관한다.
