# 2026 관광데이터 활용 공모전 정합성 점검

> 확인일: 2026-08-18
>
> 제출 부문: **②-2 웹·앱 구현 부문**
>
> 제출 형태: **반응형 웹 서비스**
>
> 선택 과제: **지정과제 1 — 여행 중 발생하는 실시간 변수(날씨 변화, 혼잡도 상승, 동선 꼬임 등) 대응의 어려움**

## 결론

W.A.V.E는 지정과제 1에 부합한다. 날씨와 관광지 집중률을 확인하고, 접근성 조건을
반영한 대안 여행지와 이동 경로를 비교·재계산하기 때문이다. 지정과제 참고 자료의
“실시간 대화형 여행 가이드”는 이해를 돕는 예시일 뿐 동일한 대화 UI를 구현해야 하는
의무사항이 아니므로, 현재의 시각적 여행 플래너 방식도 허용 범위다.

제출 형태는 앱이 아니라 웹이 적합하다. 현재 심사 가능한 완성 산출물은 Vercel에
배포된 반응형 웹이며 Android/iOS 네이티브 패키지는 존재하지 않는다.

## 요구사항 대응표

| 공식 요구사항 | W.A.V.E 대응 | 상태 |
| --- | --- | --- |
| ②-2 웹·앱 구현 부문 | 기존 아이디어를 실제 동작하는 반응형 웹으로 구현 | 충족 |
| 지정과제 10개 중 1개 선택 | 지정과제 1을 선택하고 날씨·혼잡·동선 변경 대응에 집중 | 충족 |
| 한국관광공사 OpenAPI 필수 활용 | `worker/index.ts`에서 관광지, 무장애 정보, 관광사진, 집중률, 행사·숙박 데이터를 런타임 호출 | 충족 |
| 개발 완료된 완성 서비스 | Vercel Production과 CI·CD가 연결되어 있고 핵심 검색·추천·경로 기능 동작 | 조건부 충족 |
| 국내 거주자, 팀당 최대 5명 | 코드로 확인할 수 없는 참가자 정보 | 제출자가 직접 확인 |
| 동일 서비스의 과거 수상·공사 지원사업 수혜 이력 없음 | 저장소만으로 확인할 수 없는 이력 | 제출자가 직접 확인 |

`조건부 충족`은 배포 자체가 미완성이라는 뜻이 아니다. Google Safe Browsing 재검토,
모바일 실기기 검증, 일부 관광지 사진 누락을 제출 전 운영 체크리스트로 추적한다.

## 한국관광공사 OpenAPI 실제 활용

서버 함수는 `TOUR_API_SERVICE_KEY_ENCODED`를 사용해 다음 API를 실시간 호출한다.

- `KorService2`: 지역 기반 관광지, 키워드 검색, 행사·숙박 등
- `KorWithService2`: 무장애 여행 상세 정보
- `PhotoGalleryService1`: 공공누리 관광사진
- `LocgoHubTarService1`, `TarRlteTarService1`: 지역 관광·연관 관광지와 집중률
- 기타 서비스별 관광 데이터: 반려동물·웰니스·의료관광·다국어 관광정보

원본 응답 전체를 Neon에 복제하지 않으며, 화면에는 한국관광공사·한국관광콘텐츠랩
출처와 W.A.V.E가 공식 운영 서비스가 아니라는 사실을 함께 표시한다.
