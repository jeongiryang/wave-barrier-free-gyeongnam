## 독립 QA에서 발견하고 수정한 문제

- 빈 결과를 다시 조회하면 조건 화면으로 돌아가 새 결과가 숨었다. 결과 화면의 사용 가능 여부와 완료 판정을 분리했다.
- 계정 여행을 여는 동안 편집하면 클릭 당시의 값으로 덮어썼다. 응답 뒤 최신 입력을 비교하고 변경 시 이동을 멈춘다.
- Leaflet 첫 view 이전에는 핀 DOM이 없어 선택 ID가 붙지 않았다. 초기화 뒤 실제 핀에 적용한다.
- 개인 홈이 수동 방문 순서를 무시했다. 저장 순서와 날짜를 반영했다.
- 같은 접근성 이름의 택시 안내가 반복됐다. 목적지를 포함해 구분했다.
- 저장소 오류·다른 탭/계정·늦은 응답이 새 상태를 덮는 분기를 차단하고 복구 안내를 보강했다.
- 최종 전체 CI에서 자동 구간 조회가 직접 선택한 경로 시간을 덮는 문제를 발견했다. 공개 출발·도착·이동수단이 일치하는 직접 선택을 우선하고, 수동 조회 직후 같은 구간의 자동 재조회를 막았다.
- 같은 장소 목록인데 언어 전환만으로 지도 SDK를 다시 생성하던 문제, 320px 영문 메뉴 잘림, 검색 중 키보드 초점 유실, 새 여행에 이전 탭의 편의 선택이 남는 문제를 수정했다.
- 실제 CI의 느린 지도 로딩에서 자동 이동 구간 조회가 끝나는 순간 경로 선택 위치가 움직이는 문제를 추가로 재현했다. 지도 자체뿐 아니라 앞쪽 조회 상태와 동작 영역의 크기도 유지하도록 수정했다.
- 저장 장소 ID 재조회와 새 검색의 응답 순서가 달라도 더 최근의 항목별 시설 근거를 보존한다. 최신 부재·제공처 실패 역시 이전의 긍정 정보로 되돌리지 않는다. 시설 전용 브라우저 검사는 두 API 경로에서 같은 합성 근거를 반환하게 연결했다.
- 실제 후속 대화에서 이동수단만 바꿔도 장소를 새로 고르고, 쉬는 시간을 체류 시간으로 해석했다. 최신 발화의 구체적인 변경을 분리해 장소·날짜·고정 방문·필요한 편의를 보존하며 해당 이동수단이나 휴식만 변경한다.
- 제공처 요청 제한으로 추천이 0곳일 때 나루는 실패와 빈 결과를 구분하고, 직접 편집도 현재 검색의 미확인 후보를 명시적 확인 후 담을 수 있다. 확인란은 기본 미체크이고 결과·조건·장소가 바뀌면 무효화된다. 확인 상태를 승격하거나 필수 편의를 풀지 않는다.
- 실제 축제 포스터가 240px 사진 영역을 넘어서 제목과 날짜를 덮었다. 사진 박스를 명시하고 포스터 전체를 영역 안에 맞춰 1440·960·390px에서 확인했다.

첫 전체 CI 후보는 이전 화면·수동 조회 전제를 사용한 검사와 새 저장 장소 조회를 연결하지 않은 fixture에서 실패했다. 실패를 우회하지 않고 위 제품 결함을 고쳤으며, 정확한 요청 출발·도착과 작업 완료를 기준으로 검사를 갱신했다. 필요한 편의 선택이 선택 사항으로 바뀐 동선, 실제 새 축제 메뉴, 현재 탭 복구와 명시적인 새 여행 초기화의 구분도 검증했다. PR #502의 최종 전체 CI는 단위 1,076개·브라우저 1,405개 통과, 실패·flaky 0으로 성공했다. 동일 화면 크기를 desktop 프로젝트에서 이미 검사하는 mobile 중복 1개는 기존 설정대로 생략했다.

## 실제 제공처와 합성 검증

최종 로컬 LLM 평가의 14개 의도 범주와 후속 대화 5개가 모두 올바른 작업과 필수 인수로 연결됐다. 이 결과는 모든 코스의 시설 확인 성공을 뜻하지 않는다. 제공처 실패로 실내 근거를 얻지 못한 요청은 빈 일정안과 복구 안내를 반환했다. 앞선 실제 시연에서는 이미 실내인 방문은 그대로 두고, 야외 진주성은 공식 실내 근거가 있는 진주남강유등전시관으로 교체할 수 있었다. 축제는 아라가야문화제의 실제 개최일과 함안 주변 장소를 제안했다. 장소와 시설 상태는 매번 제공처 응답으로 재검증한다.

무장애 정보 제공처가 HTTP429를 반환한 시점에는 최신 시설 근거를 받지 못했다. 이를 ‘시설 없음’이나 ‘접근 가능 확인’으로 표시하지 않는다. 장소 상세 제공처 실패로 저장 여행의 공개 좌표를 재확인하지 못한 경우도 있었다. 저장한 장소·순서·날짜는 유지하고 경로는 미확인으로 표시한다. ODsay의 기존 제한도 유지되며 실제 자동차 경로 확인이 전체 교통 접근성 확인은 아니다. 음원은 브라우저에서 재생까지 확인했다.

세션 만료·저장소 차단·오래된 응답·제공처 실패·인증 복귀는 합성 API를 연결한 실제 브라우저에서 검증한다. 이 결과를 실제 사용자 계정 로그인 성공으로 표시하지 않는다. 최종 hosted CI, 배포 SHA와 Production 시연 결과는 해당 PR/배포 실행과 최종 운영 결과에 남긴다. 로컬 PASS만으로 배포 완료라고 하지 않는다.

## 제안서와 제품 정합성

이동·돌봄·정보 접근에 제약이 있는 사람도 최소 입력으로 여행을 만들 수 있게 한다. 관광 좌표·사진, 무장애 시설, 실제 축제, 오디오·대본을 방문 결정과 일정에 연결했다. 정밀 경사·단차 데이터가 없는 구간은 정밀 지도나 통행 보장을 표시하지 않는다. 과거 제안서의 원본 관광 데이터 DB 적재 구상은 현재 정책에 따라 응답 캐시와 서비스 생성 일정 저장으로 구현한다. 다국어·사용자 제보 자동 반영 같은 향후 비전을 현재 제공 기능처럼 홍보하지 않는다.

[OpenAI 공식 GPT-6 Astra 안내](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)는 2026-09-12 개발 지침 정리에 참고했다. 서비스 런타임 AI와 추가 과금 자동화를 위한 마이그레이션이 아니다.
