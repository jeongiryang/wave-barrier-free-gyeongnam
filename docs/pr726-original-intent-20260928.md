# #726 원안 복원 기록

기준은 unknownamed가 작성한 #726의 원본 `9c988cf76199d10fe147d89101891ff32f4f0a6c`와 [당시 디자인 기록](local-design-review-20260927.md)이다. 배포된 squash `bcb380ebcba9d503a4c7acb8d0802c26efd31671`에는 이후 리뷰 과정의 변경도 들어갔다. Owner는 9월 28일 원안의 디자인·문구·배치·연출을 확정 기준으로 재지정하고, 재현 가능한 정합성·버그 수정만 허용했다.

## 복원 범위

- 리뷰가 바꾼 스타일시트 10개를 원본과 동일하게 복원했다: `map-workspace`, `naru-friendly`, `naru-workspace`, `night-secondary`, `photo-cards`, `place-decisions`, `planner-unified-workspace`, `scenic-design`, `wave-palette`, `wave-ui-refresh`.
- 사진 위 공통 표면을 원래 5% 파랑·2px 흐림으로 복원했다. 리뷰 때 추가한 85% 배경, 히어로의 어두운 방사형 덮개와 기타 색·간격 변경을 포함해 되돌렸다. 원래 사진·캐릭터·문자 그림자·배치를 유지한다.
- `ItineraryRouteCoverage`, `RouteMapWorkspace`, `TripDecisionReceipt`, `AlternativeComparisonDialog`도 원본과 동일하게 복원했다. 리뷰에서 덧붙인 반복 경고와 색상 변경이 제거된다. 실제 조회 범위·오류·제공처 정보와 기존 정책·다운로드의 제한 설명은 유지한다.
- 인트로의 사후 추가된 '이미 조작 중이면 자동 생략' 조건을 제거했다. 원래 자동 시작 조건·그림·길이·건너뛰기·재방문·모션 감소 동작을 유지한다. 원안에 없는 시작 덮개나 대기 타이머를 만들지 않는다.
- 하네스의 오래된 '#715 밤 나루·인트로 제거' 기준을 #726 원안으로 갱신했다. 하네스가 팀의 승인된 화면을 재설계하는 권한을 갖지 않도록 명시했다.

## 기능 수정과 디자인의 구분

원안 이후 추가된 수정 중 계정 변경·마운트 해제 뒤 늦은 응답 차단, 명시적 다른 탭 여행 복원 시 오래된 URL 해제, 메뉴·달력의 화면 크기 변경 처리, 중첩 대화창의 초점·스크롤 소유권, SSR 지역 선택값의 hydration 복원, 관찰 API 미지원 시 정적 콘텐츠 노출, 실제 나루 실행 상태 보존은 유지한다. 이것들을 원안의 시각 디자인으로 설명하지 않는다.

인트로가 끝나면 원래 조작하던 컨트롤에 초점을 돌려준다. 인트로 도중 native select가 custom combobox로 준비된 경우 같은 선택기의 현재 보이는 버튼으로 복귀한다. 자동 인트로를 생략해서 이 문제를 회피하지 않는다.

원안 검증 중 사진 `onLoad`가 먼저 완료된 뒤 초기 `requestAnimationFrame`이 `loading=true`로 되돌리는 경합을 재현했다. 이 상태에서는 디코딩된 사진 위에 로딩 표면이 계속 남아 있었다. 별도의 상태 수명 수정과 회귀 검증으로 처리하며 사진·표면 디자인은 바꾸지 않는다.

## 검증의 해석

복원 이후 확인한 근거를 기존 #726 리뷰의 통과 기록과 분리한다. 인트로 32개와 원안의 실제 정보 위치에 맞춘 경로·언어·다운로드 18개 검사는 desktop/mobile에서 retries 0으로 통과했다. 핵심 여행 54개, 단위 1,821개, lint도 복원 상태에서 통과했다. 사진 경합 수정 후 최종 검증과 원격 CI는 별도로 기록한다.

사진 대비 검사는 `img.complete`만으로 사진이 보인다고 가정하지 않는다. 로딩 표면이 사라지고 실제 사진이 그려진 상태인지 확인한다. 글자 측정은 실제 배경·그림자·글자 크기를 반영해야 하며, 큰 글자 3:1과 본문 4.5:1을 구분한다. 측정 오류와 실제 대비 한계는 각각 기록한다. 통과를 위해 원안의 표면을 다시 어둡게 바꾸거나 실패 표본을 버리지 않는다.

초기 진단의 흰 사진 대비 실패와 실제 사진의 일부 낮은 대비는 합격으로 바꾸지 않는다. 로딩 표면을 측정했던 초기 통과 사례도 사진 대비 통과 근거로 사용하지 않는다. 실제 렌더링과 측정 방식의 대조가 끝나기 전 전수 접근성 합격을 주장하지 않는다. 실기기 검증은 수행하지 않았다.

독립 재검증에서 1440px 히어로의 낮은 대비는 배경 도시 조명의 작은 부분과 실제 글자가 겹친 결과로 확인했다. 제목의 불투명 글자 표본 9,456개 중 251개(2.65%)가 3:1 미만이고 중앙값은 12.036이었다. 본문은 표본 2,503개 중 90개가 4.5:1 미만이었다. '화면 전체가 읽히지 않는다'는 주장과 구분하되, 국소 대비 실패 자체는 실제 결과다. 390px 제목은 32px·800 굵기에 3.562로 큰 글자 기준을 충족했다.

과거 검사에 있던 3px 초점 외곽선 강제와 지도 패널 최소 250px 강제는 원안의 2px 초점·214px 패널을 오류로 취급했다. 초점 검사는 기존 공개 화면 검사와 같은 2px 및 실제 키보드 초점으로, 지도 검사는 패널·버튼의 가로 넘침·모든 버튼의 44px 조작 영역·PNG 버튼의 실제 클릭 가능 여부로 확인한다. PNG 실패→재시도→다운로드, 지도 제어판 겹침, axe 검증은 그대로 유지했다. 원안 CSS를 변경하지 않은 두 회귀는 통과했다. 모든 글자의 세로 잘림이나 모든 버튼의 클릭 성공을 이 두 검사만으로 인증하지 않는다.

최종 사진 상태 수정 후 전체 단위 1,826개, lint(오류 0·기존 경고 33), typecheck, 하네스 계약, 두 의존성 보안 검사, Vercel 빌드와 성능 검사가 통과했다. 사진 전용 상태 회귀는 7개, 모바일 실제 UI의 빠른 사진 성공·빈 응답·오류는 3개 통과했다. CSS gzip은 104.97KiB로 기존 105KiB 한도 안이므로 한도를 바꾸지 않았다. 초기 JS gzip은 랜딩 152.32KiB, Planner 250.14KiB였다.

이 작업은 승인된 디자인을 복원하는 개발 PR이다. [기존 CI 계약](ci-validation.md)의 일반 PR/main 필수 `validate`와 CD, 9월 30일 최종 제출을 위한 Release Audit·접근성 전수 합격을 구분한다. 위 대비 실패가 남아 있으므로 이 기록은 최종 제출 인증이 아니며 전체 자동 감사를 통과했다고 주장하지 않는다. 빠른 CI에 해당 검사를 숨기거나 Release Audit에서 제외하는 변경은 하지 않았다.

## 후속 PR 처리 순서
