# 나루 운영과 품질 확인

나루는 WAVE의 여행 가이드다. 글이나 음성을 문자로 확인해 보내면 무료 자체 운영 모델이 작업 의도를 해석한다. 실제 코스는 관광지 ID·편의 근거·방문 정보·날씨·축제 날짜를 서버가 조회해 구성한다. 모델이 장소·시설·경로를 만들어서 저장하지 않는다.

## 실행 경계

브라우저 → same-origin `/api/assistant` → 인증된 WAVE 게이트웨이 → DSW의 전용 Ollama 순서로 연결한다. `/api/assistant/journey`가 실제 관광 데이터를 확인하고 단계별 진행과 일정안을 전달한다. 브라우저는 사용자가 확인한 변경안만 현재 여행에 반영한다. 같은 날의 이동 구간은 별도 경로 API에서 확인한다.

2026-09-12 구성은 Ollama 0.34.0, Gemma 4 26B Q4_K_M, 8K 문맥, 의도 구조화 온도 0이다. API 요청과 실제 게이트웨이 옵션을 함께 맞췄다. DSW의 A6000 4장 중 WAVE에 지정한 1장만 사용하며 다른 작업을 종료하지 않는다. 모델 상주는 응답 지연을 줄이기 위한 설정이다. 추가 GPU 또는 무료 모델 교체는 같은 평가에서 품질·지연·메모리 병목이 드러난 뒤 판단한다.

- `~/wave-naru` 아래 전용 서비스와 제한된 권한의 환경 파일을 사용한다.
- Ollama와 게이트웨이는 각각 루프백 18764·18765에서 동작한다. Ollama를 공개하지 않는다.
- 공개 연결은 운영자가 소유한 별도 Tailscale 등록과 HTTPS Funnel이다. 타인의 연구실 Tailscale 계정이나 관리자 승인을 사용하지 않는다.
- Vercel 서버 환경의 AI base URL·모델·인증 토큰만 연결한다. 인증 토큰·계정 비밀번호는 코드, 문서, 브라우저 번들에 넣지 않는다.
- 게이트웨이 무인증 요청은 거부한다. 타임아웃·입력 크기·동시 작업 수·속도 제한을 적용하며 질문과 답변을 로그나 DB에 남기지 않는다.
- 모델/게이트웨이 장애는 나루의 재시도와 직접 편집으로 복구한다. 관광 API 실패와 모델 실패를 같은 상태로 설명하지 않는다.

## 같은 여행을 유지하는 규칙

직접 편집과 나루는 같은 날짜·순서·체류·휴식·고정 방문을 사용한다. 변경안 도착 전 사용자가 조건이나 일정을 바꾸면 오래된 안의 적용을 막는다. 적용한 안은 상태가 유지되는 동안 되돌릴 수 있다. 다른 계정 여행을 열 때는 현재 여행을 기기 여행집에 보관하고 새 값을 한 번에 교체한다. 저장 공간이 부족하면 원래 일정을 덮어쓰지 않고 복구 안내를 한다.

필요한 편의는 결과를 늘리려고 자동 해제하지 않는다. 공식 정보에 없는 시설은 미확인, 명시적 부재는 불일치, 조회 실패는 제공처 문제로 구분한다. 실내 대안은 이름만 보고 정하지 않고 공식 소개의 공간 근거를 확인한다. 축제는 실제 개최 기간 안에만 넣으며 기존 여행 날짜를 조용히 바꾸지 않는다.

## 반복 가능한 모델 평가

개발 서버에서 `node scripts/evaluate-naru.mjs`를 실행한다. 특정 범주는 `node scripts/evaluate-naru.mjs wheel,senior,festival`처럼 고를 수 있다. 명시적으로 승인된 배포를 검사하려면 `WAVE_EVAL_BASE`를 지정한다. 실제 LLM·관광 제공처를 호출하므로 일상 단위 검사나 모든 Actions에 넣지 않는다. 입력은 합성 방문자 요청이며 결과는 표준 출력의 JSON으로 남는다. 약 6.2초 간격으로 실행해 서비스 제한을 존중한다.

일반·휠체어·고령자·임산부·영유아·시각·청각·비·축제·다일·수정·삭제·빈 결과·API 오류의 14개 범주와, 실제 일정 적용 뒤 이동수단·날짜·출발시각·휴식·두 번째 장소 삭제의 후속 대화 5개를 비교한다. 의도만 성공했다고 코스 완성을 PASS로 세지 말고 실제 장소·날짜·편의·고정 방문·적용/복원과 경로를 함께 검사한다. 실패 분기의 강제 주입은 별도 E2E에서 한다.

이번 평가에서 조건을 말하지 않았는데 모델이 지역·이동수단·날짜 기본값을 채우는 문제를 발견해 사용자 발화와 현재 상태로 다시 검증했다. 부모님의 보행 부담, 주말·요일 날짜, 축제의 실제 개최일과 기존 일정 대체도 보강했다. 후속 요청은 바꿀 항목만 적용하고 아이 동행·유아 편의 직접 요청을 보존하며, 말하지 않은 피로 사유로 방문을 줄이지 않는다. 실제 의도 응답은 대체로 1초 안팎, 관광 정보 확인은 대체로 수 초였으며 모델·GPU 확대가 필요한 병목은 확인되지 않았다. 제공처 지연이나 미확인 시설은 모델 크기로 해결하지 않는다.

## 나루 동작 추가 절차 (명세 19)

나루의 제안은 `lib/assistant-grounding.js`가 대화 맥락으로 다듬은 뒤
`lib/assistant-actions.js`의 `validateAssistantAction`이 화이트리스트로
**다시 만든다.** 통과하지 못하면 제안 전체를 버린다. 이 구조는 바꾸지
않는다. `ASSISTANT_ACTIONS`·`ASSISTANT_TOOLS`에 새 값을 추가하려면 아래
7개 조건을 모두 만족해야 한다(같은 목록이 `lib/assistant-actions.js` 상단
주석에도 있다).

1. 되돌릴 수 있다.
2. 화면에 이미 있다. 나루만 할 수 있는 일을 만들지 않는다.
3. 매개변수가 닫혀 있다(정해진 목록·숫자 범위·호출자가 보낸 id 목록).
4. 위치가 필요 없다.
5. 바깥으로 나가지 않는다(임의 URL, 외부 요청, 파일 쓰기, 결제, 메시지 전송 금지).
6. `validateAssistantAction`에 분기와 단위 테스트가 함께 추가된다.
7. 검증 실패는 제안 전체를 버리고 대화만 남긴다(부분 적용 없음).

하나라도 만족하지 못하면 화이트리스트에 넣지 않고, 12번 명세의 도움 모음
(`lib/naru-hub.js`, 사용자가 직접 누르는 진입)으로 만든다.

### 이번에 검토한 동작 두 개는 추가하지 않았다

- **편의 조건 바꾸기(`facility-filter`)**: 기존 `settings` 동작이 이미
  충분하다. `validateAssistantAction`의 `settings` 분기는 `profiles`만
  보내도(`region` 없이) 통과하며, `lib/assistant-grounding.js`의
  `groundAssistantProposal`이 발화에서 언급된 시설을
  `resolveFacilityKeys`로 이미 `action.profiles`에 병합한다. 새 동작을
  추가하면 같은 일을 하는 두 번째 경로가 생겨 화이트리스트만 넓어진다.
- **현장 의사소통판 열기(`tool: "communication"`)**: 이 저장소에는 아직
  전용 의사소통판 화면(#528)이 구현돼 있지 않다. 이미 있는 `inquiry`
  도구가 직원에게 보여줄 문의 카드를 큰 글자로 열고 복사까지 지원해
  "현장에서 말이 통하지 않을 때" 요구를 지금 화면 안에서 충족한다. 없는
  화면을 여는 도구 이름을 화이트리스트에 먼저 넣지 않는다. #528이 실제로
  구현되면 그때 이 절차로 다시 판단한다.

## 고른 도움 방식에 맞춘 안내 (명세 42)

나루는 사용자가 **직접 고른** 두 값만 근거로 안내 방식을 바꾼다. 장애 유형을 묻거나 추론해 나누지 않는다.

1. 여행 조건에서 고른 편의 조건(`resolveFacilityKeys`가 처리하는 값)
2. `lib/guidance-preferences.js`의 기존 안내 선호(`briefAnswers`, `oneAtATime`, `textFirst`)

### 반영 규칙

- 안내 선호 `briefAnswers`/`oneAtATime`/`textFirst`는 이미 시스템 프롬프트가 답변 길이·질문 방식·문자 우선 안내로 반영한다(변경 없음).
- 편의 조건에 `route`·`elevator`가 있으면 장소 안내에서 접근로·승강기 정보를 먼저 언급한다.
- 편의 조건에 `audioguide`·`bigprint`가 있으면 음성안내·큰글자안내 정보를 먼저 언급한다.
- 편의 조건에 `signguide`가 있으면 수어안내 정보를 먼저 언급하고, 확인되지 않았으면 `tool:inquiry`(현장 문의 카드)를 안내한다.
- 우선순위만 바꾼다. 사용자가 고르지 않은 시설 정보를 화면이나 답변에서 빼지 않는다. 확인·미확인 표시와 사실은 안내 방식과 무관하게 같다.
- 나루 대화 화면에 `지금 안내 방식` 한 줄을 두어 위 두 값에서 실제로 고른 것만 보여주고, `바꾸기`로 필요한 편의 도구로 보낸다. 추론한 내용은 적지 않는다.
- 읽어주기 버튼은 항상 제공하며(안내 선호와 무관), 자동 재생하지 않고 사용자가 누를 때만 읽는다.

### 하지 않은 것과 이유

- **글자 크기(`큰 글자`) 반영은 이번에 구현하지 않았다.** 이 저장소에는 아직 전역 글자 크기 설정(#552, "글자 크게 보기")이 없고, `guidancePreferences`에도 이를 나타내는 기존 값이 없다. 새 값을 만들면 "새 입력을 요구하지 않는다"는 명세 제약과 #552가 나중에 병합됐을 때 두 배로 커지는 위험을 동시에 만든다. 대신 나루 영역에서 독자적으로 배율을 곱하지 않기로 하고 이 사실을 PR에 남긴다. #552가 구현되면 그 전역 설정을 그대로 읽어 반영하는 것이 다음 작업이다.
- 장애 여부·유형·질병·보조기기 종류를 묻거나 저장하거나 추론하지 않는다. `wheel`·`visual` 같은 legacy 그룹 이름은 편의 묶음의 이름일 뿐이며 사용자 상태를 가리키는 값으로 쓰지 않는다.
- 수어 아바타나 수어 모션을 만들지 않는다. `components/NaruAvatar.tsx`는 이 작업에서 수정하지 않았다.
- 나루 요청 컨텍스트에 새 필드를 추가하지 않았다. 기존 `guidancePreferences`와 `profiles`만 쓴다.

## 실제 데이터 확인 사례

- 진주성 `126833`의 우천 대안: 진주남강유등전시관 `3429810`. 실내 공간 근거와 미확인 휠체어 편의를 함께 표시했다.
- 아라가야문화제 `3377089`: 2026-09-18–20의 실제 행사 기간을 확인하고 함안박물관 `130693` 등 주변 방문과 연결했다.
- 진주성 Odii: 서로 다른 2개 해설·대본을 확인했다. 브라우저에서 첫 음원의 약 145.9초 메타데이터와 재생 시간 증가를 확인했다. 장소 이름만 겹치는 다른 지역 해설은 제외한다.

사례는 2026-09-12의 조회 결과이며 이후 제공처 값의 보증이 아니다. 배포별 최종 증거는 해당 PR과 [제품 검증 기록](product-upgrade-20260912.md)에 연결한다.
