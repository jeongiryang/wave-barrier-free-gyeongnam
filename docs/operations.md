# W.A.V.E 운영·보안·개인정보 안내

이 문서는 현재 저장소에서 확인되는 동작과 운영자가 배포 환경에서 확인해야 할 일을
구분합니다. 코드에 없는 외부 백업·알림 설정은 완료된 것으로 간주하지 않습니다.

## 서비스와 데이터 경계

```text
브라우저
  ├─ W.A.V.E 정적 화면과 Vercel Functions (/api/*)
  ├─ Kakao Maps JavaScript SDK
  └─ 브라우저 localStorage

Vercel Functions
  ├─ 한국관광공사·공공데이터포털·Kakao·ODsay·Open-Meteo
  └─ Neon Postgres와 Neon Auth
```

- 관광·무장애·사진 원본 응답은 요청 시 제공기관에서 조회하고 Neon에 원문 전체를
  복제하지 않습니다.
- 성공한 공개 데이터 응답은 브라우저 5분, 공유 캐시 30분 범위의 캐시 헤더를 사용할
  수 있습니다. 오류 응답은 `no-store`입니다.
- `/api/health`는 배포 환경에 키가 설정됐는지만 반환합니다. 제공기관 호출 성공률,
  Neon 연결 또는 실제 경로 생성 여부를 확인하는 종합 상태 검사는 아닙니다.
- 운영 이벤트는 경로 결과의 수·제공기관 상태와 만료 정리 결과처럼 제한된 필드만
  기록합니다. 필드 이름에 좌표·사용자·이메일·쿠키·토큰·비밀키·비밀번호가 들어가면
  기록에서 제외합니다.

## 저장 항목과 보관

| 위치 | 저장 항목 | 보관·삭제 |
| --- | --- | --- |
| 브라우저 `localStorage` | 테마·언어·동작 설정, 여행 프로필, 저장 장소, 일정, 최대 20개의 여행집 | 사용자가 사이트 데이터나 브라우저 데이터를 지울 때 삭제; 서버 백업 없음 |
| `itineraries` | 공유 ID, 선택 조건, 날짜 배정, 출발지 표시 이름, 공식 장소 식별자 | 생성 30일 뒤 조회 제외; 매일 03:17 UTC 및 새 저장 요청 때 만료 행 삭제 |
| `place_feedback` | 장소 식별자·이름·분류, 로그인 없이 작성한 제보, 상태, 작성 시각 | 코드에 자동 삭제 기간 없음 |
| 커뮤니티 테이블 | Neon Auth 사용자 참조 ID·표시 이름, 게시글·댓글·좋아요·신고·처리 상태 | 코드에 자동 삭제 기간 없음; 작성자 삭제와 운영자 숨김 기능 제공 |
| Neon Auth | 계정 인증 자료 | Neon Auth 정책과 운영 설정을 따름; 커뮤니티 테이블은 이메일·비밀번호를 저장하지 않음 |

사진 코스는 원본 파일을 서버로 보내지 않습니다. 브라우저가 최대 200개 파일의 앞
256 KiB만 순서대로 읽고, 내보내기·공유 자료에서는 좌표를 제거합니다.

현재 위치는 사용자가 위치 버튼을 눌렀을 때만 브라우저 권한을 요청합니다. 선택한
출발·도착 좌표는 지도 표시와 실제 경로 조회에 쓰이며 `/api/route`를 거쳐 연결된
Kakao·ODsay에 전달될 수 있습니다. W.A.V.E 데이터베이스와 운영 이벤트에는 좌표를
저장하지 않습니다. 외부 제공기관의 처리는 각 제공기관 정책의 적용을 받습니다.

## 데이터 신뢰 기준

- 공식 편의정보의 긍정 항목만 사용자가 선택한 조건의 일치율에 반영합니다.
- 공식 편의항목이 하나도 확인되지 않으면 `0%`가 아니라 판단 보류로 표시합니다.
- 실제 경로가 없을 때의 직선 연결은 제공기관 경로와 다른 미리보기로 표시합니다.
- 요금·시간·무료 여부가 없으면 0으로 바꾸지 않습니다.
- 관광 집중률은 예측값이며 실시간 방문자 수로 표시하지 않습니다.
- 여행자 현장 제보는 작성자 한 명의 경험이며 공식 편의점수에 합산하지 않습니다.
- 공유 여행을 열 때 저장된 장소 식별자로 최신 관광정보를 다시 조회합니다. 현재
  확인되지 않는 장소는 제외하거나 같은 조건의 최신 후보임을 알리고 대체합니다.

## 보안 기준

- Vercel 응답에 CSP, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy`와 카메라·마이크 차단 `Permissions-Policy`를 적용합니다.
- 비밀 API 키와 데이터베이스 연결 문자열은 서버 환경 변수에서만 읽습니다. 지도
  표시용 Kakao JavaScript 키만 `/api/map-config`를 통해 브라우저에 전달됩니다.
- JSON 저장 API는 콘텐츠 형식, 본문 크기, 같은 출처 요청과 입력 길이를 확인합니다.
- 익명 공유·제보 쓰기는 저장소 전체의 단기·지속 요청량을 기준으로 `429`를 반환할
  수 있으며 IP와 IP 해시는 저장하지 않습니다.
- 배포 migration과 만료 정리 API는 32자 이상의 Bearer 비밀값을 상수 시간 비교하고,
  production 환경 외부나 인증 실패에는 `404`를 반환합니다.
- 커뮤니티는 서버 세션의 사용자 ID를 사용합니다. 하루 신고 10건 제한, 동일 대상
  중복 신고 방지, 서로 다른 사용자 신고 3건 시 임시 비공개 검토가 적용됩니다.
- 키가 노출되면 제공기관에서 폐기·재발급하고 Vercel 환경 변수를 교체한 뒤 새로
  배포합니다. 노출된 값은 Git 기록이나 이 문서에 적지 않습니다.

## 접근성 기준

- 주요 버튼·링크·입력은 44px 이상 터치 영역과 보이는 키보드 초점을 유지합니다.
- 색만으로 상태를 전달하지 않고 텍스트·기호를 함께 제공합니다.
- 본문은 4.5:1, 큰 글자와 비활성 요소는 3:1 이상의 대비를 기준으로 합니다.
- `prefers-reduced-motion`과 화면 내 동작 감소 설정에서 장식 애니메이션을 줄이거나
  멈춥니다.
- 일정 날짜·순서 편집과 탭 목록은 포인터 없이 조작할 수 있어야 합니다.
- CI의 Playwright·axe 검사는 데스크톱·모바일 Chromium의 주요 여정과 대비·키보드
  흐름을 검사합니다. 이 검사는 모든 보조기기와 외부 지도·예약 사이트를 보증하지 않습니다.

## 배포와 장애 대응

배포 자동화는 다음 순서를 사용합니다.

1. lint, 타입 검사, 로직 검사, Chromium 사용자 여정·접근성 검사, Vercel 빌드를 실행합니다.
2. `main`의 성공한 커밋으로 도메인을 붙이지 않은 production 후보를 만듭니다.
3. 후보의 `/api/health` 응답과 필수 환경 변수를 확인하고 migration을 적용합니다.
4. 후보를 production으로 승격합니다.
5. production `/api/health`가 재시도 뒤에도 실패하면 Vercel rollback을 실행합니다.

장애가 보이면 다음 순서로 범위를 좁힙니다.

1. 배포 커밋, `/api/health` 응답 시각과 누락 키를 확인합니다.
2. 랜딩·플래너·공유 여행·로그인·커뮤니티를 각각 확인해 정적 화면, 제공기관,
   Neon, Neon Auth 장애를 분리합니다.
3. 새 배포와 직접 관련되면 Vercel의 직전 정상 배포로 rollback합니다. migration은
   추가형·반복 실행 가능한 SQL이지만 자동 역방향 migration은 없으므로 데이터베이스를
   임의로 되돌리지 않습니다.
4. 제공기관 장애면 추정값을 실제값처럼 올리지 않았는지 확인하고, 실패 응답이
   `no-store`인지 확인합니다.
5. 공유 저장이 몰린 경우 `Retry-After`가 있는 `429`가 정상 보호 동작인지 확인합니다.
6. 복구 뒤 주요 사용자 여정, 만료 정리와 신고 처리 목록을 확인하고 원인·영향 범위·
   시작과 복구 시각·재발 방지 조치를 운영 기록에 남깁니다.

## 백업과 복구

저장소에는 Neon 백업 보존기간, 복구 시점 목표(RPO), 복구 시간 목표(RTO), 정기 복원
작업이 코드로 정의되어 있지 않습니다. 따라서 아래 항목은 배포 환경의 운영자가
완료하고 증거를 보관해야 합니다.

- [ ] Neon에서 해당 요금제의 point-in-time restore 또는 백업 기능과 실제 보존기간 확인
- [ ] 데이터베이스와 Neon Auth의 책임 경계 및 계정 복구 절차 확인
- [ ] 분리된 복구 환경에서 migration 적용과 표본 데이터 복원 훈련
- [ ] 커뮤니티 글·댓글·신고, 공유 여행, 제보의 복원 결과와 권한 확인
- [ ] RPO·RTO, 복구 승인자, 연락 경로와 마지막 복원 훈련일 기록

브라우저 `localStorage` 자료는 서버에서 복구할 수 없습니다. 공유 여행은 30일짜리
임시 자료이므로 백업 정책을 정할 때 영구 보관 자료와 구분해야 합니다.
