# WAVE 디자인 시스템

2026-09-11 Owner 최종 기준: 소개의 현재 이야기 구조와 8번의 풍경 카드를 유지하고, 10번 Horizon의 글꼴·색상·여백을 모든 화면에 적용한다. 이전 Deep Ocean 팔레트는 이 기준으로 대체된다.

- 글꼴: 자체 제공 Noto Sans KR 가변 폰트. 제목 500–600, 본문 400–500. 폰트 출처와 OFL은 public/fonts/noto-sans-kr/README.md에 기록한다.
- 본문 --ink #2b2632, 보조 --muted #696071, 강조 --blue/--accent #6940a6, 바탕 --surface #f5f4f8, 선 --line #dcd8e4.
- 공통 헤더 WaveHeader: 소개·여행 설계·커뮤니티, 북마크와 저장 개수. 모바일에서도 세 메뉴를 노출한다. 도움말·환경설정·계정은 하단 WaveFooterTools에서 제공한다.
- 사진 장면은 8번처럼 좌우 여백 없이 화면을 채운다. 중앙 텍스트 장면은 10번처럼 76–128px의 여백과 차분한 글자 위계를 쓴다. 사진 위 문구는 스크림과 함께 대비를 확보한다. 지역 카드는 마지막 준비 사진 위에서 등장하고, 충분히 큰 화면에서는 세로 스크롤을 따라 가로로 이동한 뒤 다음 장면으로 이어진다. 카드 전체가 화면에 들어가지 않거나 동작 감소를 선택하면 일반 가로 목록을 쓴다.
- 여행 설계 기본 화면은 첫 카드의 지역·날짜·활동, 다음 카드의 편의, 여행지, 일정 순서다. 데스크톱에는 내 여행 요약을 나란히 두고 작은 화면에서는 접는다. 기존 저장 여행은 보존하며, 전체 보기는 사용자가 직접 선택할 수 있다.
- 로그인·가입은 카드 한 장을 사용한다. 비회원 진입은 보호된 return URL과 별개로 /planner를 연다.
- 마지막 적용층 app/styles/wave-horizon.css. 동작·상태·오류·출처를 유지하며 새 기능도 이 토큰을 공유한다.
- 상세·댓글·지도 도구·내 여행 편집도 같은 토큰을 쓴다. 조작 라벨은 14px 이상, 입력은 16px, 보조 메타데이터는 12px 이상을 기준으로 한다. 고정 제목이 있는 스크롤 패널은 실제 제목 높이를 스크롤 여백에 반영하고, 검색 완료 전에 사용자가 옮긴 초점을 다시 가져오지 않는다.

경남 무장애 관광 플랫폼 WAVE의 화면을 만들 때 따르는 기준입니다.
새 화면이나 컴포넌트를 만들 때는 여기 있는 토큰을 먼저 찾아 쓰고,
없을 때만 새 값을 만들되 이 문서에 함께 추가합니다.

기본 색상·reset·초기 레이아웃은 [`app/globals.css`](../app/globals.css)에 둡니다. 제품 골격은 랜딩, 플래너, 지역 탐색, 테마·일정 foundation으로 나뉘며 도구 위계는 [`planner-workspace.css`](../app/styles/planner-workspace.css)가 담당합니다. 랜딩 motion과 공통 반응형 보정도 별도 layer로 분리합니다. 지도·경로·날씨는 map feature layer에, 상황 대응과 Deep Ocean 보정은 situation/intro/landing/planner/responsive refinement layer에 둡니다. 실제 import 순서가 cascade 계약이며 [`app/layout.tsx`](../app/layout.tsx)와 repository policy test가 이를 고정합니다. 공통 간격·모서리·그림자·모션 토큰은 [`app/styles/design-system.css`](../app/styles/design-system.css), 도움말·모션 감소·터치 영역·안전 영역은 [`app/styles/experience-accessibility.css`](../app/styles/experience-accessibility.css)가 담당합니다.

## 1. 원칙

이 서비스는 "갈 수 있는지"를 확인하러 오는 사람이 씁니다. 그래서 화면의 판단 기준도
보기 좋음보다 **읽히는지**가 먼저입니다.

1. **근거를 가리지 않는다.** 사진 위에 정보를 얹을 때는 항상 스크림을 깐다.
   배경 이미지가 늦게 뜨거나 밝아도 글자가 사라지면 안 된다.
2. **대비는 타협하지 않는다.** 본문·라벨은 배경 대비 4.5:1 이상.
   큰 제목(24px 이상 굵은 글자)과 비활성 요소만 3:1까지 허용한다.
3. **색만으로 상태를 말하지 않는다.** 혼잡도·연결 상태는 색과 함께
   글자나 아이콘으로도 표시한다.
4. **움직임은 끌 수 있어야 한다.** 모든 애니메이션은
   `prefers-reduced-motion: reduce`에서 정지하거나 한 프레임으로 대체된다.
5. **조작 대상은 최소 44px.** 버튼·링크·입력의 터치 영역 기준.

## 2. 색 — Horizon

밝은 라벤더 바탕, 짙은 본문, 보라색 액션을 공유합니다. 기존 컴포넌트 호환을 위해 주요 액션의 토큰 이름 `--blue`를 유지합니다. 사진과 상태색은 실제 내용에 맞게 보존합니다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--ink` | `#2b2632` | 본문, 짙은 액션 배경 |
| `--ink-soft` | `#51475e` | 보조 제목, 라벨 |
| `--blue` / `--accent` | `#6940a6` | 주요 액션, 링크, 강조 |
| `--blue-dark` | `#58348d` | 주요 액션 hover |
| `--sky` | `#efecf5` | 옅은 강조 면 |
| `--paper` / `--surface` | `#f5f4f8` | 모든 페이지가 공유하는 바탕 |
| `--white` | `#ffffff` | 카드 |
| `--line` | `#dcd8e4` | 테두리, 구분선 |
| `--muted` | `#696071` | 보조 설명 |

**상태색은 색상 리매핑에서 제외합니다.** 혼잡도(여유·보통·붐빔·매우 붐빔)와
경고·오류는 초록·앰버·주황·빨강을 그대로 유지해야 의미가 유지됩니다.

다크 테마·영어는 Owner 요청으로 공개 선택을 임시 비활성화합니다. 기존 기능의 후속 개발 검증은 개발용 표시 설정에서만 유지합니다.

이전 `.journey-editorial` / `.planner-reference` 팔레트는 `wave-horizon.css`의 동일 의미 토큰으로 대체합니다. 선택된 면·글자·버튼을 함께 검증합니다. 사용하지 않는 Hero·briefing·보류 소개 장면은 import하지 않습니다.


### 2026-09-10 Owner PDF — 이전 배치의 근거

Owner가 전달한 `WAVE_일정작성_전체보기_통합시안.pdf`에서 단계와 지역 사진 선택을 유지합니다. 나머지 색·검색·기능 패널은 2026-09-11의 10번 시안이 우선합니다. 이전 구현 기록은 [PDF 시안 적용 기록](design/planner-pdf-reference-20260910.md)을 봅니다.

### 색을 고르는 순서

1. 글자면 → `--ink` / `--ink-soft` / `--muted`

5. 위 어디에도 없으면 새로 만들지 말고 가장 가까운 토큰을 쓴다.

## 3. 간격

8px 배수를 기본으로 하되, 화면 폭에 따라 줄어드는 자리는 `clamp()`를 씁니다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--s-1` | `4px` | 아이콘과 글자 사이 |
| `--s-2` | `8px` | 칩 안쪽, 인접한 작은 요소 |
| `--s-3` | `12px` | 폼 항목 사이 |
| `--s-4` | `16px` | 카드 안 블록 사이 |
| `--s-5` | `24px` | 카드 안쪽 여백(좁은 화면) |
| `--s-6` | `32px` | 카드 안쪽 여백(기본) |
| `--s-7` | `48px` | 구역 안 큰 묶음 사이 |
| `--s-8` | `72px` | 구역과 구역 사이 |
| `--gutter` | `clamp(18px, 4vw, 48px)` | 화면 좌우 여백 |

**정렬선**: 모든 구역은 `max(var(--gutter), calc((100vw - 1240px) / 2))`를 좌우
패딩으로 써서 세로 정렬선을 공유합니다. 플래너의 기능 카드만 1560px 기준을 씁니다.

## 6. 컴포넌트 패턴

### 기능 구역 카드 (`.planner-page > section`)
플래너는 기능 단위로 구역을 끊습니다. 각 구역은 독립된 카드입니다.

```
width: min(1560px, calc(100vw - var(--gutter) * 2));
padding: clamp(26px, 3.2vw, 52px) clamp(20px, 2.8vw, 46px);
border: 1px solid var(--line);
border-radius: var(--r-xl);
background: var(--white);
box-shadow: var(--shadow-2);
```

**짙은 카드**(`--ink` 배경)는 결과·탐색처럼 흐름의 매듭에만 씁니다.
현재는 `데이터 탐색`과 `내 W.A.V.E 코스` 두 곳입니다.
밝은 카드로 바꿀 때는 반드시 안쪽 글자색도 함께 바꿔야 합니다.
(과거에 배경만 바꿔 흰 글자가 흰 배경 위에 남은 사고가 있었습니다.)

### 랜딩 구역
랜딩은 반대로 **배경을 나누지 않습니다.** 전 구역이 `--surface` 하나를 공유하고,
구분은 여백과 타이포 위계로만 만듭니다.

### 이미지 위 정보
사진 위에 글자를 얹으면 반드시 스크림을 깝니다.

```
background: linear-gradient(180deg, transparent 30%, rgba(4,32,47,.34) 62%, rgba(4,32,47,.68));
```

### 칩 / 배지
알약형(`--r-full`), 최소 높이 32px, 테두리 `--line`, 배경 `--white`.
접근성 편의 항목은 앞에 `✓`를 붙여 색 없이도 의미가 전달되게 합니다.

### 버튼
- 주요: 배경 `--blue`, 글자 흰색, `--r-md`, 최소 높이 48px
- 보조: 테두리 `--line`, 글자 `--ink-soft`, 배경 투명
- 파괴적 동작은 이 서비스에 없습니다.

첫 화면의 파동은 장식이며 본문·CTA를 가리거나 사용자 조작을 요구하지 않습니다.

## 8-1. 운영 화면 적용 규격

Apple 참고 문서는 콘텐츠 우선·명확한 타이포 위계·절제된 장식·선택 상태의 중복 표현만
채택합니다. Apple 웹의 SF Pro, 파란색, 36px 버튼, 980px 알약 모서리와 HIG 문서 카드
수치는 W.A.V.E 토큰이 아니며 복사하지 않습니다. W.A.V.E는 아래 값을 실제 변경 화면의
계약으로 사용합니다.

| 역할 | 확정 규격 | 모바일·PC 차이 |
| --- | --- | --- |
| 페이지 배경·표면 | `--surface` / `--white`; 중첩 카드가 아니면 그림자 없음 | 동일 |
| 본문·보조 문구 | `--ink` / `--muted`; 본문 행간 1.65 | 320px에서도 16px 미만으로 축소하지 않음 |
| 소개 제목 | `clamp(3rem, 4.8vw, 5.4rem)`, 행간 1.08, 한글 자간 `-.045em` | 620px 이하에서 기존 반응형 상한 적용 |
| 실제 플래너 제목 | `clamp(1.65rem, 3vw, 2.6rem)`, 행간 1.2 이상 | 질문과 입력을 한 열로 표시 |
| 주요 행동 | `--blue`, 흰 글자, 최소 48px | 고정 CTA는 safe-area와 콘텐츠 가림 검사 |
| 보조 행동 | 흰 배경, `--line` 테두리, `--ink-soft` | 최소 조작 영역 44px 유지 |
| 선택 | `aria-pressed/current` + 채움색 + 체크 또는 선택 문구 | hover 없이도 동일한 의미 |
| 포커스 | 3px 고대비 outline, 3px offset | 키보드·스위치 입력 동일 |
| 로딩·비활성 | 동작형 문구와 `aria-live`; 비활성은 이유를 인접 문구로 표시 | 모바일에서도 문구 생략 금지 |
| 오류 | 문제·보존된 값·다음 행동을 함께 표시 | 긴 문구 줄바꿈 허용 |
| 모션 | 정보 이해에 필요한 전환만 유지 | `prefers-reduced-motion`에서 정지·즉시 전환 |

반투명은 스크롤된 최상단 내비게이션에도 사용하지 않고 불투명 표면을 기본으로 합니다.
지도·사진·카드에는 유리 효과를 적용하지 않습니다. 현재 글꼴 스택은 라이선스가 있는
로컬 Pretendard가 없을 때 운영체제 한글 글꼴로 즉시 대체되며 SF Pro를 배포 자산으로
추가하지 않습니다.

## 10. 성능 기준

문자 하프톤 파도는 화면당 셀이 2만 개를 넘습니다. 셀마다 캔버스 명령을 부르면
프레임당 55ms가 나와 20fps로 떨어집니다. 그래서:

- 밝기 단계별 문자를 **배경까지 합성한 픽셀 배열**로 미리 만들어 두고
- 프레임마다 프레임 버퍼에 복사한 뒤 `putImageData`를 **한 번만** 호출합니다
- 사인은 4096칸 룩업 테이블로 대체하고, 행에만 의존하는 값은 열 루프 밖으로 뺍니다

현재 프레임당 6.4ms, 1440×900·1920×1080·960×1040 모두 60fps입니다.
