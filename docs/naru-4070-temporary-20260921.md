# 나루 임시 4070 Ti 실행 검증 — 2026-09-21

## 상태

로컬 모델 실행 및 제한된 합성 기능 검증 완료. **운영 연결·이전 완료가 아니다.**
기존 DSW GPU 반환 상태는 유지한다. 교수님 TITAN RTX 본체의 네트워크 문제는 별도로 해결한다.

## 장비 및 실행기

- 현재 Windows PC: RTX 4070 Ti 12,282 MiB, 시스템 RAM 약 64GB.
- Ollama 0.34.2 공식 Windows ZIP SHA-256 검증 후 사용자 디렉터리에 배치.
- 모델: `gemma4:12b`, Q4_K_M, digest `4eb23ef187e2c5462566d6a1d3bbbc2f1346d0b4327cbb66d58fffbcc9b2b05c`.
- 실행 폴더: `%LOCALAPPDATA%\WAVE\naru-runtime`.
- 루프백 API `127.0.0.1:18764`; 8K 문맥, 동시 추론 1, 클라우드 사용 비활성.
- 자동 시작은 아직 구성하지 않았다. 현재 실행 프로세스가 종료되거나 PC가 재시작되면 자동 복구되지 않는다.
- 모델 49/49 레이어 GPU 적재, 모델과 캐시 보고 사용량 약 8.37GB. 화면 프로그램 포함 전체 VRAM 사용량 약 10.8~11.2GB. 여유가 크지 않으므로 다른 GPU 작업과 동시 사용 검증 필요.

## 확인한 결과와 한계

- 첫 콜드 요청: 약 100초(모델 로드 약 54초 포함). 운영 요청 전에 예열 필수.
- 예열 후 별도 일반 질문: 100 출력 토큰 약 2.4초. 이 요청은 의도적으로 짧은 토큰 한도로 잘렸으며 완성 답변 품질 검증으로 세지 않는다.
- `scripts/verify-naru-local-model.mjs`는 실제 서비스 시스템 프롬프트·입력 검증·응답 검증을 사용하되, 제공처 전송만 루프백 Ollama에 직접 연결한다. 실제 게이트웨이 인증·배포 요청·브라우저 버튼 동작 검증이 아니다.
- 합성 사례 8개: 조건 설정, 일정 생성, 체류 시간, 되돌리기, 일정 점검, 장소 삭제, 큰 글자 문의 도구, 사진 일정 정보. 최종 실행에서 8개 통과.
- 최종 텍스트 사례 약 0.87~1.64초, 사진 3.77초. 작은 합성 표본이며 기존 26B와 동등한 품질·동시 사용자 성능을 보장하지 않는다.
- 장소 ID 1001/1002와 합성 포스터는 테스트 입력이다. 공식 관광 API 조회나 운영 데이터로 해석하지 않는다.
- 기존 나루 관련 Node 테스트 211개 통과. Python 게이트웨이 회귀 검사도 해당 실행에 포함된다.

## 발견 및 수정

1. 사진 JSON 스키마가 `facts`를 금지해 앱의 사진→일정 정보 경로에 전달할 수 없었다. 장소·지역·날짜·시작/종료·주소 최대 4개를 허용하고 `proposal:null`을 유지했다.
2. 실제 12B가 체류 시간 요청의 `minutes`를 누락해 앱 검증에서 503이 발생했다. visit/break 생성 스키마에 장소 ID와 분을 필수화했다. 앱의 장소/범위 검증은 유지한다.

## 운영 연결 전 남은 작업

- Tailscale 자동 설치 명령이 도구의 자동 승인 검토에서 정책상 거절됨. 구체적인 사유 없음. 사용자에게 현재 Windows PC에서 공식 설치·기존 본인 계정 로그인을 요청함.
- 비밀 토큰 생성·ACL 설정·로컬 인증 게이트웨이 실행을 묶은 명령도 같은 정책상 거절됨. 실행되지 않았으며 인증 게이트웨이는 아직 켜지지 않았다. 거절된 작업을 우회 실행하지 않음.
- 인증 게이트웨이, 인증 없는 요청 거부, 공개 HTTPS 접근, 재시작/예열을 검증해야 한다.
- 운영 환경 설정 변경은 아직 하지 않았다. Production 나루 복구를 주장하지 않는다.
- 운영 연결 후 기능설명서 기준 실제 여행 생성·편의 유지·시간 변경·사진 정보·도구·되돌리기·실패 복구를 브라우저로 확인해야 한다.
- 현재 변경은 독립 작업 브랜치에 있으며 병합·배포되지 않았다.

비밀키·인증 토큰·사용자 대화·환경 파일은 저장소나 검증 결과에 기록하지 않는다. 모델 검증 스크립트는 합성 입력 전용이다.


## 2026-09-22: TITAN RTX 주 서버와 4070 Ti 예비 서버 전환 작업

- 사용자가 두 장비의 Tailscale 설치/본인 계정 로그인을 완료했다. Windows에서 교수님 Mint 본체로 SSH 공개키 접속 검증 완료. 접속 개인키는 사용자 `.ssh`에만 있으며 문서나 Git에 포함하지 않는다. 사용자 대신 sudo를 실행할 권한은 아직 확인되지 않았다.
- Mint 본체: TITAN RTX 24GB, LM Studio의 Gemma 4 26B A4B Q4_K_M. Tailscale 중계 연결 확인. 현재 GPU 약 19.7GB 사용. 기존 DSW GPU는 재점유하지 않았다.
- 사용자 서비스 `wave-naru-gateway.service` 설치·시작. loopback 18765에서만 수신. 별도 비밀 설정은 Mint의 `~/wave-naru/gateway.env` 권한 600으로 보관. 비인증 health 401, 인증 health 200/ready=true, 인증된 합성 일정 점검 요청 200/1.58초 확인.
- LM Studio 어댑터는 이미지 배열을 image_url 입력으로 변환하고, loaded_instances로 실제 적재 상태를 확인한다. 구조화 출력 스키마와 길이 제한을 보존한다. `reasoning` 필드는 효과가 없어 초기 8개 중 4개가 출력 한도로 실패했다. `reasoning_effort:none`으로 수정한 뒤 실제 나루 프롬프트와 검증기를 통과한 합성 사례 8개가 모두 성공했다. 텍스트 0.83~3.88초, 사진 4.76초. 출력 검증은 변경 제안 수준이며 브라우저 실제 적용 검증이 아니다.
- 애플리케이션의 선택적 예비 연결 변수: `WAVE_AI_FALLBACK_BASE_URL`, `WAVE_AI_FALLBACK_MODEL`, `WAVE_AI_FALLBACK_TOKEN`. 운영자 설정만 사용. 주 서버 정상 시 예비를 호출하지 않으며 주 서버 준비 실패·추론 통신 실패/시간 초과/혼잡 시 한 번만 예비 호출. 주 서버 응답을 외부에 전달한 이후에는 전환하지 않아 두 답변을 섞지 않는다. 인증 오류나 잘못된 동작 제안은 전환으로 숨기지 않는다. 취소 신호와 전체 45초 제한 유지. 주 서버 최초 응답 대기는 예비 구성 시 최대 15초, health는 3초.
- 전체 자동 테스트 1,635개 및 Python 게이트웨이 검사 7개 통과. 타입 검사·빌드 통과, lint 오류 0개/기존 경고 25개.
- 로컬 SSH 검증 터널 및 인증 설정의 Windows 보호 폴더 복사를 묶은 명령이 자동 승인 검토에서 `blocked by policy`로 거절되어 실행되지 않았다. 이를 우회하지 않았으며, 사용자가 요청한 Gmail 내게쓰기로 직접 실행할 명령을 보냈다. 메일에 비밀값은 포함하지 않았다.

## 2026-09-22 오후: 인증 HTTPS 및 실제 장애 전환 검증

위의 설치·접속 차단 기록은 당시 상태이며 다음 단계에서 해소됐다.
- 사용자가 Gmail로 전달한 비밀 설정 복사와 Mint HTTPS 권한 명령을 실행했다. SSH 관리와 두 장비의 Tailscale Funnel HTTPS 연결을 검증했다. 토큰은 각 장비 전용 환경 파일과 Vercel Secret에만 저장한다. 원시 LM Studio/Ollama 포트는 공개 Funnel로 노출하지 않는다.
- 주 서버 HTTPS: 합성 8개 모두 통과, 텍스트 0.80~1.55초, 사진 4.07초. 예비 HTTPS: 합성 8개 모두 통과, 첫 텍스트 7.30초/이후 0.81~1.33초, 사진 3.86초.
- Mint 게이트웨이를 실제로 중지한 상태에서 앱 핸들러가 예비 4070 Ti로 체류 시간 변경을 수행했다(200, 1.74초). finally에서 Mint 서비스를 재시작했고 active를 확인했다. 합성 테스트이며 실제 브라우저 적용 완료를 의미하지 않는다.
- Windows 전용 supervisor는 기존 프로세스를 죽이지 않고 loopback 상태를 확인해 종료된 전용 런타임만 복구하고 모델을 예열한다. 사용자 시작프로그램 바로가기로 로그인 후 실행한다. 예약 작업 방식은 실행 오류로 제거했으며 재부팅 검증은 하지 않았다. 실행 중 시스템 절전만 방지하고 화면 절전은 허용한다.
- 운영 Secret에 주/예비 모델 설정 6개를 저장했다. 기존 Secret은 Vercel에서 재다운로드할 수 없으므로 로컬 pull 결과를 실제 복구용 비밀값으로 취급하지 않는다. 구 DSW GPU를 다시 사용하지 않는다.
- 남은 배포 검증: PR 전체 CI, GitHub Actions CD, Production 브라우저 여정. Mint는 현재 사용자 gateway 서비스와 LM Studio가 실행 중이지만 로그아웃/재부팅 후 모델 자동 복구는 아직 보장하지 않는다. 양쪽 PC의 전원·네트워크·로그인 세션 유지가 필요하다.
