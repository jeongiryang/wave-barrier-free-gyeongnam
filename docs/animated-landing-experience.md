# 여행 장면이 이어지는 W.A.V.E 메인화면 제안

- 관련 이슈: #340
- 날짜 데이터 수정: #339
- 동작 시안: https://wave-gyeongnam-journey.tlswlsgk7174.chatgpt.site
- 인터랙션 참고: https://www.hanwhaocean.com/

## 목표

사용자가 메인화면을 내리는 동안 경남 여행 장면을 계속 마주하고 필요한 편의와 일정을 부담 없이 선택하게 한다

PDF 시안의 청록, 민트, 짙은 남색 색감을 유지하면서 큰 관광 사진, 짧은 문장, 충분한 글자 크기와 명확한 조작 요소를 사용한다

한화오션 사이트에서는 스크롤에 따라 장면이 이어지는 방식만 참고한다. 코드, 이미지, 문구, 고유한 화면 구성은 복제하지 않는다

## 사용자 의견 반영

| 기존 인상 또는 문제 | 반영 기준 |
| --- | --- |
| 문장마다 마침표가 있어 정적이고 단호함 | 제목, 버튼, 짧은 안내에서는 마침표를 생략하고 긴 설명에만 필요한 문장부호를 사용 |
| 텍스트 중심이라 여행이 떠오르지 않음 | 지역 섹션마다 실제 관광 사진을 크게 배치하고 지역 전환에도 사진을 유지 |
| `먼저`가 조건이나 과제처럼 느껴짐 | 행동 순서를 강요하지 않는 문구로 변경 |
| `고르면 바로 이렇게 짜집니다`가 부담스러움 | `선택한 조건으로 여행 일정을 한눈에 확인해요`처럼 결과 중심으로 안내 |
| 전체 폰트가 작음 | 본문은 최소 16px, 핵심 설명은 18px 이상을 기본으로 검토 |
| 날짜 변경 후 기존 일정 상태가 불명확함 | 새 기간 밖의 일정과 선택 가능한 처리 방법을 변경 전에 명시 |

## 전체 화면 흐름

### 1. 여행을 시작하는 첫 화면

- 짙은 남색 스크림을 적용한 경남 관광 사진
- `모두가 편안한 경남 여행`처럼 짧고 부드러운 제목
- `여행 계획 만들기`, `지역 둘러보기` CTA
- 현재 여행 계획이 있으면 지역과 날짜를 작은 고정 요약으로 표시

### 2. 이어지는 지역 장면

창원, 통영, 거제를 기본 대표 장면으로 보여 주고 이후 18개 시군 탐색으로 연결한다

- 장면당 지역명, 한 줄 이야기, 접근성 정보 확인 CTA 제공
- 스크롤 진입 시 사진과 문구를 부드럽게 전환
- 일정 시간마다 다음 지역을 보여 주는 자동 전환 제공
- 사용자가 직접 넘기거나 포커스를 이동하면 자동 전환을 잠시 멈춤
- 정지와 재생 버튼을 항상 제공하고 상태를 텍스트로 알림
- 지역 선택 결과는 기존 지역 지도와 여행 계획 화면으로 연결

### 3. 편의 조건과 빠른 일정 만들기

- 휠체어 접근, 무장애 화장실, 엘리베이터, 유아 동반 등 조건을 큰 칩으로 제공
- 지역, 날짜, 필요한 편의를 같은 영역에서 확인
- 선택 결과를 고정 여행 요약에 즉시 반영
- 다음 단계가 필수인 것처럼 보이는 `먼저` 표현을 사용하지 않음

### 4. 날짜 변경 안내

#### 기간을 넓힐 때

9월 7일~9월 8일 계획을 9월 6일~9월 9일로 바꾸면 기존 일정은 그대로 유지한다

#### 기간을 줄일 때

기존 일정이 새 범위를 벗어나면 저장 전에 아래 정보를 보여 준다

- 범위를 벗어난 날짜와 장소
- 새 기간 안으로 옮기기
- 일정에서 제거하기
- 날짜 변경 취소하기

사용자가 선택하기 전에는 기존 일정을 자동으로 삭제하거나 숨기지 않는다

날짜 데이터의 저장과 복원 오류 자체는 #339에서 처리하고 이 제안은 사용자가 결과를 이해하고 선택하는 안내 UI를 다룬다

### 5. 마지막 CTA와 신뢰 정보

- 출처, 최신 확인일, 다시 확인할 정보를 구분
- `내 조건으로 경남 여행 만들기` CTA
- 관광 정보는 출발 전에 다시 확인하도록 짧게 안내

## 색과 타이포그래피

- 핵심 색상: 청록, 민트, 짙은 남색, 밝은 종이색
- 사진 위에는 방향성 스크림을 적용해 텍스트 대비 4.5:1 이상 확보
- 본문 최소 16px, 핵심 설명 18px 이상, 버튼 최소 높이 44px
- 긴 문장을 한 줄에 몰지 않고 모바일에서는 문구와 조작 요소를 세로로 배치
- 기존 `docs/design-system.md`의 토큰을 우선 사용하고 새 토큰이 필요하면 문서와 함께 갱신

## 모션과 접근성

- 모션은 정보의 순서와 지역 변화를 설명할 때만 사용
- 자동 전환은 일시정지할 수 있어야 함
- 키보드 포커스가 장면 밖으로 이동하지 않도록 일반 문서 흐름을 유지
- 상태 변화는 색뿐 아니라 지역명과 `재생`, `일시정지` 텍스트로 전달
- `prefers-reduced-motion: reduce` 또는 서비스의 차분한 모션 설정에서는 자동 전환, 시차 이동, 큰 확대 효과를 중지
- 화면 낭독기용 현재 지역 상태는 `aria-live="polite"`로 과도하지 않게 알림

## 구현 단위

저장소의 작업 단위 하나당 PR 하나 원칙에 따라 아래처럼 분리한다

1. 대표 지역 스크롤 장면과 정지 가능한 자동 전환
2. 문구 톤과 기본 글자 크기 조정
3. 여행 요약과 빠른 조건 선택
4. 날짜 축소 시 범위 밖 일정 확인 대화상자
5. 반응형, 모션 감소, 대비 E2E 검증

각 구현 PR은 최신 `main` 또는 필요한 선행 PR이 병합된 `main`에서 시작한다. 현재 열린 랜딩 관련 PR과 동일 파일을 수정할 경우 선행 PR 병합 뒤 진행한다

## 검수 기준

- 1440px, 960px, 모바일 폭에서 핵심 문구와 CTA가 잘리지 않음
- 관광 사진이 실패해도 제목과 CTA를 사용할 수 있는 대체 배경이 유지됨
- 자동 전환을 키보드와 터치로 정지하고 다시 시작할 수 있음
- 모션 감소 설정에서 자동 전환과 시차 효과가 중단됨
- 사진 위 텍스트 대비와 포커스 표시가 WCAG AA 수준을 충족
- 불필요한 마침표와 `먼저` 표현이 제거됨
- 날짜 확장 시 기존 일정이 유지됨
- 날짜 축소 시 범위 밖 일정을 명시하고 사용자가 처리 방법을 선택함
- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build:vercel`을 모두 통과
