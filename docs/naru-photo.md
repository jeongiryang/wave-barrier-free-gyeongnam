# 나루 사진 질문

나루 대화 아래 **사진 첨부**에서 JPG·PNG·WebP 한 장을 고른다. 미리보기에서 사진을 바꾸거나 삭제할 수 있다. “이 안내문의 운영시간을 읽어줘”, “축제 장소와 날짜를 읽어줘”처럼 질문하고 보내기를 누른다. 사진만 보내도 장소·날짜·시간 읽기를 요청한다.

읽은 내용은 확인용 답변이다. 날짜나 장소가 맞는지 확인한 다음 **읽은 내용으로 요청 작성**으로 입력창에 옮겨 필요한 부분을 수정하고 보내면 여행 요청으로 이어진다. 사진을 읽는 동안 기존 일정은 바뀌지 않는다. 연결 실패나 중단 시 사진은 입력창에 남아 다시 보낼 수 있다.

원본은 12MB 이하, 해상도 4천만 화소 이하로 제한한다. 브라우저에서 긴 변 1600px 이하 JPEG로 다시 만들고 EXIF·ICC·주석 메타데이터를 제거한 후 최대 800KB만 보낸다. 원본 파일명과 GPS 정보는 요청에 넣지 않는다. 사진은 WAVE 서버를 거쳐 DSW의 무료 로컬 모델에서 처리하며 파일·DB·로그에 저장하지 않는다. AI 경로에 프롬프트나 본문 로깅을 추가하지 않는다.

사진 속 명령은 실행 지시가 아니다. 사진 요청은 별도 읽기 프롬프트와 JSON 스키마로 처리하고, 서버는 모델이 작업을 반환해도 proposal을 null로 고정한다. 이후 일반 대화에 사진·사진 분석 답변을 자동 재전송하지 않는다. 사용자가 확인하고 편집한 요청만 다음 대화에 사용한다. 사진만 보고 접근 가능 여부·안전·장애나 신원을 판정하지 않는다. 흐리거나 잘린 글자는 미확인으로 안내한다.

텍스트 모델과 같은 gemma4:26b의 비전 기능을 사용한다. [Ollama 모델 목록](https://ollama.com/library/gemma4/tags)과 [이미지 입력 방식](https://docs.ollama.com/capabilities/vision)을 확인했다. 모델 기능 지원과 실제 DSW 인식 품질은 구별하며, 실제 포스터 인식 결과와 시간은 배포 검증 기록에 남긴다.

검증: `tests/assistant-photo.test.mjs`, `tests/planner-assistant.test.mjs`는 허용 크기·메타데이터·동일 출처·이미지 유래 작업 차단을 합성 입력으로 검증한다. `server/assistant/test-photo-gateway.py`는 게이트웨이의 독립 검증이며 실제 모델을 호출하지 않는다. `e2e/naru-photo.spec.ts`는 브라우저 재인코딩, 미리보기, 재시도, 확인 후 요청 작성과 접근성을 합성 모델 응답으로 검증한다.

2026-09-14 실제 모델 검증: 로컬 웹 API → SSH 포워딩 → DSW 게이트웨이 → gemma4:26b에서 생성한 한국어 시험 포스터를 6.4초에 읽었다. ‘통영 바다 음악회’, ‘2026-10-17’, ‘14–17시’, ‘통영시 강구안’, ‘무료’를 인식했고 HTTP 200, source `local-vision`, proposal null을 확인했다. 이는 선명한 시험 포스터 한 장의 결과이며 모든 현장 사진의 인식 정확도나 Production 경로 완료를 의미하지 않는다. 독립 브라우저 검증에서 사진 관련 두 시나리오를 데스크톱·모바일 4회 실행해 모두 통과했다.
