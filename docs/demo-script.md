# WAVE 여행 설계 시연

## API 값을 만들지 않는 시연 화면

`/demo`에서는 다섯 가지 방문 일정 예시를 골라 체류 시간, 휴식, 날짜, 순서, 시작 시각을 바꾸고 직전 변경을 되돌릴 수 있다. 고정 방문 예시는 **이동시간을 제외한 최소 시간**만 비교한다. 방문지 A~D는 실제 장소가 아닌 사용자의 일정 자리이며, 시설·운영시간·날씨·축제·교통 정보와 공식 장소 ID를 포함하지 않는다. 체크리스트는 사용자가 확인할 일을 표시할 뿐 제공처의 확인 완료 상태가 아니다. 현장 문의 카드에도 답변을 미리 채우지 않는다.

시연 저장·복원은 `wave-demo-plan-v1` 브라우저 저장 키만 사용하며 실제 여행집·계정·공개 링크에 반영되지 않는다. JSON 내보내기는 `WAVE_DEMO_ONLY` 표식을 포함한다. 실제 관광지·축제·편의·경로·나루 장소 제안은 각 기능의 제공처 조회 결과로 확인한다. 커뮤니티의 `[시연]` 게시글 배치는 [별도 운영 절차](community-demo-data.md)를 따른다.

현재 제품의 핵심 흐름은 직접 선택과 나루 대화를 같은 일정으로 이어가는 것이다. 공개 주소는 https://wave-barrier-free-gyeongnam.vercel.app 이다. 이전 배포의 시연 기록은 [Git 이력의 문서](https://github.com/jeongiryang/wave-barrier-free-gyeongnam/blob/7ecb1eaccc619b1df10e050305cc6c1842b8f3bb/docs/demo-script.md)에 보존한다.

## 처음 방문한 사용자

1. 서비스 소개에서 설명 옆의 풍경 사진과 지역 격자를 본다. 지역 사진을 누르면 해당 지역 여행지가 열린다. 소개의 일정·나루 예시는 실조회로 표시하지 않는다.
2. 여행 설계의 ‘여행지 찾기’에서 지역을 고른다. 검색은 바로 시작하며 날짜와 편의·활동을 강제하지 않는다. 필요한 경우에만 ‘필요한 편의’를 열어 개별 시설을 적용한다.
3. 사진이나 장소 이름으로 상세를 확인한다. 필수 시설의 확인·미확인·명시적 부재·제공처 오류를 구분한다. 선택한 시설을 자동으로 풀지 않는지 확인한다.
4. 장소를 담아도 검색 화면을 유지한다. ‘내 일정’에서 날짜와 이동수단을 정하고 시간표를 만든다. PC는 시간표와 지도, 모바일은 시간표/지도 전환으로 본다.
5. 장소의 ‘수정’에서 날짜·체류·휴식·고정 방문을 정하고 적용한다. 취소는 원래 값을 유지하며, 적용 뒤에는 되돌릴 수 있다. 장소의 지도 버튼과 핀으로 같은 이동 구간을 확인한다.
6. ‘내 여행에 저장’을 누른 뒤 수정하고 같은 저장 항목이 갱신되는지 확인한다. ‘공유’에서 카카오톡·링크·파일·달력을 선택한다. 새 공개 링크는 동일 주소에 수정 내용이 반영되며 ‘공유 종료’ 뒤에는 열리지 않는다.
7. ‘출발 전 확인’과 ‘여행 도구’는 필요한 경우에만 펼친다. 새로고침해 날짜·순서·이동수단·수정 값이 유지되는지 확인한다.

## 나루 시연 A–E

| 시연 | 입력·동작 | 확인할 결과 |
| --- | --- | --- |
| A | ‘비 오는 날 휠체어로 갈 수 있는 경남 여행 코스 만들어줘.’ | 실제 장소 검색→편의·날씨→일정안→적용→날짜별 지도와 경로. 미확인 시설은 적용 전 보인다. |
| B | ‘부모님이 오래 걷기 힘들어. 창원에서 출발해서 당일치기로 여행하고 싶어.’ | 창원 공개 거점, 짧은 방문 수와 방문 사이 휴식, 실제 이동/도보 근거. 거리 추정은 실제 경로와 구분한다. |
| C | ‘아이와 갈 건데 축제도 하나 넣어줘.’ | 실제 개최 기간과 아이 동행 조건, 주변 장소. 현재 날짜에 없으면 없다고 말하고 새 날짜안은 적용 전 확인한다. |
| D | 장소 하나 삭제 후 ‘주변 대체 장소를 찾아줘.’ | 남은 일정 유지→실제 대안→적용→순서에 맞춘 경로·시간 재계산. 고정한 방문은 삭제되지 않는다. |
| E | 야외 방문이 있는 일정에서 ‘비가 온대. 실내 장소로 바꿔줘.’ | 변경 이유와 공식 실내 근거, 교체할 장소, 고정 방문 보존, 되돌리기. 이미 실내라면 불필요하게 교체하지 않는다. |

대화창을 닫았다 다시 열어 작업 진행과 결과가 유지되는지 확인한다. 음성 입력은 인식한 문장을 확인한 후 전송하며 문자 입력으로도 같은 작업을 할 수 있다. 나루에게 필요한 작업을 요청하면 관련 일정·지도·공유 도구를 대화 안에서 열 수 있다. 명확한 체류·휴식·순서 변경은 적용 뒤 되돌리기를 제공하며, 새 장소나 전체 일정 제안은 승인하기 전까지 원래 일정을 바꾸지 않는다. 마이크는 실제 입력 음량과 인식 문장을 보여주고, 취소·닫기·다른 화면 이동 때 장치 사용을 해제한다.

## 수동 완성과 재접속 F–G

F는 AI를 열지 않고 위 처음 방문 동선을 끝까지 수행한다. G는 로그인 후 나의 여행 홈에서 닉네임·현재 여행·계정 여행을 확인하고 이어서 편집한다. 계정 여행을 여는 동안 내용을 수정하면 이전 값으로 이동하지 않아야 한다. 재로그인이 필요해도 작성 중인 내용을 같은 계정으로 복구해야 한다.

## 환경과 결과의 구분

- 1440px·960px·390px, 키보드, 동작 감소에서 핵심 경로를 확인한다.
- 강제로 만든 네트워크·저장 실패와 합성 로그인은 E2E 결과로 기록한다. 실제 LLM·관광·음원·Production 결과와 섞지 않는다.
- ODsay의 기존 제공처 제한은 별도 운영 상태다. 성공 화면을 만들려고 반복 호출하지 않는다. 자동차 경로와 미확인 교통 구간을 분명히 구분한다.
- 2026-09-12 실조회에서 무장애 정보 제공처가 HTTP 429를 반환한 경우도 있었다. 조회 실패를 시설 부재로 바꾸지 않으며, 이미 만든 일정과 다른 관광 정보를 계속 사용할 수 있어야 한다.
- 배포 SHA, 시각, 입력, 실제 장소 ID, 결과와 한계를 함께 기록한다. [고도화 기록](product-upgrade-20260912.md), [나루 운영](naru-service.md), 해당 배포 PR에 최종 증거를 연결한다.
