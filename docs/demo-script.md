# W.A.V.E 3분 시연 동선

심사·리뷰 환경에서 로그인 없이 필요한 편의를 고르고, 공식 근거를 확인한 뒤
일정과 출발 전 확인으로 이어지는 핵심 여정을 보여주는 동선입니다.
Production 기준 주소는 `https://wave-barrier-free-gyeongnam.vercel.app`입니다.

이 동선과 캡처는 **#353 적용 후 Production에서 최종 확인할 예정**입니다.
기존 `34e6021` 검토 PDF를 최신 서비스 화면으로 사용하지 않습니다.
[제출 원고와 최종 캡처 목록](submission/development-entry-draft.md)을 함께 관리합니다.

## 시연 전 30초 점검

1. `/api/health`의 확인 시각과 설정 상태를 봅니다. 키 설정 확인은 외부 제공처의 실제 응답 성공을 보증하지 않습니다.
2. 브라우저 확대 100%, 화면 크기 1366×768 또는 모바일 390×844를 사용합니다.
3. 개인 계정과 현재 위치를 사용하지 않고 `창원중앙역` 같은 공개 출발 거점을 선택합니다.
4. 여행 설계·지도·일정·기기 저장·공유와 공개 후기 읽기는 로그인 없이 이용합니다. 후기 작성은 이 기본 시연에 포함하지 않습니다.
5. ODsay 제한이 남아 있으면 해당 제공처로 이어지는 경로 새 조회와 최신 정보 재조회를 실행하지 않습니다. 제한 안내와 일정 편집·기기 저장으로 계속합니다.

## 0:00–0:25 · 필요한 편의에서 시작

“W.A.V.E는 필요한 편의부터 고르고, 공식 정보에서 확인된 내용과 더 확인할 내용을
살펴 경남 여행을 계획하는 서비스입니다.”

랜딩의 `여행 계획 만들기`로 `/planner`를 엽니다. 로그인 없이 시작할 수 있음을 보여주고
현재 단계와 다음 행동을 확인합니다. 경남 18개 시·군과 필요한 편의 선택으로 이어갑니다.

확인 포인트: 소개 화면에서 플래너로 바로 이동할 수 있고, 본문 건너뛰기와 키보드 초점이 보입니다.

## 0:25–1:05 · 조건과 공식 근거 확인

1. 지역 `창원`, 여행 주제 `자연·휴양`, 필요한 편의 `휠체어 이용`과 `걷기 불편`을 직접 선택합니다.
2. 검색을 실행하고 실제 반환된 추천 장소와 편의 확인이 부족한 장소의 구분을 봅니다.
3. 추천 장소의 편의정보를 열어 확인됨·미확인·불일치 개수와 원문을 읽습니다.
4. `출처·확인 시각·계산 방법`을 열어 출처와 조회 시각을 확인합니다.

“확인됨은 공식 데이터에 해당 편의가 기재됐다는 뜻입니다. 미확인은 시설이 없다는 뜻이
아닙니다. 추천 정렬은 선택한 편의의 긍정 근거를 바탕으로 하며, 사진·인기·후기는 계산에 넣지 않습니다.”

확인 포인트: 조회 시각을 시설 갱신일로 소개하지 않습니다. 긍정 근거가 없는 장소는
일반 추천과 일정 추가에서 제외하며, 확인 상태를 접근성 인증이나 안전 확률로 설명하지 않습니다.

## 1:05–1:45 · 직접 편집하는 일정과 이동

1. 현재 추천에서 편의 근거가 확인된 장소를 `일정에 추가`로 담습니다.
2. 출발일·도착일과 `하루 시작` 시각을 바꿉니다.
3. `앞`·`뒤` 버튼으로 같은 날의 순서를 바꾸고 날짜 선택으로 방문일을 옮깁니다.
4. 해당 날짜의 장소와 이동 구간에서 실제 제공기관 응답, 추정, 미확인을 구분해 읽습니다.
5. ODsay 제한 중에는 경로를 새로 요청하지 않고 현재 제한·미확인 안내와 남은 일정 편집을 보여줍니다.

“날짜별 장소와 이동 구간을 확인하고, 제공기관의 경로와 추정값을 구분해 읽습니다.
한 구간을 확인했다고 일정 전체의 이동이 확인되는 것은 아닙니다.”

확인 포인트: 드래그 없이 버튼과 키보드로 순서를 바꿀 수 있습니다. 직선거리 추정이나
제공기관의 응답 건수를 실제 경로 또는 대중교통 전체 확인 성공으로 설명하지 않습니다.

## 1:45–2:20 · 출발 전 확인

1. `출발 전 확인`에서 날씨·관광 집중률·교통·장소 편의근거의 상태를 봅니다.
2. 현재 표시된 상태와 각 출처·조회 시각·다음 행동을 읽습니다.
3. 날씨·상황 대응에서 강수나 관광 집중률 예측이 일정에 줄 수 있는 영향과 대안을 살펴봅니다.
4. 외부 제공처 제한 중에는 `최신 정보 확인`을 반복 실행하지 않습니다.

“조회 결과가 없는 항목은 다시 확인할 내용으로 남습니다. 관광 집중률은 예측값이며,
날씨와 혼잡이 일정에 주는 영향은 W.A.V.E의 계산을 참고해 사용자가 판단합니다.”

확인 포인트: 관광 집중률을 실시간 방문자 수로 표현하지 않고, 실패·정보 없음·예측을
확인 완료나 출발 안전 보장으로 바꾸지 않습니다.

## 2:20–3:00 · 보관과 데이터 경계

1. `/travel-book`의 내 여행집에 일정을 보관하고 같은 브라우저에서 다시 여는 범위를 설명합니다.
2. 공유는 최종 Production에서 확인한 동선과 실제 상태로 보여줍니다. 공유 저장이 성공한 경우에만 공유 링크나 `캘린더(.ics) 저장`의 결과를 설명합니다.
3. 장소별 공개 후기 또는 `/community`를 열고 공식 관광정보와 작성자의 경험이 분리되는 안내를 봅니다.
4. 후기가 없으면 빈 상태를 그대로 읽고 작성 화면이나 게시 성공을 시연하지 않습니다.

“여행집은 이 브라우저에 보관합니다. 공유 여행은 별도의 서버 보관 기능이며 정밀 현재 위치를
공유하지 않습니다. 여행자 후기는 한 사람의 현장 경험으로 공식 편의정보와 구분합니다.
공개 읽기는 로그인 없이 가능하고 글 작성에는 계정이 필요합니다.”

확인 포인트: 기기 저장, 30일 서버 공유 보관과 공개 게시물을 구분합니다.
후기를 공식 정보에 근거한 W.A.V.E 추천 계산에 합산하지 않습니다.

## 접근성 빠른 확인

- 키보드: 본문 건너뛰기 → 여행 조건 → 여행지 → 이 기기 일정·이동 → 출발 전 확인 순서
- 모바일: 390px에서 수평 넘침 없이 조작 영역 44px 이상
- 동작 감소: 환경설정의 동작 효과를 줄이고 필요한 정보와 행동이 유지되는지 확인
- 테마: 밝은·어두운 화면에서 상태 배지가 색 외에 텍스트를 함께 사용하는지 확인
- 입력: 조건·날짜·순서 변경을 키보드로 수행하고 오류 설명과 초점 확인

## 최종 시연 증거

Production SHA, 시연 시각, 화면 크기, 선택 조건, 확인한 기능과 제공처 제한을 함께 기록합니다.
#353 화면 개편과 최종 캡처가 배포되기 전에는 이 문서를 시연 완료 증거로 사용하지 않습니다.
인증이 필요한 후기 작성까지 심사 범위를 넓히는 경우에는 공식 지정 형식의 전용 테스트 계정을
별도로 준비하며 계정 값은 공개 문서에 넣지 않습니다.
