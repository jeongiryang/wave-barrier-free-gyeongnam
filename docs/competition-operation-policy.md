> 서비스 브랜드 W.A.V.E와 접수 정보를 구분한다. 원 접수 화면 대조와 실제 제출은 사람 확인 항목이다.
> [공식 Notion](https://lowly-polyanthus-1fb.notion.site/2026-36b5dce406e380e0a3d1f80525667a11)의 부문별 안내와

> 이전 구현 부문·지정과제 판단은 폐기된 과거 판단이며 현재 제출 요건으로 사용하지 않는다.

이 문서는 W.A.V.E의 배포, 한국관광공사 OpenAPI 활용, 데이터베이스 사용,
위치정보 처리 및 출처 표기 기준을 하나로 정리한 내부 운영 규칙이다.
공식 공지가 변경되면 이 문서와 [공모전 정합성 점검](contest-compliance.md)을 함께 갱신한다.

## 1. 최종 배포 구조

W.A.V.E의 공식 서비스 주소는 Vercel Production 도메인 하나로 통일한다.

```text
사용자 브라우저
  └─ Vercel
      ├─ 프런트엔드
      ├─ Vercel Functions (/api/*)
      ├─ 한국관광공사·Kakao·TAGO·KORAIL API 실시간 호출
      └─ Neon Postgres (서비스 자체 영속 데이터만 저장)
```

- 공식 웹 배포: Vercel
- 서버 함수: Vercel Functions
- 영속 데이터베이스: Neon Postgres
- 소스 및 CI: GitHub와 GitHub Actions
- 공식 배포 경로는 Vercel 하나만 유지해 중복 배포와 도메인 혼선을 방지한다.
- Pull Request의 CI 통과를 `main` 병합 조건으로 두고, 병합된 커밋을 Vercel이
  Production으로 자동 배포한다.
- Pull Request는 Vercel Preview와 CI로 검증한다.
- 로컬 개발은 `.env.local`을 사용하고 실제 키를 Git에 커밋하지 않는다.

## 2. 한국관광공사 OpenAPI 운영 규칙

### 반드시 지킬 사항

1. 한국관광공사 OpenAPI를 서비스 기능에서 실제로 호출한다.
2. 파일 데이터만 사용해서는 안 되며 OpenAPI 형태의 활용만 인정된다.
3. 심사 자료에 활용 API·신청자별 인증키·서비스 내 활용 내역을 기재하되 실제 값은 비공개 제출 화면에서만 입력한다.
   대표 API 운영계정 신청은 현재 확보한 제출 안내상 선택 사항이며 필수로 단정하지 않는다.
4. 심사 시 실제 호출 이력을 확인할 수 있도록 운영한다.
5. 관광지 정보와 사진 등 한국관광공사 응답은 가능한 한 실시간으로 조회한다.

### 금지 또는 사전 협의가 필요한 사항

- 한국관광공사 API 원본 응답을 Neon에 장기 저장한 뒤 API 대신 제공하지 않는다.
- API 응답을 대량으로 복제하여 W.A.V.E 자체 데이터처럼 재배포하지 않는다.
- 로컬 DB 저장 또는 캐싱이 불가피하면 구현 전에 별도 신청서를 준비하고
  `tourapi@knto.or.kr`로 문의한다.
- DB 데이터만 사용하여 개발 기간 중 실제 API 호출 이력이 사라지게 하지 않는다.

## 3. 저장 범위와 운영 정책

다음은 저장을 허용하는 내부 정책이며 각 항목의 실제 DB 저장·운영 완료 선언이 아니다.
이 기기의 일정/설정, 공유 여행, 커뮤니티의 저장 위치와 삭제 동작은
[개인정보처리방침](../app/privacy/page.tsx)과 [API 감사](api-integration-audit.md)에 맞춰 확인한다.
공공 API 원본 전체를 자체 데이터처럼 복제하지 않는다.

### 저장 가능

- 저장한 여행 일정과 일정 순서
- 즐겨찾기한 관광지의 `contentId` 등 참조 식별자
- 사용자가 선택한 접근성 조건과 서비스 설정
- 사용자가 직접 작성한 접근성 제보 및 후기
- 여행자 커뮤니티 게시글·댓글·좋아요·신고와 지역·관광지 참조 식별자
- 공유 링크, 생성 시각, 만료 시각
- 서비스 자체 평가값과 그 계산 기준 버전
- API 장애 분석을 위한 상태·오류 코드와 호출 시각

### 커뮤니티 운영

- 신고는 로그인한 사용자의 세션 ID에서 작성자를 확인하며 클라이언트가 전달한 사용자 ID를 신뢰하지 않는다.
- 동일 사용자의 동일 내용 중복 신고를 막고 24시간 신고 횟수를 제한한다.
- 서로 다른 사용자 신고가 3건 모이면 해당 내용은 `under_review`로 전환해 공개 목록에서 잠시 숨긴다.
- 지정 운영자만 공개 유지 또는 숨김 처리를 할 수 있고, 운영자 ID는 서버 환경 변수로만 관리한다.
- 신고 사유와 처리 상태는 운영 목적으로만 사용하며 관광 공공데이터와 결합하지 않는다.

### 저장하지 않음

- 한국관광공사 API 원본 응답 전체
- 한국관광공사 사진 원본 파일의 무단 복제본
- Kakao·Naver 등 외부 서비스의 지도 타일이나 리뷰 원문
- 사용자의 실시간 GPS 좌표와 이동 경로
- 인증키, 비밀키 및 배포 환경 변수
- 커뮤니티 테이블의 이메일·비밀번호와 불필요한 개인정보

### 참조 식별자 처리

이 기기 일정과 공유 여행은 장소 ID·날짜·순서뿐 아니라 복원용 공개 장소 요약을 포함할 수 있다.
모든 화면 진입에서 원본 API를 새로 호출하거나 최신 운영 정보를 보장한다고 설명하지 않는다.
저장된 요약과 새 조회 결과의 신뢰 범위를 구분하고 출발 전에 운영·편의시설 정보를 재확인한다.
정밀 GPS·인증정보·관광 API 원본 전체는 이 복원 요약에 포함하지 않는다.

## 4. 위치정보 처리 규칙

현재 코드의 최소화 조치는 아래와 같다. 이 구조만으로 신고·동의·약관 등 법적 의무가
해결됐다고 판단하지 않는다. 운영주체의 위치정보지원센터 등 공식 경로 검토 결과는 사람 확인 항목으로 남긴다.

- 위치 권한은 사용자가 현재 위치 기능을 누른 시점에만 요청한다.
- 현재 좌표는 브라우저 메모리에서만 사용하고 새로고침 또는 종료 시 폐기한다.
- 현재 위치가 출발점인 동안 W.A.V.E 경로 API 호출을 차단한다.
- 정밀 GPS는 공유 URL·공유 DB·이 기기 저장 장소 목록에 넣지 않는다. 공개 장소 좌표와 구분한다.
- 공개 출발 거점·사용자가 선택한 지도 지점은 W.A.V.E 경로 API와 Kakao·ODsay에 전달될 수 있다.
- 지도 SDK·대체 지도 타일 제공처는 화면 영역·접속 IP 등을 처리할 수 있다.
  사용자가 주변 검색을 실행하면 검색 시점의 지도 중심 좌표가 Kakao 장소 검색에 전달된다.
  따라서 모든 위치 처리가 기기 안에서만 이루어진다고 안내하지 않는다.
- 서비스 코드 밖의 호스팅/제공처 로그·보관 정책은 운영자 확인 항목으로 남긴다.
- 위치 권한을 거부한 이용자를 위해 지역·출발지 직접 선택 기능을 제공한다.
- 향후 GPS 좌표의 서버 전송이 필요한 기능을 추가할 때는 구현 전에 데이터 흐름과
  위치기반서비스사업 신고 필요성을 다시 검토한다.

근거: [현재 위치](../features/planner/hooks/useRouteOrigin.ts),
[경로 요청 제한](../features/planner/hooks/useRouteRequest.ts),
[주변 검색](../features/routing/useNearbyPlaces.ts), [개인정보처리방침](../app/privacy/page.tsx).

## 5. 출처와 브랜드 표기

- 한국관광공사 데이터에는 텍스트로 `출처: ⓒ한국관광공사` 또는
  `출처: ⓒ한국관광콘텐츠랩`을 표시한다.
- `TourAPI`만 단독 출처로 표시하지 않는다.
- 한국관광공사가 직접 개발·운영하는 서비스로 오인될 표현을 사용하지 않는다.
- 공사의 공식 CI·BI 로고는 별도 허가 없이 사용하지 않는다.
- 다른 제공기관의 데이터에도 각 이용조건에 맞는 출처를 표시한다.

## 6. API 키와 보안

- 공개 가능한 카카오 JavaScript 키를 제외한 비밀키는 서버 환경 변수에서만 사용한다.
- Vercel Production·Preview·Development 환경 변수를 목적에 맞게 분리한다.
- 클라이언트 번들, Git 기록, 로그 및 DB에 비밀키를 넣지 않는다.
- `/api/health`는 키 존재 여부만 반환하고 실제 키 값은 절대 반환하지 않는다.
- 키가 노출되면 즉시 재발급하고 Vercel 환경 변수를 교체한다.

## 8. 변경 관리

- 공식 자료가 서로 다르면 부문·발행일·원본 양식·주최 측 답변을 대조하고 미확인 차이를 #11에 남긴다.
  다른 부문의 문서를 현재 개발 부문 요건으로 적용하지 않는다.
- 규칙 해석이 필요한 한국관광공사 API 저장·캐싱은 구현 전에
  `tourapi@knto.or.kr`로 확인한다.
- 위치정보 처리 구조를 변경하면 위치정보지원센터 기준을 다시 확인한다.
- 이 문서를 변경하는 Pull Request에는 변경 근거와 확인일을 함께 적는다.
