# W.A.V.E 공모전 운영·데이터 정책

> 기준일: 2026-08-18  
> 공식 기준: [2026 관광데이터 활용 공모전 웹·앱 개발 부문 운영 페이지](https://lowly-polyanthus-1fb.notion.site/2026-36b5dce406e380e0a3d1f80525667a11?pvs=143)

이 문서는 W.A.V.E의 배포, 한국관광공사 OpenAPI 활용, 데이터베이스 사용,
위치정보 처리 및 출처 표기 기준을 하나로 정리한 내부 운영 규칙이다.
공식 공지가 변경되면 이 문서도 함께 갱신한다.

## 1. 최종 배포 구조

W.A.V.E의 공식 서비스 주소는 Vercel Production 도메인 하나로 통일한다.

```text
사용자 브라우저
  └─ Vercel
      ├─ 프런트엔드
      ├─ Vercel Functions (/api/*)
      ├─ 한국관광공사·Kakao·TAGO·KORAIL API 실시간 호출
      └─ Neon Postgres (서비스 자체 영속 데이터만 저장)
```

- 공식 웹 배포: Vercel
- 서버 함수: Vercel Functions
- 영속 데이터베이스: Neon Postgres
- 소스 및 CI: GitHub와 GitHub Actions
- 공식 배포 경로는 Vercel 하나만 유지해 중복 배포와 도메인 혼선을 방지한다.
- Pull Request의 CI 통과를 `main` 병합 조건으로 두고, 병합된 커밋을 Vercel이
  Production으로 자동 배포한다.
- Pull Request는 Vercel Preview와 CI로 검증한다.
- 로컬 개발은 `.env.local`을 사용하고 실제 키를 Git에 커밋하지 않는다.

## 2. 한국관광공사 OpenAPI 운영 규칙

### 반드시 지킬 사항

1. 한국관광공사 OpenAPI를 서비스 기능에서 실제로 호출한다.
2. 파일 데이터만 사용해서는 안 되며 OpenAPI 형태의 활용만 인정된다.
3. 심사 자료에 활용 API 운영계정 및 서비스 내 활용 내역을 명시한다.
4. 심사 시 실제 호출 이력을 확인할 수 있도록 운영한다.
5. 관광지 정보와 사진 등 한국관광공사 응답은 가능한 한 실시간으로 조회한다.

### 금지 또는 사전 협의가 필요한 사항

- 한국관광공사 API 원본 응답을 Neon에 장기 저장한 뒤 API 대신 제공하지 않는다.
- API 응답을 대량으로 복제하여 W.A.V.E 자체 데이터처럼 재배포하지 않는다.
- 로컬 DB 저장 또는 캐싱이 불가피하면 구현 전에 별도 신청서를 준비하고
  `tourapi@knto.or.kr`로 문의한다.
- DB 데이터만 사용하여 개발 기간 중 실제 API 호출 이력이 사라지게 하지 않는다.

## 3. Neon Postgres 사용 범위

Neon 사용 자체는 허용한다. 다만 서비스 자체 데이터와 이용자가 생성한 데이터만
영속 저장하는 것을 원칙으로 한다.

### 저장 가능

- 저장한 여행 일정과 일정 순서
- 즐겨찾기한 관광지의 `contentId` 등 참조 식별자
- 사용자가 선택한 접근성 조건과 서비스 설정
- 사용자가 직접 작성한 접근성 제보 및 후기
- 공유 링크, 생성 시각, 만료 시각
- 서비스 자체 평가값과 그 계산 기준 버전
- API 장애 분석을 위한 상태·오류 코드와 호출 시각

### 저장하지 않음

- 한국관광공사 API 원본 응답 전체
- 한국관광공사 사진 원본 파일의 무단 복제본
- Kakao·Naver 등 외부 서비스의 지도 타일이나 리뷰 원문
- 사용자의 실시간 GPS 좌표와 이동 경로
- 인증키, 비밀키 및 배포 환경 변수

### 참조 식별자 처리

여행 일정에는 관광지 이름과 상세 응답 전체 대신 `contentId`, 일정 순서,
사용자 메모를 저장한다. 화면을 열 때 `contentId`로 최신 관광지 정보를 다시
호출하여 데이터 갱신과 실제 API 이용을 모두 보장한다.

## 4. 위치정보 처리 규칙

공식 FAQ는 개인위치정보를 단말기 내부에서만 활용하고 서버로 전송하지 않는
경우를 비신고 사례로 안내한다. 반대로 개인위치정보를 사업자 서버로 전송하면
DB 저장 여부와 관계없이 신고 대상이 될 수 있다고 안내한다.

W.A.V.E는 다음 원칙을 적용한다.

- 위치 권한은 사용자가 현재 위치 기능을 누른 시점에만 요청한다.
- 현재 좌표는 브라우저 메모리에서만 사용하고 새로고침 또는 종료 시 폐기한다.
- GPS 좌표를 Vercel API, Neon, 로그, 분석 도구로 전송하지 않는다.
- `localStorage`, 쿠키 및 URL 쿼리에 좌표를 기록하지 않는다.
- 지도 마커, 직선거리 계산, 거리순 정렬은 브라우저에서 처리한다.
- 서버에는 좌표 대신 관광지 식별자, 지역 코드 또는 정류장 식별자를 전달한다.
- 위치 권한을 거부한 이용자를 위해 지역·출발지 직접 선택 기능을 제공한다.
- 향후 GPS 좌표의 서버 전송이 필요한 기능을 추가할 때는 구현 전에 데이터 흐름과
  위치기반서비스사업 신고 필요성을 다시 검토한다.

## 5. 출처와 브랜드 표기

- 한국관광공사 데이터에는 텍스트로 `출처: ⓒ한국관광공사` 또는
  `출처: ⓒ한국관광콘텐츠랩`을 표시한다.
- `TourAPI`만 단독 출처로 표시하지 않는다.
- 한국관광공사가 직접 개발·운영하는 서비스로 오인될 표현을 사용하지 않는다.
- 공사의 공식 CI·BI 로고는 별도 허가 없이 사용하지 않는다.
- 다른 제공기관의 데이터에도 각 이용조건에 맞는 출처를 표시한다.

## 6. API 키와 보안

- 공개 가능한 카카오 JavaScript 키를 제외한 비밀키는 서버 환경 변수에서만 사용한다.
- Vercel Production·Preview·Development 환경 변수를 목적에 맞게 분리한다.
- 클라이언트 번들, Git 기록, 로그 및 DB에 비밀키를 넣지 않는다.
- `/api/health`는 키 존재 여부만 반환하고 실제 키 값은 절대 반환하지 않는다.
- 키가 노출되면 즉시 재발급하고 Vercel 환경 변수를 교체한다.

## 7. Pull Request 점검표

- [ ] 한국관광공사 OpenAPI의 실제 호출 경로가 유지되는가?
- [ ] 한국관광공사 원본 응답을 DB에 새로 저장하지 않는가?
- [ ] GPS 좌표가 서버 요청·로그·DB로 전송되지 않는가?
- [ ] 데이터별 출처가 화면에 표시되는가?
- [ ] 비밀키가 클라이언트 코드나 Git 변경사항에 포함되지 않았는가?
- [ ] Pull Request CI와 Vercel Preview에서 주요 기능을 확인했는가?
- [ ] API 실패 시 오류 상태와 대체 UI가 정상적으로 표시되는가?

## 8. 변경 관리

- 공식 노션 공지와 공고문이 충돌하면 최신 공식 공지를 우선 확인한다.
- 규칙 해석이 필요한 한국관광공사 API 저장·캐싱은 구현 전에
  `tourapi@knto.or.kr`로 확인한다.
- 위치정보 처리 구조를 변경하면 위치정보지원센터 기준을 다시 확인한다.
- 이 문서를 변경하는 Pull Request에는 변경 근거와 확인일을 함께 적는다.
