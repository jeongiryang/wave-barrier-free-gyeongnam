# Owner PDF: 기능 화면 디자인 적용

2026-09-10 Owner가 지정한 최신 Gmail 첨부 `WAVE_일정작성_전체보기_통합시안.pdf` 4쪽을 모두 렌더링해 읽고 기능 화면의 시각 기준으로 삼았다. 메일 주소, 첨부 다운로드 토큰, 개인 메일 본문은 저장소에 복사하지 않는다.

## 화면 대응

| 시안 | 구현 |
| --- | --- |
| 1쪽 지역 선택 | 흰 헤더, 조건 검색 pill, 둥근 관심 버튼, 큰 지역 사진 1장과 작은 사진 4장, 선택 요약·다음 버튼. 전체 보기에서 경남 18개 지역과 경남 전체를 고를 수 있다. |
| 1쪽 여행지 선택 | 실제 검색 결과의 3열 사진 카드, 우측 하트와 일정 추가, 확인된 편의 칩, 미확인/불일치 표시, 선택 요약. 모바일은 1열이다. |
| 2쪽 날짜 | 실제 월별 달력과 기간 선택, 직접 날짜 입력, 7일 제한, 우측 날짜별 요약. 변경된 기간 밖 일정은 명시적인 이동 동작을 제공한다. |
| 3쪽 일정 편집 | 날짜 탭, 시작 시각, 시간·사진·장소 목록, 순서·날짜·삭제 조작, 현재 검색 결과에서 추가할 여행지. |
| 3쪽 지도 편집 | 일정 목록·실제 지도·날씨의 3열 배치. 좁은 화면은 세로 배치. 기존 지도 도구·이동수단 비교를 상세 보기에서 사용할 수 있다. |
| 2·4쪽 전체보기 | 날짜·방문 순서 배너, 날짜별 시간표, 현재 날씨, 이동 경로·접근성 요약, 기존 공유와 내 일정 저장. |

단계는 지역 → 필요한 편의 → 활동 → 여행지 → 날짜 → 일정 → 전체보기의 7개로 통일한다. 브라우저 뒤로/앞으로와 질문 URL, 기존 전체 도구 보기 설정을 유지한다. 기존 일정은 새로운 검색 전에도 편집할 수 있다. 화면의 7단계 위치와 실제 준비 완료율은 서로 다른 값이다. 완료율은 검색·선택·모든 이동 구간 검토·출발 검토의 기존 근거를 유지한다.

## 실제 서비스 데이터와 시안 값의 구분

- 시안에서 반복 사용된 다른 지역의 사진 대신 장소와 일치하는 기존 KTO 사진을 사용하고 저작자와 원본 링크를 제공한다. 사진은 생성하지 않았다.
- 관심 버튼은 기존 자연·휴양/역사·문화/음식 조건을 선택한다. 바다·숲길은 자연, 문화·실내는 문화 정보 탐색의 시작점이다. 확인되지 않은 접근성 등급을 `접근 우수`라고 주장하지 않고 필요한 편의 선택으로 연결한다.
- 고정 추천 12곳, 날씨 22도, 시설 확인 3개, 이동 시간은 복제하지 않는다. 조회값·기간·선택 목록·구간 검증값에서 계산한다. 바다·실내 필터는 현재 검색된 장소 설명의 관련 문구로 좁히며, 접근로·장애인 화장실·조건 확인 필터는 항목별 confirmed 근거만 사용한다. 조건 확인은 선택한 모든 facilityKeys가 확인된 경우에만 포함한다. 근거가 없는 장소는 이 필터에 포함하지 않는다.
- 기존 비로그인 저장·공유, 날짜별 일정, 실제 지도·경남 범위, 경로·날씨·혼잡도·접근성 상세는 유지한다. 사용자 좌표·민감 정보의 새 저장 경로를 추가하지 않는다.
- 공개 화면은 한국어·기본 밝은 테마를 유지한다. 개발자 전용 과거 영문/테마 회귀 설정은 공개 버튼으로 노출하지 않는다.

## 검증 범위

새 화면의 데스크톱·모바일 실제 브라우저 흐름에서 조건 선택→여행지 추가→날짜 변경→기존 일정의 명시적 이동→추가/순서 변경→지도→전체보기→공유/저장을 확인한다. 새 화면과 변경된 탐색을 사용하는 기존 테스트의 선택자를 업데이트하고 저장·준비 완료·키보드 초점·검색 요청 수·접근성 검증은 유지한다. 외부 유료 API 한도 검증과 인증 전환은 이 디자인 PR에 포함하지 않는다.

전체 서비스의 반복 대규모 시각 회귀는 후속 회귀 분석에서 다룬다. 이 PR의 필수 CI와 변경된 핵심 흐름 검증은 수행한다.

초기 로딩 예산을 유지하기 위해 달력·일정·전체보기 코드를 분리하고, 교체된 예전 헤더·레일·지역 지도·카드의 미사용 CSS 선택자를 정리했다. 현재 컴포넌트가 사용하는 스타일과 성능 예산은 유지한다.
