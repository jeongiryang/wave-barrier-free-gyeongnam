# 9월 27일 잔여 기능 검증

## 이번에 고친 사용자 영향

- 나루의 지도 도구가 사라진 `#itinerary-map`에 초점을 보내던 문제를 실제 지도 섹션 `#navigation`으로 수정했다. 도구 진입·기능 수행·복귀와 기존 여행 보존을 검사한다.
- 저장 장소 좌표가 모두 정상일 때 좌표 복원 도구가 빈 화면이 되지 않도록, 추가 조회가 필요 없다는 안내와 접근성 미확인 한계를 표시한다.
- 댓글 변경 후 최신 내용을 읽는 동안 기존 게시글을 유지한다. 저장 성공 뒤 재조회만 실패한 경우 저장 실패로 오해하지 않도록 분리해서 안내한다. 인증 주체 변경 시에는 이전처럼 새로 불러온다.
- ODsay·Kakao 경로가 실제 반환됐는데 제공처의 `queryStatus`가 `not-requested`로 남는 오류를 수정했다. 성공·정상 빈 결과·실패 및 검증된 경로 수를 일치시킨다.
- 작은 일정 썸네일에서 사진 미확인 안내가 잘리지 않도록 간결한 두 줄 표시와 접근성 이름을 제공한다. 큰 사진 카드의 상세 안내는 유지한다.

## 실제 제공처·화면 근거

운영 `509bff5`에서 ODsay 앱 7013의 로그인된 계정 화면을 확인했다. 2026-09-27 01:58 KST 활성 Basic, 현재 호출 0/30건이었다. 제한된 두 요청 후 02:02 화면은 성공 호출 1/30건·전체 요청 2건이었다. 키·요금제·계정 설정은 바꾸지 않았다.

첫 743m 구간은 정상 경로 없음이었다. 실제 나루 여행의 통영시립도서관→강구안 구간은 ODsay 대안 3개(20/21/21분, 도보 398/381/398m, 환승 0회)를 반환했다. 경로 조회를 휠체어 통행 보장으로 해석하지 않는다. 이 응답은 정상 경로 반환 근거이며 실제 승차 검증은 아니다.

실제 운영 Kakao 지도 SDK와 35개 타일의 로딩을 확인했다. 같은 SHA의 정확한 공개 장소 쌍에만 위 ODsay 응답을 재생하여 일정의 이동시간 연결을 확인했고, 다른 구간의 추가 제공처 조회는 차단했다. 따라서 지도 SDK는 실제 연결, 재사용한 경로 응답은 재생 검증으로 구분한다.

독립 API 검토는 기존 응답에 더해 시작·종료 health 포함 11개 읽기 요청을 사용했다. 공식 장소 4개 ID·사진·시설 원문·운영정보·축제기간·날씨를 대조했다. Odii/축제 주변 화장실의 정상 빈 결과와 주차 대안 제공처의 502 오류는 구별해 기록했다. 실제 응답을 재생한 화면 검사 6개는 API 추가 호출 없이 데이터 표시와 일정 보존을 확인한다.

## 검증 구성

- `e2e/naru-tool-completion.spec.ts`: 기존 도메인 검사와 연결해 외부 화면으로 나가는 도구의 초점·의미 있는 조작·나루 복귀 공백을 보완한다. 전체 28개 UI 도구 목록을 새로 세는 검사로 완주를 대신하지 않는다.
- `e2e/community-comment-refresh.spec.ts`: 저장 후 재조회 대기·실패 때 본문 유지 및 경합 회귀.
- ODsay/Kakao 관련 단위 검사: 실제 반환 경로 수, 정상 빈 결과, 제한·파싱·연결 검증 실패의 상태 대조.
- 독립 시각 QA: 소개·여행 설계·일정·커뮤니티·축제 5개 화면을 1440/960/390px에서 확인. 실제 API 사진과 합성 화면의 범위를 구분한다.

로컬의 일회성 실제 계정 검증 결과와 민감정보를 제거한 자료는 `harness-results/release-final/`에 보존한다. 최종 CI/Audit/배포 커밋과 배포 후 실증 결과는 PR에 연결한다. 이전 SHA의 근거를 새 SHA의 실제 실행으로 표시하지 않는다.

## 남은 경계

사용자는 현재 실제 휴대전화·화면낭독기를 사용할 수 없다고 확인했다. 가상 모바일·키보드·axe 검사를 실기기나 TalkBack/VoiceOver 실증으로 표시하지 않는다. 실제 데이터가 없는 음원/시설의 정상 빈 응답도 양성 콘텐츠 성공은 아니다. 전체 79개 요구의 출시 판정은 이러한 미확인 범위와 제공처 오류를 포함해 수용 기준별로 판단해야 한다.
